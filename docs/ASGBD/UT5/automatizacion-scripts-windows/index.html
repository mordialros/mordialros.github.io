5.3. Automatización mediante scripts del sistema operativo

1️⃣ ¿Qué es un script del sistema operativo?​

En el apartado anterior aprendimos a guardar instrucciones SQL en archivos .sql y a ejecutarlas con el cliente mysql.

Pero algunas tareas administrativas necesitan combinar órdenes del sistema operativo con herramientas de MySQL. Por ejemplo, ejecutar una comprobación, guardar su resultado en un archivo y avisar si se produce un error.

En Windows podemos preparar estas operaciones mediante un archivo por lotes, también llamado script .bat. Es un archivo de texto que contiene comandos que interpreta la consola de Windows (CMD), ejecutándolos en el orden indicado.

Conviene distinguir:

Archivo¿Quién lo interpreta?¿Qué contiene?
.sqlEl servidor MySQL, a través de un cliente como mysqlInstrucciones SQL.
.batCMD de WindowsComandos del sistema, entre ellos llamadas al cliente mysql.

Un .bat puede ejecutar un .sql: no sustituye al lenguaje SQL, sino que permite organizar su ejecución junto con otras operaciones del sistema.

2️⃣ Crear y ejecutar un archivo .bat​

Los archivos .bat se pueden redactar con el Bloc de notas o Visual Studio Code y deben guardarse como texto plano, con la extensión .bat (no .bat.txt).

🔶 Primer ejemplo: un archivo por lotes sencillo​

Vamos a crear saludo.bat con estas instrucciones:

@echo off
echo Iniciando comprobacion del servidor...
echo Comprobacion preparada.
pause

El significado de los comandos es:

ComandoFunción
@echo offEvita que CMD muestre cada instrucción antes de ejecutarla.
echoMuestra un mensaje en pantalla.
pauseEspera a que se pulse una tecla antes de continuar.

Para ejecutarlo, abrimos CMD, accedemos a la carpeta donde lo hemos guardado y escribimos su nombre:

cd /d C:\scripts_mysql
saludo.bat

El comando cd /d permite cambiar de carpeta y, si hace falta, también de unidad.

Importante: pause sirve para observar la salida durante las primeras pruebas, pero no debe incluirse en un script que vaya a ejecutarse automáticamente, porque detendría la tarea esperando una intervención manual.

3️⃣ Ejecutar un script SQL desde un archivo .bat​

Veamos cómo utilizar un archivo por lotes para ejecutar una comprobación de MySQL.

🔶 Ejemplo: comprobación en una tienda de informática​

El personal técnico de una tienda quiere consultar la versión del servidor, su fecha y hora y el número de conexiones activas, sin introducir las consultas una a una.

Paso 1. Crear el archivo SQL

En la carpeta C:\scripts_mysql, guardar estado_servidor.sql con el siguiente contenido:

-- Comprobaciones administrativas de lectura
SELECT VERSION() AS version_mysql;
SELECT NOW() AS fecha_hora;
SHOW GLOBAL STATUS LIKE 'Threads_connected';

Paso 2. Crear el archivo por lotes

En la misma carpeta, guardar comprobar_estado.bat:

@echo off
echo Iniciando comprobacion de MySQL...
mysql -u root -p < "C:\scripts_mysql\estado_servidor.sql"
echo Comprobacion finalizada.
pause

Paso 3. Ejecutar y observar

Abrir CMD y ejecutar:

cd /d C:\scripts_mysql
comprobar_estado.bat

El cliente mysql solicitará la contraseña, ejecutará las instrucciones y mostrará sus resultados.

En este ejemplo se utiliza root únicamente para ilustrar una prueba manual en un entorno de laboratorio. Para una comprobación de lectura es preferible una cuenta con permisos limitados.

Observa: el mensaje «Comprobación finalizada» solo indica que Windows ha llegado a esa instrucción. No demuestra que la consulta se haya ejecutado correctamente. Necesitamos comprobar si el comando anterior produjo un error.

4️⃣ Guardar los resultados en un archivo​

En un script .bat podemos usar los operadores de redirección que ya conocemos:

  • > guarda la salida normal y sustituye el contenido anterior del archivo.
  • >> añade la salida al final de un archivo existente.
  • 2>&1 envía los mensajes de error al mismo destino que la salida normal.

Por ejemplo:

mysql -u root -p < "C:\scripts_mysql\estado_servidor.sql" > "C:\scripts_mysql\resultado.txt" 2>&1

Después de introducir la contraseña, podemos abrir resultado.txt y revisar la información obtenida. Si ejecutamos otra vez el comando, > reemplazará su contenido.

Si cambiamos > por >>, los resultados se añadirán al final del archivo. Esta opción puede servir para conservar el historial de varias ejecuciones, aunque el archivo irá creciendo.

5️⃣ Detectar errores con ERRORLEVEL​

Cuando un programa termina, devuelve a Windows un código de salida. Por regla general, el valor 0 indica que la ejecución se ha completado correctamente y un valor distinto de 0 indica un error.

En un archivo .bat, if errorlevel 1 permite comprobar si el último programa ha devuelto un código igual o superior a 1.

Vamos a mejorar el script anterior para que diferencie entre un resultado correcto y un fallo:

@echo off
echo Iniciando comprobacion de MySQL...

mysql -u root -p < "C:\scripts_mysql\estado_servidor.sql" > "C:\scripts_mysql\resultado.txt" 2>&1

if errorlevel 1 (
    echo ERROR: la comprobacion ha fallado.
    echo Revisa C:\scripts_mysql\resultado.txt
    exit /b 1
)

echo OK: comprobacion realizada correctamente.
echo Revisa C:\scripts_mysql\resultado.txt
exit /b 0

En este caso:

  1. Windows ejecuta el cliente mysql y guarda su salida y sus errores en resultado.txt.
  2. Justo después, comprueba el código de salida del cliente.
  3. Si hay un error, muestra un aviso y termina con exit /b 1.
  4. Si no hay error, muestra un mensaje de confirmación y termina con exit /b 0.

El comando exit /b finaliza el archivo por lotes sin cerrar la consola CMD desde la que se haya ejecutado.

¿Por qué comprobamos el error inmediatamente? Porque otros comandos podrían cambiar el código de salida que queremos examinar.

En los ejemplos utilizamos una ejecución manual con -p, que solicita la contraseña. Este script todavía no está preparado para ejecutarse sin intervención. En los siguientes apartados veremos cómo planificar tareas con una autenticación adecuada, sin escribir contraseñas directamente en los comandos.

6️⃣ Buenas prácticas al preparar scripts administrativos​

Antes de utilizar un .bat en la administración de MySQL, conviene aplicar algunas medidas básicas:

  • Utilizar nombres y rutas claros para los archivos. Si una ruta contiene espacios, escribirla entre comillas dobles.
  • Probar primero los comandos manualmente para comprobar que funcionan.
  • Guardar los resultados y los mensajes de error cuando sea necesario revisar la ejecución.
  • Comprobar el código de salida antes de dar la operación por correcta.
  • Evitar instrucciones interactivas (pause, confirmaciones o solicitudes de contraseña) en tareas programadas.
  • Aplicar el principio de mínimo privilegio: utilizar una cuenta de MySQL con los permisos necesarios para la tarea, sin emplear root de forma innecesaria.
  • No escribir contraseñas directamente en el .bat ni dejar archivos que las contengan accesibles a otros usuarios.

Un script puede terminar sin mostrar errores y, aun así, no haber producido el resultado esperado. Por eso, además del código de salida, hay que verificar el resultado de la operación.

✅ Qué debes saber​

Al finalizar este apartado debes ser capaz de:

  • Diferenciar un script SQL (.sql) de un archivo por lotes de Windows (.bat).
  • Crear y ejecutar un archivo .bat desde CMD.
  • Utilizar un .bat para lanzar un script SQL con el cliente mysql.
  • Redirigir resultados y errores a un archivo de texto.
  • Comprobar el código de salida de una ejecución mediante if errorlevel 1.
  • Reconocer qué cambios necesita un script manual antes de poder ejecutarse como tarea programada.
