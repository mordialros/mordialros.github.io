5.2. Creación y ejecución de scripts SQL

1️⃣ ¿Qué es un script SQL?​

Un script SQL es un archivo de texto que contiene una o varias instrucciones SQL preparadas para ejecutarse de forma consecutiva. Habitualmente utiliza la extensión .sql.

En la administración de MySQL, los scripts permiten repetir comprobaciones y operaciones sin tener que escribir cada instrucción de nuevo. También facilitan revisar qué comandos se van a ejecutar y conservar un procedimiento documentado.

Por ejemplo, un script puede consultar la versión del servidor, la fecha y hora y las bases de datos disponibles. Estas consultas no modifican la información.

SELECT VERSION() AS version_mysql;
SELECT NOW() AS fecha_hora;
SHOW DATABASES;

Un script no se ejecuta por el hecho de guardarlo: es necesario enviarlo a MySQL utilizando una herramienta cliente.

2️⃣ Herramientas para crear y ejecutar scripts​

Podemos redactar un archivo .sql con cualquier editor de texto que guarde archivos de texto plano, como el Bloc de notas o Visual Studio Code. También podemos utilizar el editor SQL de MySQL Workbench.

Para ejecutarlo utilizaremos principalmente el cliente de línea de comandos mysql, que ya conocemos. Workbench también permite abrir y ejecutar scripts, pero en este apartado nos centraremos en la consola, porque después podremos incorporar estas operaciones a un archivo .bat.

HerramientaFunción
Editor de texto / WorkbenchRedactar y guardar las instrucciones SQL.
Archivo .sqlConservar las instrucciones que se quieren ejecutar.
Cliente mysqlConectarse al servidor y ejecutar las instrucciones.
CMD de WindowsIniciar el cliente mysql y redirigir archivos de entrada o salida.

Antes de empezar: el comando mysql debe estar disponible en el equipo desde el que se ejecuta. Si Windows no lo reconoce, se puede utilizar su ruta completa o añadir la carpeta bin de MySQL al PATH.

3️⃣ Cómo organizar un script​

Para que un script pueda revisarse y reutilizarse con facilidad, conviene:

  • Darle un nombre descriptivo, por ejemplo, comprobar_servidor.sql.
  • Incluir comentarios que indiquen su finalidad.
  • Ordenar las instrucciones en una secuencia lógica.
  • Terminar las sentencias SQL con ; cuando corresponda.
  • Evitar incluir contraseñas en el archivo.
  • Revisar qué objetos o datos podría modificar antes de ejecutarlo.

En MySQL, podemos escribir comentarios de una línea usando -- (dos guiones y un espacio).

-- Comprobaciones básicas del servidor MySQL
SELECT VERSION() AS version_mysql;
SELECT NOW() AS fecha_hora;
SHOW DATABASES;

Los scripts administrativos pueden contener operaciones de consulta o de modificación. En las primeras pruebas utilizaremos consultas de lectura, para evitar cambios accidentales en el entorno.

4️⃣ Ejecutar un script desde la consola MySQL​

El comando SOURCE permite ejecutar las instrucciones contenidas en un archivo .sql desde una sesión abierta en el cliente MySQL.

🔶 Ejemplo: comprobación del servidor​

Una tienda de informática utiliza una base de datos para gestionar sus productos. El personal técnico quiere guardar un procedimiento que permita obtener información básica del servidor sin repetir manualmente las consultas.

Paso 1. Crear la carpeta C:\scripts_mysql en Windows.

Paso 2. Guardar en ella el archivo comprobar_servidor.sql con este contenido:

-- Comprobación básica del servidor
SELECT VERSION() AS version_mysql;
SELECT NOW() AS fecha_hora;
SHOW DATABASES;

Paso 3. Abrir CMD y conectarse al servidor:

mysql -u root -p

Introducir la contraseña cuando la solicite. En el laboratorio se utilizará la cuenta autorizada para cada operación; root se muestra aquí únicamente como ejemplo de una conexión administrativa local.

Paso 4. Dentro del cliente MySQL (mysql>), ejecutar:

SOURCE C:/scripts_mysql/comprobar_servidor.sql;

En los ejemplos utilizamos / en las rutas de Windows para evitar problemas con las barras invertidas. SOURCE es un comando del cliente mysql, no una sentencia SQL del servidor.

Paso 5. Comprobar que se muestran la versión de MySQL, la fecha y hora y el listado de bases de datos.

Si modificamos el archivo y volvemos a ejecutar SOURCE, se utilizará su contenido actualizado.

5️⃣ Ejecutar un script directamente desde CMD​

También podemos ejecutar un archivo .sql sin abrir antes la consola interactiva de MySQL. Para ello, Windows puede redirigir el contenido del archivo a la entrada del cliente mysql mediante el símbolo <.

mysql -u root -p < C:\scripts_mysql\comprobar_servidor.sql

El cliente se conecta, ejecuta las instrucciones y termina. Esta forma resulta especialmente útil para la automatización que veremos en el apartado 5.3.

🔶 Guardar los resultados en un archivo​

Desde CMD, el símbolo > permite enviar la salida normal de un comando a un archivo de texto:

mysql -u root -p < C:\scripts_mysql\comprobar_servidor.sql > C:\scripts_mysql\resultado.txt

Una vez introducida la contraseña, podemos abrir resultado.txt para revisar la salida de las consultas.

Para recoger también los mensajes de error en el mismo archivo, podemos añadir 2>&1 al final:

mysql -u root -p < C:\scripts_mysql\comprobar_servidor.sql > C:\scripts_mysql\resultado.txt 2>&1

En CMD:

SímboloSignificado
<Lee la entrada del programa desde un archivo.
>Guarda la salida normal en un archivo, sustituyendo su contenido anterior.
2>&1Envía los mensajes de error al mismo destino que la salida normal.

Seguridad: los ejemplos utilizan -p sin escribir la contraseña. En la ejecución manual, MySQL la solicita de forma interactiva. Esta solución todavía no sirve para una tarea desatendida; en los apartados siguientes veremos cómo preparar la ejecución automática sin introducir la contraseña en el comando.

6️⃣ Comprobar errores de ejecución​

Un archivo .sql puede contener una instrucción incorrecta, utilizar un objeto que no existe o intentar realizar una operación para la que la cuenta conectada no tiene permisos.

Por ejemplo, si el script incluye:

SELECT * FROM tabla_inexistente;

MySQL mostrará un error porque no puede encontrar esa tabla en la base de datos seleccionada. Además, es importante distinguir entre que el cliente haya ejecutado el script y que todas las operaciones hayan terminado correctamente.

Para realizar una comprobación básica:

  1. Revisar los mensajes mostrados por MySQL o el archivo de salida.
  2. Identificar si hay errores y a qué instrucción corresponden.
  3. Corregir el problema y volver a ejecutar el script cuando sea seguro hacerlo.
  4. Verificar el resultado de las operaciones realizadas.

En una tarea administrativa, es preferible detectar un fallo antes que dar por correcta una operación que no se ha completado. En el próximo apartado veremos cómo registrar y comprobar errores desde un archivo .bat.

✅ Qué debes saber​

Al finalizar este apartado debes ser capaz de:

  • Explicar qué es un script SQL y para qué se utiliza en la administración de MySQL.
  • Identificar herramientas para redactar y ejecutar archivos .sql.
  • Organizar scripts con nombres descriptivos y comentarios.
  • Ejecutar un script mediante SOURCE desde el cliente MySQL.
  • Ejecutar un script desde CMD utilizando la redirección de entrada <.
  • Guardar y revisar los resultados y errores de una ejecución.
