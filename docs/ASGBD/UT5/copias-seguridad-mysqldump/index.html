5.3. Copias de seguridad con mysqldump

1️⃣ ¿Por qué necesitamos copias de seguridad?​

Administrar una base de datos también implica proteger la información frente a errores, pérdidas de datos o incidencias. Una copia de seguridad permite recuperar los datos a partir de un estado anterior.

Una copia lógica guarda instrucciones y datos que permiten reconstruir los objetos de la base de datos. En MySQL podemos generarla con mysqldump, una herramienta que acompaña al servidor y se utiliza desde la consola del sistema operativo.

important

Una copia no se considera comprobada por el mero hecho de existir un archivo: hay que verificar que puede restaurarse. En esta unidad restauraremos siempre en una base de datos diferente, para no modificar los datos originales.

🔶 ¿Qué guarda mysqldump?​

De forma habitual, el archivo generado incluye sentencias CREATE TABLE para reconstruir las tablas y sentencias INSERT para recuperar sus registros. Por defecto, también incorpora DROP TABLE IF EXISTS antes de recrear cada tabla, con el riesgo de sustituir datos si restauramos en una base que ya contiene tablas con esos nombres.

Los eventos y procedimientos almacenados no se exportan por defecto: para incluirlos se necesitan, respectivamente, --events y --routines. Los disparadores de tablas sí se incluyen de forma predeterminada. En esta unidad nos centraremos en la copia de estructura y datos.

HerramientaFunción
mysqldumpExporta la estructura y los datos a un archivo SQL.
mysqlEjecuta el archivo SQL para reconstruir la información.
MySQL WorkbenchPermite comprobar mediante consultas las tablas y los registros restaurados.

No confundas mysqldump con el cliente mysql: el primero genera la copia; el segundo puede ejecutarla para restaurarla.

2️⃣ Preparación del entorno​

Trabajaremos en la máquina virtual con Windows 11 Pro y MySQL Server 8.0, utilizando la base tienda_informatica preparada en el apartado 5.2.

Antes de continuar, comprueba en Workbench:

USE tienda_informatica;
SHOW TABLES;
SELECT COUNT(*) AS total_productos FROM productos;

Deben existir las tablas categorias, productos y registro_tareas. Con los datos iniciales, productos contiene 9 registros.

Abre Símbolo del sistema (CMD). La carpeta C:\ASGBD\UT5 ya se preparó en el apartado 5.2. Puedes acceder a ella con:

cd /d C:\ASGBD\UT5
note

Los comandos mysqldump y mysql se ejecutan en CMD, no después del indicador mysql>. No utilices Windows PowerShell para copiar estos comandos tal cual: en Windows PowerShell 5.1 el operador < no está admitido y > puede crear archivos en UTF-16 que no se restauren correctamente con mysql. Si abres Windows Terminal, selecciona el perfil Símbolo del sistema.

El cliente mysql y mysqldump son ejecutables distintos; que funcione el primero no demuestra que el segundo esté disponible en PATH. Si el comando no se reconoce, utiliza su ruta completa, como se indica a continuación.

3️⃣ Generar una copia de seguridad con mysqldump​

Desde CMD, ejecuta:

mysqldump -u root -p --single-transaction tienda_informatica > C:\ASGBD\UT5\copia_tienda.sql

Si mysqldump no se reconoce, emplea la ruta habitual de instalación (ajústala si corresponde):

"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe" -u root -p --single-transaction tienda_informatica > C:\ASGBD\UT5\copia_tienda.sql

Introduce la contraseña cuando se solicite. Si no se produce ningún error, se habrá generado el archivo copia_tienda.sql en C:\ASGBD\UT5.

🔶 ¿Qué significa cada parte?​

ElementoSignificado
mysqldumpUtilidad que genera una copia lógica.
-u rootCuenta utilizada para conectarse. En un entorno real conviene usar una cuenta de copia con los permisos necesarios.
-pSolicita la contraseña sin escribirla en el comando.
--single-transactionObtiene una instantánea consistente de las tablas transaccionales, como las InnoDB del ejemplo, sin bloquearlas durante toda la copia.
tienda_informaticaBase de datos que queremos copiar.
>Redirige la salida a un archivo. Si el archivo existe, lo sobrescribe.
C:\ASGBD\UT5\copia_tienda.sqlRuta del archivo que contiene la copia.

🔶 Comprobar el archivo​

En CMD puedes ejecutar:

dir C:\ASGBD\UT5\copia_tienda.sql

Comprueba que existe y que no está vacío. También puedes abrirlo con Workbench para observar las instrucciones SQL que contiene; no lo ejecutes sobre la base original.

warning

La existencia del archivo no demuestra por sí sola que la copia sea utilizable. Si mysqldump muestra un error, hay que corregirlo antes de considerar la copia válida. Además, > puede crear un archivo vacío o incompleto aunque la operación falle.

4️⃣ Restaurar la copia en otra base de datos​

Vamos a recuperar el contenido de copia_tienda.sql en una base nueva llamada tienda_pruebas. Así comprobamos la restauración sin alterar tienda_informatica.

🔶 Paso 1. Crear la base de destino​

Desde MySQL Workbench, ejecuta:

CREATE DATABASE tienda_pruebas
CHARACTER SET utf8mb4
COLLATE utf8mb4_0900_ai_ci;

🔶 Paso 2. Ejecutar el archivo de copia​

Vuelve a CMD y ejecuta el comando con la ruta completa del archivo:

mysql -u root -p tienda_pruebas < C:\ASGBD\UT5\copia_tienda.sql

Introduce la contraseña cuando se solicite. Si CMD no reconoce mysql, utiliza la ruta completa de mysql.exe, siguiendo el ejemplo del 5.2.

El archivo generado en el apartado anterior no incluye CREATE DATABASE ni USE tienda_informatica, porque exportamos una base por su nombre sin la opción --databases. Por ello, podemos ejecutarlo sobre tienda_pruebas.

important

No confundas los signos de redirección: > envía la salida de mysqldump a un archivo; < proporciona el contenido del archivo al cliente mysql.

🔶 Paso 3. Verificar los datos restaurados​

En Workbench, despliega el esquema tienda_pruebas en el panel SCHEMAS. Deben aparecer las tres tablas. Para ver los recuentos en una única pestaña de resultados, ejecuta:

USE tienda_pruebas;

SELECT 'Categorías' AS comprobacion, COUNT(*) AS total
FROM tienda_pruebas.categorias
UNION ALL
SELECT 'Productos', COUNT(*)
FROM tienda_pruebas.productos
UNION ALL
SELECT 'Registros de tareas', COUNT(*)
FROM tienda_pruebas.registro_tareas;

Con el script inicial, los resultados esperados son:

ComprobaciónResultado esperado
Tablascategorias, productos, registro_tareas
Categorías3
Productos9
Registros de tareas0, si aún no hemos ejecutado eventos

La siguiente captura muestra la comprobación realizada en Workbench: el esquema restaurado, sus tres tablas y los recuentos en un único resultado.

Si la tabla registro_tareas ya contiene información por prácticas anteriores, su número de filas deberá coincidir con el de la base original en el momento de la copia.

Para contrastar ambas bases, ejecuta:

SELECT COUNT(*) AS productos_original FROM tienda_informatica.productos;
SELECT COUNT(*) AS productos_restaurados FROM tienda_pruebas.productos;

Una verificación más completa consiste en revisar algunos productos y sus campos, no solo el número de filas.

5️⃣ Alternativa gráfica: copia y restauración desde Workbench​

mysqldump es un programa del sistema operativo, no una sentencia SQL. Por eso no puede escribirse en el editor SQL de Workbench ni después del indicador mysql>. Sin embargo, MySQL Workbench incluye un asistente que utiliza mysqldump por debajo y permite hacer la misma operación sin escribir el comando.

🔶 Generar la copia: Data Export​

  1. En Workbench, abre Server → Data Export.
  2. Marca el esquema tienda_informatica y elige Dump Structure and Data.
  3. Selecciona Export to Self-Contained File e indica la ruta, por ejemplo C:\ASGBD\UT5\copia_tienda_wb.sql.
  4. Activa Create Dump in a Single Transaction: equivale a la opción --single-transaction.
  5. Deja desmarcada la opción Include Create Schema. Si se marca, el archivo incluye CREATE DATABASE y USE tienda_informatica, y al restaurarlo se modificaría la base original en lugar de la base de pruebas.
  6. Pulsa Start Export y revisa el registro de la parte inferior.

[IMAGEN. Pantalla Server → Data Export con tienda_informatica marcada, Export to Self-Contained File con la ruta C:\ASGBD\UT5\copia_tienda_wb.sql, Create Dump in a Single Transaction activada e Include Create Schema desmarcada]

🔶 Restaurar la copia: Data Import/Restore​

  1. Abre Server → Data Import.
  2. Elige Import from Self-Contained File y selecciona el archivo de copia.
  3. En Default Target Schema, selecciona una base de pruebas vacía o créala con New….
  4. Pulsa Start Import y comprueba el resultado con las mismas consultas del apartado anterior.
OperaciónDesde CMDDesde Workbench
Generar la copiamysqldump … > archivo.sqlServer → Data Export
Restaurar la copiamysql … base < archivo.sqlServer → Data Import
note

El asistente produce el mismo tipo de copia lógica. Los nombres de las opciones pueden variar ligeramente según la versión de Workbench. En esta unidad trabajamos sobre todo con la consola porque permite ver y entender el comando completo.

6️⃣ Errores habituales y buenas prácticas​

SituaciónQué revisar
'mysqldump' no se reconoce...Que la carpeta bin de MySQL esté incluida en PATH o utilizar la ruta completa del ejecutable.
Access deniedUsuario, contraseña y permisos necesarios para realizar la operación.
Unknown databaseNombre de la base y existencia de la base de origen o destino.
El archivo de copia no apareceCarpeta actual de CMD y ruta indicada tras >.
CREATE DATABASE tienda_pruebas devuelve database existsLa base ya existe; usa un nombre nuevo o comprueba su contenido antes de continuar.
La restauración reemplaza tablas existentesEn un volcado habitual, DROP TABLE IF EXISTS elimina las tablas existentes antes de recrearlas. No restaures sobre bases con datos que debas conservar.

Recuerda:

  • No escribas la contraseña directamente en el comando.
  • Conserva las copias fuera de ubicaciones compartidas sin protección: pueden contener datos sensibles.
  • Comprueba tanto la generación del archivo como su restauración.
  • Evita restaurar una copia de prueba encima de la base de datos original: el volcado puede borrar y recrear tablas sin pedir confirmación.
  • Ten en cuenta que la copia de este ejercicio incluye estructura y datos, pero no los eventos del Event Scheduler.

7️⃣ Actividad guiada: comprobamos nuestra copia​

Realiza estas operaciones con tienda_informatica:

  1. Genera copia_tienda.sql con mysqldump.
  2. Comprueba que se ha creado y no está vacío.
  3. Crea tienda_pruebas y restaura allí la copia.
  4. Comprueba las tablas y compara las cantidades de productos de ambas bases.
  5. Explica brevemente qué función cumplen mysqldump, mysql, > y <.

Resultado final: una copia lógica generada, una restauración realizada en una base independiente y evidencias de que los datos pueden recuperarse.

note

En este apartado ejecutamos la copia cuando lo decidimos. La planificación automática de instrucciones SQL mediante MySQL Event Scheduler se estudiará en el 5.4. Event Scheduler no ejecuta directamente mysqldump, que es una herramienta externa al servidor.

✅ Qué debes saber​

  • Explicar qué es una copia de seguridad lógica.
  • Reconocer la función de mysqldump y del cliente mysql.
  • Generar un archivo SQL con una copia de tienda_informatica.
  • Restaurarlo en una base de datos de pruebas.
  • Comprobar los resultados y detectar errores habituales (RA4.b y RA4.d).
  • Identificar mysqldump y mysql como herramientas administrativas con funciones distintas (RA4.c).
