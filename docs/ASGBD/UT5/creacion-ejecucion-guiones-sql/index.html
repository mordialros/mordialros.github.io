5.2. Creación y ejecución de guiones SQL

1️⃣ ¿Qué es un guion SQL?​

Un guion o script SQL es un archivo de texto que reúne instrucciones para ejecutarlas en un orden determinado. Normalmente se guarda con la extensión .sql.

En la administración de MySQL, un guion resulta útil para repetir comprobaciones, dejar documentadas las instrucciones utilizadas y evitar escribirlas una por una. Por ejemplo, podemos reunir en un mismo archivo consultas sobre la versión del servidor, la conexión utilizada y determinados parámetros de configuración.

-- Información básica del servidor
SELECT VERSION() AS version_mysql;
SELECT NOW() AS fecha_comprobacion;
SHOW VARIABLES LIKE 'max_connections';
important

Guardar un guion no significa programar su ejecución automática. En este apartado aprenderemos a crearlo y ejecutarlo cuando lo necesitemos. La ejecución automática de instrucciones SQL mediante el Event Scheduler se estudiará en el apartado 5.4.

2️⃣ Herramientas para redactar y ejecutar guiones​

Un archivo .sql es un archivo de texto plano con instrucciones SQL. Puede abrirse desde distintas herramientas: no depende del programa con el que se haya creado.

HerramientaFunción
MySQL WorkbenchRedactar, editar y guardar guiones SQL; también permite ejecutarlos. Será nuestro editor principal.
Otros editores (Visual Studio Code, Notepad++, DBeaver, phpMyAdmin)Alternativas para escribir o editar SQL; algunas también permiten ejecutarlo.
Cliente mysqlEjecutar instrucciones y archivos SQL desde una consola, con conexión al servidor.
CMD de WindowsIniciar el programa mysql con un archivo de entrada; no es un editor SQL.

En los ejemplos utilizaremos MySQL 8.0 en la máquina virtual con Windows 11 Pro. Para los comandos que incluyen < o > abre Símbolo del sistema (CMD), no Windows PowerShell. En Windows Terminal se puede elegir el perfil Símbolo del sistema. Trabajaremos con Workbench para escribir y guardar los guiones, y conoceremos después dos formas de ejecutarlos desde la consola. Redactar y ejecutar son funciones diferentes, aunque algunas herramientas realicen ambas.

3️⃣ Preparar la base de datos de prácticas​

Antes de empezar, crea en la máquina virtual la carpeta C:\ASGBD\UT5. Allí guardaremos los guiones y las copias de la unidad.

Como base de datos de prácticas utilizaremos tienda_informatica. Contiene datos ficticios que nos permitirán comprobar el funcionamiento de los guiones y eventos.

📥 Descargar tienda_informatica.sql

Este archivo prepara tres tablas:

TablaFinalidad
categoriasClasificación de productos.
productosProductos, precios y existencias.
registro_tareasRegistro de ejecuciones que utilizaremos con el Event Scheduler.

🔶 Cargar el archivo​

  1. Descargar tienda_informatica.sql y guardarlo en C:\ASGBD\UT5.
  2. Abrir el archivo en MySQL Workbench (File → Open SQL Script) y ejecutar su contenido completo para preparar la base.

El script crea la base si no existe, prepara las tablas y carga los registros iniciales sin duplicar los que tengan el mismo identificador. No elimina las tablas ya existentes.

🔶 Comprobar el resultado​

USE tienda_informatica;
SHOW TABLES;
SELECT * FROM categorias;
SELECT * FROM productos;
SELECT * FROM registro_tareas;

Resultado esperado: aparecen categorias, productos y registro_tareas. La tabla productos contiene 9 productos y registro_tareas está inicialmente vacía. Si ya se han ejecutado prácticas anteriores, esta última podría contener registros.

La existencia de las tablas puede observarse también en el panel SCHEMAS de Workbench, pero ejecutamos SHOW TABLES para practicar una comprobación mediante SQL.

4️⃣ Crear y guardar un guion desde MySQL Workbench​

Un guion legible debería incluir:

  • Un comentario inicial con su finalidad.
  • Las sentencias ordenadas según la operación que realizan.
  • Un punto y coma al final de las sentencias SQL.
  • Comentarios breves cuando una instrucción no sea evidente.
  • Ninguna contraseña escrita en el archivo.

En MySQL, los comentarios de una línea pueden comenzar por -- (dos guiones y un espacio).

🔶 Ejemplo: comprobación del servidor​

Paso 1. Abrir MySQL Workbench, conectarse al servidor MySQL y abrir una nueva pestaña de consultas SQL.

Paso 2. Escribir el siguiente guion:

-- Comprobación administrativa del servidor MySQL
-- UT5. Automatización de tareas

SELECT VERSION() AS version_mysql;
SELECT NOW() AS fecha_comprobacion;
SHOW DATABASES;

Paso 3. Guardar el guion desde File → Save As.... Elegir la carpeta C:\ASGBD\UT5 y el nombre comprobacion_servidor.sql.

Paso 4. Ejecutar todas las instrucciones mediante la opción de ejecutar el contenido del editor (botón del rayo correspondiente, no la opción que ejecuta solo la sentencia actual). Comprobar los resultados en las cuadrículas y el panel Action Output.

El archivo consulta información, pero no modifica bases de datos ni parámetros del servidor.

tip

Guardar un archivo .sql en Workbench no lo ejecuta ni programa su ejecución. Conviene distinguir las acciones de guardar, ejecutar y programar.

5️⃣ Ejecutar el mismo guion desde el cliente MySQL​

Ahora utilizaremos el archivo que acabamos de guardar con Workbench, sin volver a escribirlo.

El comando SOURCE permite leer y ejecutar un archivo desde una sesión abierta en el cliente mysql.

🔶 Ejecución paso a paso​

Paso 1. Abrir CMD y conectar con MySQL utilizando la cuenta de laboratorio autorizada:

mysql -u root -p

La contraseña se solicita a continuación. El ejemplo utiliza la cuenta administradora local del laboratorio; para otras tareas se debe utilizar una cuenta con los privilegios necesarios.

Si CMD no reconoce mysql, utiliza la ruta completa del ejecutable o configura su carpeta bin en PATH. Por ejemplo, en una instalación habitual:

"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p

La aplicación MySQL 8.0 Command Line Client permite entrar en el modo interactivo, pero no sustituye a CMD para ejecutar redirecciones como < ni para utilizar mysqldump.

Paso 2. Cuando aparezca el indicador mysql>, ejecutar:

SOURCE C:/ASGBD/UT5/comprobacion_servidor.sql;

Paso 3. Comprobar que aparecen los tres resultados: versión de MySQL, fecha y hora y listado de bases de datos. En el laboratorio se comprobó con MySQL Server 8.0.46; el número de versión y la fecha dependerán de cada equipo.

note

SOURCE es un comando del cliente mysql, no una sentencia SQL que pueda ejecutarse directamente en cualquier editor o aplicación. En las rutas de SOURCE utilizamos / aunque estemos trabajando en Windows.

6️⃣ Ejecutar el guion directamente desde CMD​

También podemos ejecutar el mismo archivo sin iniciar primero una sesión interactiva de MySQL.

Si seguimos dentro del cliente MySQL, salimos con:

EXIT;

Ya en CMD, ejecutamos:

mysql -u root -p < C:\ASGBD\UT5\comprobacion_servidor.sql

El cliente solicita la contraseña, procesa las instrucciones del archivo y finaliza. En este modo los resultados aparecen como texto sin los recuadros del modo interactivo. El símbolo < redirige el contenido del archivo a mysql: es una operación de CMD, no una sentencia SQL.

Si mysql no se reconoce desde CMD, puedes utilizar el ejecutable con su ruta completa, manteniendo la redirección:

"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p < C:\ASGBD\UT5\comprobacion_servidor.sql

La ruta puede variar según la instalación. Comprueba dónde está mysql.exe antes de utilizarla.

🔶 Comparación de métodos​

Método¿Cómo se inicia?Característica principal
WorkbenchAbriendo o redactando el guion en el editor.Permite editar, guardar, ejecutar y revisar los resultados gráficamente.
SOURCEDesde una sesión abierta del cliente mysql.Ejecuta el archivo reutilizando la conexión actual.
mysql con <Desde CMD, indicando un archivo de entrada.Ejecuta el guion sin entrar primero en una sesión interactiva.

Los tres métodos procesan las instrucciones del mismo archivo .sql. La principal diferencia es la forma de iniciar la ejecución y consultar los resultados. En la ejecución no interactiva con <, el cliente mysql normalmente se detiene ante un error SQL; la opción --force permite continuar, pero no la utilizaremos porque interesa detectar y corregir los fallos.

7️⃣ Comprobar resultados y reconocer errores​

Al ejecutar un guion conviene distinguir entre que se hayan procesado las instrucciones y que el resultado sea el esperado.

Algunos fallos habituales son:

SituaciónQué revisar
No se encuentra el archivoNombre y ruta utilizados en SOURCE o tras <.
No database selectedEl guion no incluye USE y la sesión no tiene una base seleccionada.
Error de sintaxis SQLInstrucción señalada en el mensaje y delimitadores ;.
Acceso denegadoCuenta utilizada y privilegios sobre la operación.
No existe una tablaBase de datos seleccionada y ejecución del script de preparación.

Para realizar comprobaciones, es preferible comenzar con guiones de solo lectura. Un guion que modifica datos debe revisarse antes de repetirlo, ya que ejecutarlo dos veces no siempre produce el mismo resultado.

8️⃣ Guiones que modifican datos​

Hasta ahora, nuestros guiones solo consultaban información. Sin embargo, muchas tareas que interesa automatizar modifican datos: actualizar precios, eliminar registros antiguos o reponer existencias. En estos casos hay que preguntarse siempre qué ocurre si el guion se ejecuta más de una vez.

🔶 Ejemplo 1. Actualizar precios: cuidado al repetir​

-- actualizar_precios.sql
-- Sube un 5 % los precios de la categoría 3
USE tienda_informatica;

START TRANSACTION;

UPDATE productos
SET precio = precio * 1.05
WHERE id_categoria = 3;

SELECT id_producto, nombre, precio
FROM productos
WHERE id_categoria = 3;

ROLLBACK;  -- Mientras se prueba. Cuando sea definitivo: COMMIT;

Cada ejecución vuelve a subir los precios: si el guion se lanza dos veces, la subida acumulada es del 10,25 %. Por eso lo probamos entre START TRANSACTION y ROLLBACK: vemos el resultado con el SELECT y los datos vuelven a su estado anterior. Solo cuando el resultado es el esperado sustituimos ROLLBACK por COMMIT.

🔶 Ejemplo 2. Limpiar registros antiguos: se puede repetir​

-- limpiar_registro.sql
-- Elimina los registros de más de 30 días
USE tienda_informatica;

DELETE FROM registro_tareas
WHERE fecha_ejecucion < NOW() - INTERVAL 30 DAY;

SELECT COUNT(*) AS registros_restantes
FROM registro_tareas;

Si se ejecuta dos veces seguidas, la segunda no encuentra nada más que borrar: el resultado es el mismo. Es un buen candidato para programarlo con un evento diario, como veremos en el apartado 5.4.

Por ahora registro_tareas está vacía, así que el guion no borrará ninguna fila. Tendrá sentido cuando los eventos del apartado 5.4 empiecen a añadir registros.

🔶 Ejemplo 3. Reponer existencias: dejar constancia​

-- reponer_stock.sql
-- Repone 20 unidades de los productos con menos de 10 y lo registra
USE tienda_informatica;

START TRANSACTION;

UPDATE productos
SET stock = stock + 20
WHERE stock < 10;

INSERT INTO registro_tareas (nombre_tarea, observaciones)
VALUES ('Reposición', 'Stock +20 en productos con menos de 10 unidades');

SELECT id_producto, nombre, stock FROM productos ORDER BY stock;

ROLLBACK;  -- En la práctica no conservamos el cambio

Además de modificar los datos, el guion anota en registro_tareas lo que ha hecho. Dejar constancia permite comprobar después qué tarea se ejecutó y cuándo. En el ejemplo terminamos con ROLLBACK para no alterar las existencias que utilizaremos en la práctica 5.5.

ROLLBACK deshace la inserción, pero no reinicia el contador AUTO_INCREMENT de id_registro. Si ejecutas este ejemplo, el primer registro que generen los eventos del apartado 5.4 no tendrá el identificador 1.

🔶 ¿Se puede repetir sin riesgo?​

Guion¿Repetirlo cambia el resultado?Precaución
actualizar_precios.sqlSí: los precios suben en cada ejecución.Probar con ROLLBACK y ejecutarlo una sola vez.
limpiar_registro.sqlNo: la segunda vez no hay nada que borrar.Revisar bien el WHERE antes de ejecutarlo.
reponer_stock.sqlSí: cada ejecución suma otras 20 unidades.Registrar la operación y comprobarla.
Antes de automatizar un guion que modifica datos
  • Pruébalo entre START TRANSACTION y ROLLBACK.
  • Revisa el WHERE: sin él, UPDATE y DELETE afectan a todas las filas.
  • Comprueba el resultado con un SELECT.
  • Piensa qué ocurriría si se ejecutara dos veces.
Error 1175 en Workbench

Workbench activa por defecto el modo Safe Updates, que rechaza un UPDATE o un DELETE cuyo WHERE no utilice una columna clave. Si aparece el Error 1175, puedes desactivarlo para la sesión con SET SQL_SAFE_UPDATES = 0; o desde Edit → Preferences → SQL Editor, volviendo a conectar después. Desde CMD o con SOURCE, el cliente mysql no activa este modo por defecto.

✏️ Ponlo en práctica: tu primer guion administrativo​

Crea el archivo diagnostico_servidor.sql en C:\ASGBD\UT5. Debe contener comentarios descriptivos e instrucciones que permitan:

  1. Identificar la versión de MySQL y la cuenta con la que se ejecuta utilizando CURRENT_USER().
  2. Consultar la fecha y hora del servidor.
  3. Mostrar los valores de max_connections y wait_timeout con SHOW VARIABLES.
  4. Consultar la base de datos seleccionada mediante SELECT DATABASE();.
tip

CURRENT_USER() devuelve la cuenta de MySQL que se ha autenticado para aplicar los privilegios de la sesión. Puedes consultarla con SELECT CURRENT_USER();.

Observa SELECT DATABASE();

Compara su resultado en los tres métodos. En Workbench puede mostrar el esquema seleccionado por defecto, pero al ejecutar el guion desde CMD con < devolverá NULL, porque la sesión no tiene ninguna base seleccionada. Por eso, un guion que consulte tablas debe incluir USE nombre_base; o escribir los nombres completos (base.tabla) si va a ejecutarse desde la consola.

Comprueba el trabajo creándolo y guardándolo primero desde Workbench. Ejecútalo allí y después mediante SOURCE desde la consola. Como tercera opción, pruébalo desde CMD con redirección de entrada y compara los resultados.

Evidencia de aprendizaje: conserva el archivo .sql y comprueba que ofrece resultados coherentes. Esta actividad es de práctica guiada; no necesita una entrega evaluable independiente.

✅ Qué debes saber​

  • Crear, editar y guardar archivos .sql desde MySQL Workbench e identificar otras herramientas de redacción (RA4.c).
  • Explicar las diferencias entre SOURCE, Workbench y la ejecución del cliente mysql con un archivo (RA4.b).
  • Crear, guardar, ejecutar y comprobar un guion con instrucciones administrativas (RA4.d).
  • Probar un guion que modifica datos y valorar si puede repetirse sin riesgo (RA4.d).
