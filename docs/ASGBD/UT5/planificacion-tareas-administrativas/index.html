5.4. Planificación de tareas administrativas

1️⃣ ¿Qué significa planificar una tarea?​

En el apartado anterior aprendimos a utilizar archivos .bat para ejecutar instrucciones administrativas de MySQL y guardar sus resultados. Sin embargo, para poner en marcha estos archivos todavía teníamos que abrir una consola y ejecutarlos manualmente.

Planificar una tarea consiste en configurar el sistema operativo para que ejecute un programa o un script en un momento determinado o cuando se cumpla una condición, sin que una persona tenga que iniciarlo cada vez.

Por ejemplo, una tienda de informática puede necesitar que el servidor registre su estado todos los días al comenzar la jornada. En lugar de ejecutar manualmente la comprobación, puede dejarla programada.

Conviene distinguir tres elementos:

ElementoFunciónEjemplo
ScriptContiene las instrucciones que se van a ejecutar.comprobar_estado.bat.
DesencadenadorDetermina cuándo se inicia la tarea.Todos los días a las 08:00.
PlanificadorEjecuta el script cuando se cumple el desencadenador.Programador de tareas de Windows.

Recuerda: ejecutar un script y programar su ejecución son operaciones diferentes. Primero debe comprobarse que el script funciona manualmente y después configurar su ejecución automática.

2️⃣ El Programador de tareas de Windows​

Windows 11 incluye una herramienta llamada Programador de tareas (Task Scheduler), que permite ejecutar automáticamente programas y scripts.

Entre sus posibilidades se encuentran:

  • Ejecutar una tarea a una hora determinada.
  • Repetirla diariamente o semanalmente.
  • Iniciarla cuando un usuario abre sesión o al arrancar el equipo.
  • Consultar la última ejecución y su resultado.

Para abrirla, escribe Programador de tareas en el menú Inicio de Windows.

🔶 Elementos principales de una tarea​

Al configurar una tarea, encontraremos varios apartados:

Apartado¿Qué se configura?
GeneralNombre de la tarea y cuenta de Windows con la que se ejecutará.
DesencadenadoresFecha, hora o condición que inicia la ejecución.
AccionesPrograma o script que Windows debe ejecutar.
CondicionesRequisitos adicionales, como determinadas condiciones de energía.
ConfiguraciónComportamiento si se produce un error o se pierde una ejecución.

El Programador de tareas pertenece a Windows, no a MySQL. Su función es iniciar el programa indicado; las operaciones sobre la base de datos las realizan las herramientas de MySQL que invoca el script.

3️⃣ Preparar un script para ejecutarlo sin intervención​

Un script destinado a ejecutarse de forma programada no puede detenerse para pedir una contraseña ni esperar a que alguien pulse una tecla.

Antes de programarlo, debemos revisar estos requisitos:

  1. Sin instrucciones interactivas: eliminar pause y cualquier otra orden que exija una respuesta manual.
  2. Rutas completas: especificar dónde están los scripts, las herramientas y los archivos de resultados.
  3. Autenticación preparada: permitir la conexión a MySQL sin escribir una contraseña dentro del .bat.
  4. Registro de resultados: guardar la salida y los errores para poder revisar la ejecución.
  5. Comprobación del fallo: devolver un código de salida que permita distinguir una ejecución correcta de una fallida.

🔶 Autenticación mediante un perfil de conexión​

En el apartado 5.3 utilizábamos mysql -u root -p. Esa forma sirve para una prueba manual, pero -p sin contraseña solicita que se introduzca por teclado, por lo que no es adecuada para una tarea desatendida.

MySQL 8.0 dispone de la utilidad mysql_config_editor, que permite guardar los datos de conexión en un perfil de conexión (login path). La contraseña no se escribe en el script ni aparece como texto legible en él.

Supongamos que ya existe en MySQL una cuenta de laboratorio denominada revision_tienda, con los permisos mínimos necesarios para realizar las consultas de comprobación.

Desde CMD, con el usuario de Windows que ejecutará la tarea:

mysql_config_editor set --login-path=revision_tienda --host=127.0.0.1 --user=revision_tienda --password

La utilidad solicitará la contraseña para almacenarla en el archivo de perfiles del usuario de Windows. Podemos comprobar qué perfiles existen con:

mysql_config_editor print --all

Las contraseñas aparecen ocultas. A partir de ese momento, podemos conectarnos usando:

mysql --login-path=revision_tienda

Comprueba que funciona antes de continuar. Si el comando mysql_config_editor no se reconoce, hay que localizar la carpeta bin de la instalación de MySQL o incorporarla al PATH, como se hizo con las demás herramientas.

Seguridad: el archivo de perfiles debe quedar protegido por los permisos de la cuenta de Windows. Este mecanismo evita poner la contraseña en el .bat, pero no sustituye la protección de la cuenta ni el principio de mínimo privilegio. La tarea programada debe ejecutarse con el mismo usuario de Windows que preparó el perfil, o disponer de su propia configuración de autenticación.

4️⃣ Ejemplo: preparar una comprobación automática​

Continuamos con el ejemplo de la tienda de informática del apartado anterior. Queremos ejecutar las consultas administrativas y guardar un registro de cada ejecución.

🔶 Paso 1. Revisar el archivo SQL​

En C:\scripts_mysql\estado_servidor.sql tendremos:

SELECT VERSION() AS version_mysql;
SELECT NOW() AS fecha_hora;
SHOW GLOBAL STATUS LIKE 'Threads_connected';

🔶 Paso 2. Crear el archivo por lotes​

Guardaremos el siguiente contenido en C:\scripts_mysql\comprobar_estado_programado.bat:

@echo off
set "CARPETA=C:\scripts_mysql"
set "REGISTRO=%CARPETA%\historial_estado.txt"

echo ---------------------------------------- >> "%REGISTRO%"
echo Inicio: %date% %time% >> "%REGISTRO%"

mysql --login-path=revision_tienda < "%CARPETA%\estado_servidor.sql" >> "%REGISTRO%" 2>&1

if errorlevel 1 (
    echo ERROR: fallo en la comprobacion. >> "%REGISTRO%"
    exit /b 1
)

echo OK: comprobacion completada. >> "%REGISTRO%"
exit /b 0

¿Qué hace este script?

  1. Define la carpeta de trabajo y el archivo donde se guardarán los resultados.
  2. Añade la fecha y la hora de inicio al registro.
  3. Ejecuta el archivo SQL con el perfil de conexión preparado.
  4. Guarda tanto los resultados como los posibles errores.
  5. Termina con exit /b 1 si falla el comando o con exit /b 0 si termina correctamente.

El operador >> permite conservar en el mismo archivo el resultado de varias ejecuciones.

🔶 Paso 3. Comprobarlo manualmente​

Antes de programar la tarea, desde CMD ejecutamos:

C:\scripts_mysql\comprobar_estado_programado.bat

Después abrimos C:\scripts_mysql\historial_estado.txt y comprobamos que aparecen la fecha, los resultados de las consultas y el mensaje final.

Si el script no funciona manualmente, no debemos programarlo todavía. Hay que resolver primero el error de conexión, permisos, rutas o ejecución.

5️⃣ Programar la tarea paso a paso​

Una vez probado el archivo .bat, configuraremos Windows para que lo ejecute automáticamente.

🔶 Paso 1. Crear la tarea​

  1. Abre el Programador de tareas.
  2. En el panel derecho, selecciona Crear tarea....
  3. En la pestaña General, escribe el nombre: Comprobacion MySQL tienda.
  4. Comprueba que se utiliza la cuenta de Windows que ha configurado el perfil de conexión.
  5. Para el laboratorio, selecciona inicialmente Ejecutar solo cuando el usuario haya iniciado sesión. Así resulta más sencillo comprobar su funcionamiento.

La opción Ejecutar tanto si el usuario inició sesión como si no permite una ejecución desatendida más completa, pero puede exigir credenciales adicionales y debe probarse con esa misma cuenta y su perfil de MySQL.

🔶 Paso 2. Configurar el desencadenador​

  1. Abre la pestaña Desencadenadores y pulsa Nuevo....
  2. Selecciona Según una programación.
  3. Elige una repetición Diaria.
  4. Establece una hora adecuada para la prueba; en el laboratorio, utiliza una hora próxima para poder observar la ejecución.
  5. Comprueba que el desencadenador esté Habilitado y acepta.

Una tarea diaria solo se iniciará a la hora indicada si se cumplen las condiciones configuradas. Que el equipo esté apagado o no esté disponible puede impedir la ejecución prevista.

🔶 Paso 3. Indicar qué programa debe ejecutarse​

  1. Abre la pestaña Acciones y pulsa Nueva....
  2. Selecciona Iniciar un programa.
  3. Introduce estos valores:
CampoValor
Programa o scriptC:\Windows\System32\cmd.exe
Agregar argumentos/c "C:\scripts_mysql\comprobar_estado_programado.bat"
Iniciar enC:\scripts_mysql

No incluyas comillas en el campo «Iniciar en». Es la carpeta de trabajo, no el nombre de un archivo.

En este ejemplo, CMD ejecutará el archivo por lotes y terminará. La carpeta de trabajo también está indicada, aunque los archivos del script ya utilizan rutas completas.

🔶 Paso 4. Revisar las condiciones​

En las pestañas Condiciones y Configuración revisa si hay opciones que puedan impedir la ejecución, por ejemplo una condición de alimentación que no se cumpla en la máquina virtual.

Guarda la tarea. No es necesario activar Ejecutar con los privilegios más altos para realizar esta comprobación con una cuenta limitada.

6️⃣ Comprobar que la tarea programada funciona​

Crear una tarea no demuestra que esté funcionando correctamente. Debemos probarla y revisar el resultado.

🔶 Ejecución de prueba​

  1. Localiza Comprobacion MySQL tienda en la Biblioteca del Programador de tareas.
  2. Haz clic derecho y selecciona Ejecutar.
  3. Comprueba la columna Estado y el campo Resultado de la última ejecución.
  4. Abre historial_estado.txt y verifica que se ha añadido un nuevo bloque con la fecha y los resultados.
  5. Espera a la hora programada para comprobar también que funciona el desencadenador.

Habitualmente, el resultado 0x0 indica que el programa terminó correctamente. Sin embargo, no basta por sí solo: también debemos revisar el archivo de registro y confirmar que se realizó la operación esperada.

Si es necesario, habilita el Historial de todas las tareas desde el panel de acciones del Programador para consultar los eventos de ejecución.

🔶 ¿Y si la tarea falla?​

Comprueba primero estos aspectos:

SíntomaPosible causa o comprobación
No se ejecuta a la hora previstaRevisar desencadenador, estado habilitado y condiciones.
Se inicia, pero no conecta con MySQLComprobar que el servidor está en marcha, la cuenta MySQL y el perfil de conexión.
Funciona desde CMD, pero no desde el ProgramadorRevisar el usuario de Windows, el directorio de trabajo y las rutas.
No aparece el archivo de resultadosComprobar permisos de escritura y ruta del registro.
El resultado indica un errorRevisar el código de salida y los mensajes guardados en el registro.

🔶 Prueba de un fallo controlado​

Para demostrar que el sistema detecta errores, podemos detener temporalmente el servicio MySQL en el laboratorio, ejecutar la tarea y observar el resultado registrado. Después, debemos volver a iniciar el servicio y repetir la comprobación.

Esta prueba se realiza únicamente sobre la máquina virtual de prácticas, nunca sobre un servidor en producción.

7️⃣ Buenas prácticas al planificar tareas​

  • Probar el script manualmente antes de programarlo.
  • Utilizar una cuenta de MySQL con los permisos mínimos y no incluir contraseñas en texto claro en los scripts.
  • Mantener las rutas completas y comprobar los permisos de lectura y escritura.
  • Conservar un registro de ejecuciones y errores, sin dejar que crezca indefinidamente.
  • Comprobar tanto el resultado del Programador de tareas como el resultado real de la operación.
  • Evitar programar varias ejecuciones simultáneas de una tarea que no esté preparada para ello.
  • Documentar qué tarea se ejecuta, cuándo, con qué usuario y dónde se guardan sus resultados.

✅ Qué debes saber​

Al finalizar este apartado debes ser capaz de:

  • Explicar qué es una tarea programada y distinguir entre script, desencadenador y planificador.
  • Identificar las funciones del Programador de tareas de Windows.
  • Preparar un script para que se ejecute sin intervención manual.
  • Configurar una tarea que ejecute un .bat de administración de MySQL.
  • Comprobar la ejecución, interpretar los resultados y localizar posibles errores.
  • Aplicar medidas básicas de seguridad al programar tareas administrativas.
