5.4. Planificación de tareas con MySQL Event Scheduler

1️⃣ ¿Qué significa planificar una tarea en MySQL?​

Hasta ahora hemos creado y ejecutado guiones SQL cuando los necesitábamos. Pero hay operaciones que interesa realizar en un momento concreto o de forma periódica, sin que una persona tenga que iniciar su ejecución cada vez.

MySQL dispone de un componente llamado Event Scheduler (programador de eventos). Permite definir eventos programados: objetos almacenados en una base de datos que ejecutan instrucciones SQL según un calendario.

Por ejemplo, una empresa podría registrar automáticamente una comprobación cada día o actualizar determinados datos durante la noche.

Ejecución¿Quién la inicia?Ejemplo
ManualUna persona desde Workbench o la consolaEjecutar una consulta de comprobación.
Mediante guion SQLUna persona lanza un archivo .sql con varias instruccionesEjecutar comprobacion_servidor.sql.
ProgramadaMySQL ejecuta el evento cuando correspondeRegistrar la ejecución de una comprobación cada día.
important

Un evento programado se ejecuta en función del tiempo. No debe confundirse con un disparador (trigger), que se activa al producirse una operación sobre una tabla, como INSERT, UPDATE o DELETE. Los disparadores se estudiarán en la UT6.

2️⃣ Comprobar y activar el programador de eventos​

Utilizaremos MySQL Workbench en la máquina virtual con Windows 11 Pro y la base de datos tienda_informatica, preparada en el apartado 5.2.

Para conocer el estado del programador, ejecuta:

SHOW VARIABLES LIKE 'event_scheduler';

La variable puede mostrar los siguientes valores:

ValorSignificado
ONEl programador está activado y puede ejecutar eventos habilitados.
OFFEl programador está detenido; los eventos no se ejecutan mientras permanezca así.
DISABLEDEl programador está deshabilitado desde el arranque; no puede activarse con un simple SET GLOBAL.

Si aparece OFF, una cuenta con los privilegios administrativos necesarios puede activarlo con:

SET GLOBAL event_scheduler = ON;

Después, vuelve a comprobar su estado:

SHOW VARIABLES LIKE 'event_scheduler';
note

Este cambio se aplica al servidor en funcionamiento y no garantiza que se conserve tras reiniciarlo. No modificaremos la configuración de arranque en esta práctica. Si el valor ya es ON, no es necesario cambiarlo.

3️⃣ Crear un evento programado​

La instrucción básica es:

CREATE EVENT nombre_evento
ON SCHEDULE programacion
DO instruccion_sql;
  • CREATE EVENT define un nuevo evento en la base de datos.
  • ON SCHEDULE establece cuándo debe ejecutarse.
  • DO indica la instrucción SQL que se ejecutará.

Se necesita el privilegio EVENT sobre la base de datos para crear y gestionar eventos. El evento ejecuta sus instrucciones con los permisos correspondientes a su definidor (DEFINER), por lo que también debe poder realizar la operación programada. En nuestro laboratorio utilizaremos la cuenta administrativa ya configurada; en un entorno real convendría una cuenta con permisos limitados.

🔶 Ejemplo: un evento que se ejecuta una sola vez​

En tienda_informatica tenemos una tabla registro_tareas con estos campos:

CampoFunción
id_registroIdentificador autoincremental.
nombre_tareaNombre de la tarea ejecutada.
fecha_ejecucionFecha y hora del registro (DATETIME, con DEFAULT CURRENT_TIMESTAMP).
observacionesInformación complementaria.

Vamos a registrar una ejecución automática un minuto después de crear el evento. Desde Workbench:

USE tienda_informatica;

CREATE EVENT evento_comprobacion
ON SCHEDULE AT CURRENT_TIMESTAMP + INTERVAL 1 MINUTE
DO
    INSERT INTO registro_tareas (nombre_tarea, observaciones)
    VALUES ('Comprobación automática', 'Evento ejecutado correctamente');
  • ON SCHEDULE AT ... fija un momento para una única ejecución.
  • DO introduce la sentencia que ejecutará MySQL cuando llegue ese momento.
  • No indicamos id_registro ni fecha_ejecucion: se generan automáticamente.

Comprueba que se ha creado:

SHOW EVENTS FROM tienda_informatica;

Si consultas los eventos después de su ejecución, es normal que ya no aparezca: MySQL elimina por defecto los eventos de ejecución única cuando terminan. Si quisiéramos conservar su definición, añadiríamos ON COMPLETION PRESERVE antes de DO.

Para observar el resultado, ejecuta la siguiente consulta después del minuto programado:

SELECT
    id_registro,
    nombre_tarea,
    DATE_FORMAT(fecha_ejecucion, '%d/%m/%Y %H:%i:%s') AS fecha_hora_ejecucion,
    observaciones
FROM tienda_informatica.registro_tareas
WHERE nombre_tarea = 'Comprobación automática'
ORDER BY id_registro;

Resultado obtenido en el laboratorio: se creó una fila con la tarea «Comprobación automática», la fecha y hora de ejecución y el texto «Evento ejecutado correctamente».

tip

Un evento que solo ejecuta SELECT no muestra su resultado en la ventana de Workbench. Para comprobar una ejecución programada necesitamos un efecto observable, como un registro insertado en una tabla.

4️⃣ Programar una ejecución periódica​

Con EVERY podemos establecer un intervalo de repetición. En el laboratorio utilizaremos un evento que registre una ejecución cada minuto:

USE tienda_informatica;

CREATE EVENT evento_periodico
ON SCHEDULE EVERY 1 MINUTE
DO
    INSERT INTO registro_tareas (nombre_tarea, observaciones)
    VALUES ('Comprobación periódica', 'Ejecución automática');

Comprueba que el evento está habilitado:

SHOW EVENTS FROM tienda_informatica;

En el resultado debe aparecer evento_periodico con tipo RECURRING, intervalo 1 MINUTE y estado ENABLED.

Para ver todas las ejecuciones, con fecha y hora completas, utiliza:

SELECT
    id_registro,
    nombre_tarea,
    DATE_FORMAT(fecha_ejecucion, '%d/%m/%Y %H:%i:%s') AS fecha_hora_ejecucion,
    observaciones
FROM tienda_informatica.registro_tareas
ORDER BY id_registro;

En nuestra prueba aparecieron varios registros de «Comprobación periódica» separados exactamente un minuto. La primera fila correspondía al evento de ejecución única.

warning

Este intervalo de un minuto es solo para comprobar el funcionamiento. Una vez verificados varios registros, desactiva el evento para evitar inserciones indefinidas.

ALTER EVENT tienda_informatica.evento_periodico DISABLE;

La desactivación se comprueba con SHOW EVENTS: debe aparecer Status = DISABLED. La desactivación no borra los registros ya generados.

5️⃣ Consultar, desactivar y eliminar eventos​

🔶 Consultar los eventos​

SHOW EVENTS FROM tienda_informatica;

Para ver la definición del evento periódico:

SHOW CREATE EVENT tienda_informatica.evento_periodico;

En MySQL Workbench también puedes consultar SCHEMAS → tienda_informatica → Events; actualiza el panel si no aparece el evento.

🔶 Activar, desactivar y eliminar​

-- Detener el evento sin borrarlo
ALTER EVENT tienda_informatica.evento_periodico DISABLE;

-- Reactivarlo cuando sea necesario
ALTER EVENT tienda_informatica.evento_periodico ENABLE;

-- Eliminarlo cuando ya no se necesite
DROP EVENT IF EXISTS tienda_informatica.evento_periodico;

En nuestra comprobación final dejamos evento_periodico desactivado, no eliminado. En el laboratorio del alumnado se puede eliminar al terminar, siguiendo las instrucciones de cada práctica.

note

No es lo mismo desactivar que eliminar. DISABLE conserva el objeto para usarlo después; DROP EVENT lo borra. Ninguna de las dos operaciones elimina las filas previamente insertadas en registro_tareas.

6️⃣ Comprobación de resultados y diagnóstico de errores​

Al crear un evento, MySQL puede aceptar la definición aunque la instrucción del cuerpo falle cuando llegue el momento de ejecutarse. Por tanto, que el evento aparezca en SHOW EVENTS no demuestra que haya realizado su tarea.

🔶 Qué comprobar si no funciona​

ComprobaciónInstrucción o acciónQué observar
ProgramadorSHOW VARIABLES LIKE 'event_scheduler';Debe estar en ON.
Existencia y estadoSHOW EVENTS FROM tienda_informatica;Evento habilitado; tipo y planificación correctos. Un evento único puede haber desaparecido tras ejecutarse.
DefiniciónSHOW CREATE EVENT tienda_informatica.evento_periodico;Revisar el SQL programado y el calendario.
ColumnasDESCRIBE tienda_informatica.registro_tareas;Verificar nombres, tipos y restricciones.
SentenciaProbar el INSERT manualmente, con precaución, en el entorno de prácticas.Comprobar si produce un error; evitar registros de prueba innecesarios.
ResultadoSELECT * FROM tienda_informatica.registro_tareas;Ver si existen las filas esperadas. Revisar los filtros WHERE.
Errores de ejecuciónConsultar el error log de MySQL si es necesario.Buscar el motivo de un fallo no mostrado en Workbench.

Se puede consultar también la última ejecución registrada de un evento mediante:

SELECT EVENT_NAME, STATUS, LAST_EXECUTED
FROM information_schema.EVENTS
WHERE EVENT_SCHEMA = 'tienda_informatica';

LAST_EXECUTED indica cuándo se intentó ejecutar el evento, pero no garantiza que su instrucción haya terminado correctamente.

🔶 Un error real encontrado en nuestra práctica​

En el primer intento se creó un evento con este fragmento:

INSERT INTO registro_tareas (descripcion, fecha_ejecucion)
VALUES ('Comprobación automática', NOW());

¿Qué ocurrió? No se insertó ningún registro porque descripcion no es una columna de registro_tareas. La tabla tiene nombre_tarea y observaciones. Lo comprobamos con:

DESCRIBE tienda_informatica.registro_tareas;

La instrucción correcta es:

INSERT INTO tienda_informatica.registro_tareas (nombre_tarea, observaciones)
VALUES ('Comprobación automática', 'Evento ejecutado correctamente');

En las pruebas del laboratorio se corrigió la instrucción y se creó un segundo evento para verificarla. En los pasos guiados de esta unidad utilizamos directamente el nombre evento_comprobacion. Un error en el cuerpo puede detectarse únicamente al llegar la hora programada.

🔶 Un resultado vacío no siempre significa que haya fallado​

Al consultar los registros del evento único utilizamos un filtro:

WHERE nombre_tarea = 'Comprobación automática'

Este filtro oculta los registros del evento periódico, cuyo nombre es «Comprobación periódica». Para comprobar ambas tareas hay que quitarlo o adaptar la condición.

important

Ante un fallo, comprueba la programación, la sentencia y el resultado. No crees nuevos eventos repetidamente sin identificar antes la causa.

7️⃣ Actividad guiada: comprobamos la planificación​

  1. Comprueba que el Event Scheduler esté en ON. Si aparece OFF, consulta cómo activarlo con una cuenta autorizada.
  2. Revisa la estructura de registro_tareas e identifica qué columnas se rellenan automáticamente.
  3. Crea un evento único que registre una comprobación dentro de un minuto. Verifica la fila insertada mostrando fecha y hora.
  4. Crea un evento periódico cada minuto. Comprueba que aparecen varias filas con marcas de tiempo diferentes.
  5. Desactiva el evento periódico y verifica su estado con SHOW EVENTS.
  6. Explica qué revisarías si el evento estuviera habilitado, pero no apareciera ningún registro.

✅ Qué debes saber​

Al terminar este apartado debes ser capaz de:

  • Explicar para qué sirve el Event Scheduler de MySQL.
  • Comprobar si está activado y reconocer los permisos necesarios.
  • Crear eventos de ejecución única y periódica.
  • Consultar, activar, desactivar y eliminar eventos.
  • Verificar mediante resultados observables que una tarea se ha ejecutado automáticamente.
  • Diferenciar un evento programado de un disparador.
  • Definir, ejecutar y comprobar instrucciones SQL programadas (RA4.b y RA4.d).
