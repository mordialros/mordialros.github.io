5.5. Aplicación práctica: automatización de una tarea administrativa

En los apartados anteriores hemos aprendido a crear archivos .sql, ejecutar comandos desde archivos .bat y planificar su ejecución con el Programador de tareas de Windows. Ahora vamos a reunir estos conocimientos para resolver una necesidad habitual de administración: realizar automáticamente una copia de seguridad de una base de datos y comprobar que puede recuperarse.

Trabajaremos con MySQL 8.0 y Windows 11 Pro, en la máquina virtual de prácticas. El ejemplo utiliza la base de datos de una tienda de informática.

1️⃣ ¿Qué queremos automatizar?​

La tienda guarda información sobre sus productos en la base de datos tienda_informatica. El personal técnico necesita preparar una tarea que:

  1. Genere una copia lógica de la base de datos.
  2. Guarde el resultado en un archivo .sql.
  3. Registre cuándo se ha ejecutado y si se ha producido un error.
  4. Se ejecute automáticamente a una hora determinada.
  5. Permita comprobar la recuperación de la información en otra base de datos.

Recuerda: en la UT3 ya se trabajó la realización y restauración de copias. Aquí el aprendizaje nuevo consiste en automatizar, programar y comprobar esa operación administrativa; no se pretende volver a estudiar las copias de seguridad desde el principio.

2️⃣ Preparar el entorno de trabajo​

Para realizar la práctica necesitamos:

  • El servicio de MySQL Server en funcionamiento.
  • El archivo de preparación tienda_informatica.sql, con las tablas categorias y productos y datos ficticios. Debe cargarse antes de comenzar.
  • Las herramientas mysqldump, mysql y mysql_config_editor accesibles desde CMD (mediante el PATH o su ruta completa).
  • Una carpeta de trabajo y una carpeta de copias con permisos de escritura para la cuenta de Windows que ejecutará la tarea.

Utilizaremos esta estructura:

C:\scripts_mysql\
    copia_tienda.bat
    copias\
        tienda_informatica.sql
    registros\
        historial_copias.txt
        errores_copia.txt

Crea las carpetas C:\scripts_mysql\copias y C:\scripts_mysql\registros antes de continuar.

🔶 Preparar y comprobar la base de datos​

Descarga el archivo tienda_informatica.sql y guárdalo, por ejemplo, en C:\scripts_mysql\. Desde el cliente MySQL, ejecútalo una vez con una cuenta que pueda crear la base de datos y sus tablas:

SOURCE C:/scripts_mysql/tienda_informatica.sql;

Después, comprueba que existe la base de datos:

SHOW DATABASES LIKE 'tienda_informatica';
USE tienda_informatica;
SHOW TABLES;

El script crea categorias y productos e incorpora 3 categorías y 9 productos. Comprueba los datos con SELECT COUNT(*) FROM productos;. No utilizaremos la base de datos del supuesto reservado para la prueba práctica.

3️⃣ Preparar una conexión para la copia​

Una tarea programada no debe detenerse para solicitar una contraseña. En el apartado 5.4 vimos cómo crear un perfil de conexión mediante mysql_config_editor.

En este ejemplo utilizaremos un perfil llamado copia_tienda. La cuenta MySQL asociada debe existir previamente y tener los permisos necesarios para leer los objetos que se van a copiar; no es necesario utilizar root para realizar una copia lógica.

Desde CMD, con la misma cuenta de Windows que ejecutará la tarea programada:

mysql_config_editor set --login-path=copia_tienda --host=127.0.0.1 --user=usuario_copias --password

Sustituye usuario_copias por la cuenta de MySQL preparada para el laboratorio e introduce su contraseña cuando se solicite. El perfil debe tener permisos suficientes para los objetos incluidos en la copia. Para una base con tablas y vistas pueden ser necesarios, entre otros, SELECT, SHOW VIEW y TRIGGER (si existen disparadores).

Comprueba la conexión:

mysql --login-path=copia_tienda -e "SHOW DATABASES LIKE 'tienda_informatica';"

Seguridad: no escribas la contraseña en el .bat, no la incluyas como argumento de los comandos y protege el perfil de conexión mediante los permisos de la cuenta de Windows.

4️⃣ Ejecutar la copia manualmente​

Antes de automatizar nada, probaremos el comando desde CMD:

mysqldump --login-path=copia_tienda --single-transaction --quick --no-tablespaces tienda_informatica > "C:\scripts_mysql\copias\tienda_informatica.sql"

🔶 ¿Qué significa cada parte?​

ElementoFunción
mysqldumpGenera una copia lógica mediante instrucciones SQL.
--login-path=copia_tiendaUtiliza el perfil de conexión configurado.
--single-transactionPermite obtener una copia consistente de las tablas transaccionales InnoDB sin bloquearlas para escritura durante el volcado.
--quickRecupera los registros progresivamente, sin cargarlos todos a la vez en memoria.
--no-tablespacesOmite sentencias relacionadas con la creación de espacios de tablas.
tienda_informaticaIndica la base de datos que se quiere copiar.
>Guarda la salida del comando en un archivo (sustituyendo su contenido si ya existe).

El archivo generado contiene las instrucciones necesarias para reconstruir los objetos y datos incluidos en el volcado. En este ejemplo se ha utilizado una base con tablas InnoDB y una carga de trabajo sencilla.

Comprueba que el comando termina sin errores, que existe el archivo y que no está vacío. Recuerda que la existencia de un archivo .sql no demuestra por sí sola que la copia sea válida.

5️⃣ Crear el script de automatización​

Vamos a guardar la operación anterior en C:\scripts_mysql\copia_tienda.bat, añadiendo un registro de ejecución y una comprobación básica de errores.

@echo off
set "CARPETA=C:\scripts_mysql"
set "COPIA=%CARPETA%\copias\tienda_informatica.sql"
set "HISTORIAL=%CARPETA%\registros\historial_copias.txt"
set "ERRORES=%CARPETA%\registros\errores_copia.txt"

echo ---------------------------------------- >> "%HISTORIAL%"
echo Inicio: %date% %time% >> "%HISTORIAL%"

mysqldump --login-path=copia_tienda --single-transaction --quick --no-tablespaces tienda_informatica > "%COPIA%" 2> "%ERRORES%"

if errorlevel 1 (
    echo ERROR: la copia no se ha completado. >> "%HISTORIAL%"
    if exist "%COPIA%" del "%COPIA%"
    exit /b 1
)

for %%F in ("%COPIA%") do if %%~zF EQU 0 (
    echo ERROR: el archivo de copia esta vacio. >> "%HISTORIAL%"
    exit /b 1
)

echo OK: copia generada correctamente. >> "%HISTORIAL%"
echo Fin: %date% %time% >> "%HISTORIAL%"
exit /b 0

🔶 ¿Qué incorpora este archivo respecto a la ejecución manual?​

  • Rutas definidas: identifica dónde se guarda la copia y dónde quedan los registros.
  • Registro de inicio y fin: permite revisar cuándo se ejecutó el script.
  • Captura de errores: 2> guarda los mensajes de error en errores_copia.txt.
  • Código de salida: if errorlevel 1 detecta un fallo comunicado por mysqldump.
  • Comprobación del archivo: verifica que la copia no esté vacía.
  • Resultado para Windows: exit /b 0 indica ejecución correcta y exit /b 1, ejecución fallida.

Limitaciones de este ejemplo: se utiliza siempre el mismo nombre de archivo, por lo que cada ejecución correcta sobrescribe la copia anterior. Además, un archivo no vacío no garantiza que su contenido pueda restaurarse. En un entorno real se conservarían varias copias según una política de retención, se evitaría perder la última copia válida durante la generación de una nueva y se realizarían verificaciones periódicas.

🔶 Probar el script​

Desde CMD ejecuta:

C:\scripts_mysql\copia_tienda.bat

Después comprueba:

  1. Que existe C:\scripts_mysql\copias\tienda_informatica.sql.
  2. Que contiene instrucciones SQL y no está vacío.
  3. Que historial_copias.txt incluye el resultado de la ejecución.
  4. Que errores_copia.txt no muestra errores relevantes.

Si aparece un error, corrígelo antes de programar la tarea.

6️⃣ Programar la ejecución automática​

Ahora configuraremos el Programador de tareas de Windows para ejecutar el .bat sin intervención manual.

  1. Abre el Programador de tareas y selecciona Crear tarea....
  2. En General, indica el nombre Copia automatica tienda y selecciona la cuenta de Windows que tiene configurado el perfil copia_tienda.
  3. Para esta prueba en el laboratorio, utiliza Ejecutar solo cuando el usuario haya iniciado sesión.
  4. En Desencadenadores, configura una ejecución diaria, a una hora próxima para poder observarla.
  5. En Acciones, selecciona Iniciar un programa e introduce:
CampoValor
Programa o scriptC:\Windows\System32\cmd.exe
Agregar argumentos/c "C:\scripts_mysql\copia_tienda.bat"
Iniciar enC:\scripts_mysql
  1. Revisa las Condiciones y guarda la tarea.
  2. Desde la Biblioteca del Programador, selecciona la tarea y pulsa Ejecutar para hacer una comprobación inicial.
  3. Comprueba también que se activa a la hora establecida por el desencadenador.

En un equipo de producción podría utilizarse la ejecución sin sesión iniciada, pero habría que verificar previamente que la cuenta de Windows, el perfil de conexión, las credenciales y los permisos funcionan en ese contexto.

Importante: una tarea puede aparecer como ejecutada en Windows aunque la operación administrativa no haya producido el resultado esperado. Revisa tanto el resultado del Programador como el registro y la copia creada.

7️⃣ Verificar la restauración de la copia​

La comprobación definitiva consiste en demostrar que los datos se pueden recuperar. No restauraremos sobre la base original, para evitar sobrescribir la información del laboratorio.

Desde una sesión de MySQL con una cuenta de administración del laboratorio que tenga permisos para crear una base de datos e insertar objetos y registros:

CREATE DATABASE tienda_verificacion;

Si tienda_verificacion ya existe de una prueba anterior, utiliza otro nombre o elimínala solo después de comprobar que es una base de pruebas.

Desde CMD, restaura el archivo en esa base de datos:

mysql -u root -p tienda_verificacion < "C:\scripts_mysql\copias\tienda_informatica.sql"

En este paso se introduce la contraseña manualmente. La restauración es una comprobación supervisada, no parte de la tarea programada. También podría utilizarse una cuenta de laboratorio con los permisos de restauración necesarios.

Conéctate a MySQL y verifica los objetos y los registros recuperados:

USE tienda_verificacion;
SHOW TABLES;
SELECT COUNT(*) FROM productos;

Con el script de preparación facilitado, la tabla productos contiene inicialmente 9 registros. Si después se han añadido o modificado datos, contrasta el resultado con el estado original en el momento de realizar la copia.

Conclusión: solo podemos considerar verificada la copia cuando la restauración termina sin errores y los datos esperados se recuperan correctamente.

8️⃣ Comprobar un fallo y documentar el resultado​

Una automatización administrativa también debe permitir detectar incidencias. Para probarlo de forma controlada, en la máquina virtual de laboratorio:

  1. Realiza primero una copia correcta y verifica su restauración.
  2. Detén temporalmente el servicio MySQL.
  3. Ejecuta copia_tienda.bat e identifica el mensaje de error y el resultado en historial_copias.txt.
  4. Vuelve a iniciar el servicio MySQL.
  5. Repite la ejecución y comprueba que vuelve a funcionar.

Atención: el script didáctico elimina el archivo de salida de una copia fallida, porque puede haber quedado incompleto. Por eso no debe utilizarse como sistema real de conservación de copias históricas. Realiza esta prueba únicamente sobre datos ficticios en la VM.

✅ Qué debes saber​

Al finalizar este apartado debes ser capaz de:

  • Convertir una operación administrativa manual en un script ejecutable.
  • Automatizar una copia lógica de MySQL mediante mysqldump y un archivo .bat.
  • Registrar el resultado y detectar errores básicos de ejecución.
  • Programar el script con el Programador de tareas de Windows.
  • Comprobar que la tarea se ejecuta automáticamente y produce el resultado esperado.
  • Verificar una copia mediante su restauración en una base de pruebas.
  • Explicar las medidas básicas de seguridad y las limitaciones de una automatización sencilla.
