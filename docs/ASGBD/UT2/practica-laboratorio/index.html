Práctica 2.1. Preparamos nuestro laboratorio

Duración orientativa: 120–165 minutos, según los recursos y la velocidad de descarga.
Organización: individual, con realización guiada en clase.
Entrega: sí, un único documento PDF en Classroom.
¿Qué vamos a trabajar? Instalación, documentación, verificación y resolución de incidencias del SGBD.
Evaluación: práctica evaluable, asociada a RA1.d, e, f, g, h, i y j.

1️⃣ Objetivo​

Creamos un laboratorio con MySQL Server en una nueva máquina virtual. Comprendemos qué instalamos y para qué sirve cada componente, comprobamos el funcionamiento del servidor y documentamos el proceso.

La guía utiliza VirtualBox y Ubuntu Desktop 24.04 LTS como referencia. En nuestro grupo realizamos la práctica con VMware y Windows 11 Pro, adaptando los pasos y manteniendo las comprobaciones y las evidencias solicitadas.

Punto de partida

Conservamos las instalaciones utilizadas en UT0 y comprobadas en UT1. Creamos una nueva VM de laboratorio tanto si trabajamos con equipo propio como si utilizamos un ordenador del aula. Registramos los pasos mientras los realizamos.

2️⃣ Guía de trabajo​

Descargamos la guía en PDF: Preparamos nuestro laboratorio de bases de datos

Seguimos el orden de la guía. Sus recuadros amarillos indican qué incluimos en el documento de entrega en cada paso.

La guía utiliza VirtualBox y Ubuntu como referencia. Para trabajar con VMware y Windows 11 Pro, adaptamos los pasos según las indicaciones siguientes. Realizamos únicamente la opción correspondiente a nuestro entorno.

🔸 Bloque 1. Preparamos la máquina virtual​

En ambos entornos, comprobamos RAM, CPU, espacio libre, virtualización y permisos del anfitrión antes de comenzar.

🛠️ Ubuntu · VirtualBox​

  1. Comprobamos o instalamos VirtualBox y descargamos la ISO de Ubuntu Desktop 24.04 LTS.
  2. Creamos la VM y asignamos los recursos acordados y la red NAT.
  3. Instalamos Ubuntu y comprobamos el primer arranque y la conexión a Internet.
  4. Apagamos la VM y creamos la instantánea «Ubuntu limpio».

🛠️ Windows · VMware​

  1. Comprobamos o instalamos VMware y obtenemos la ISO de Windows 11 Pro.
  2. Creamos la VM, asignamos los recursos acordados y la red NAT, y comprobamos los requisitos de Windows 11, incluidos TPM virtual y arranque seguro.
  3. Instalamos Windows 11 Pro y comprobamos el primer arranque y la conexión a Internet.
  4. Apagamos la VM y creamos la instantánea «Windows limpio».

En el documento, explicamos la función del programa de virtualización, el sistema operativo y la ISO. Justificamos la asignación de recursos y el uso de NAT.

Disco de destino

Instalamos el sistema operativo dentro de la nueva VM. Las opciones de borrar, formatear o crear particiones se aplican al disco virtual. Comprobamos que estamos trabajando dentro de la VM antes de continuar.

🔸 Bloque 2. Instalamos y verificamos MySQL Server​

🛠️ Ubuntu · Gestor de paquetes y Terminal​

  1. Actualizamos la lista de paquetes y consultamos la versión candidata.
  2. Revisamos los paquetes propuestos e instalamos MySQL Server.
  3. Comprobamos el servicio con systemctl, accedemos al cliente de consola mediante sudo mysql y ejecutamos las consultas de prueba de la guía.
  4. Salimos del cliente, detenemos el servicio e intentamos conectarnos de nuevo. Interpretamos el error y recuperamos el funcionamiento.
  5. Consultamos el registro de errores de MySQL y los mensajes del servicio mediante journalctl. Identificamos mensajes de parada y arranque.
  6. Apagamos la VM y creamos la instantánea «MySQL instalado».

🛠️ Windows · Instalador y herramientas del sistema​

  1. Obtenemos el instalador oficial de MySQL Server e identificamos su versión y los componentes disponibles.
  2. Instalamos MySQL Server y justificamos los componentes seleccionados. Configuramos el puerto 3306, la cuenta de administración y el servicio de Windows. Anotamos el nombre del servicio y conservamos la contraseña sin mostrarla en el documento.
  3. Comprobamos el servicio desde services.msc, accedemos mediante MySQL Command Line Client y ejecutamos las consultas de prueba de la guía.
  4. Salimos del cliente, detenemos el servicio desde Servicios e intentamos conectarnos de nuevo. Interpretamos el error, iniciamos el servicio y comprobamos que podemos acceder.
  5. Localizamos el registro de errores de MySQL, consultando su ubicación en la configuración de nuestra instalación. Identificamos mensajes de parada y arranque.
  6. Apagamos la VM y creamos la instantánea «MySQL instalado».

En el documento, explicamos qué hace MySQL Server, para qué sirve el cliente de consola y qué demuestra cada comprobación. Registramos las versiones, las opciones elegidas y los resultados obtenidos.

Sistema operativo y cliente MySQL

En Ubuntu, ejecutamos los comandos del sistema en la Terminal. En Windows, utilizamos PowerShell o las herramientas indicadas, como Servicios.

Las consultas SQL se ejecutan dentro del cliente MySQL, cuando aparece mysql>. Salimos con exit antes de continuar con la administración del servicio.

3️⃣ Incidencias de instalación​

Si encontramos una incidencia durante la instalación, registramos el mensaje, explicamos la causa, aplicamos una solución y comprobamos el resultado.

Si no aparece ninguna incidencia, realizamos el caso guiado correspondiente a nuestro sistema operativo. Simulamos un conflicto de puerto: otro proceso ocupa el 3306 e impide que MySQL lo utilice.

Realizamos todos los pasos dentro de la máquina virtual.

Partimos de una instalación de MySQL que funciona correctamente y utiliza el puerto 3306.

🛠️ Ubuntu · El servidor no puede iniciarse​

Herramientas: Terminal, systemd-socket-activate, ss y gestor de servicios systemctl.

Simulamos que otro proceso ocupa el puerto 3306. Debemos identificar por qué MySQL no puede iniciarse, liberar el puerto y comprobar el funcionamiento del servidor.

Realizamos los pasos dentro de la máquina virtual.

  1. Detenemos MySQL:

    sudo systemctl stop mysql

  2. Ocupamos temporalmente el puerto 3306:

    systemd-socket-activate --listen=127.0.0.1:3306 --inetd /usr/bin/cat

    Este comando mantiene un puerto a la escucha para una prueba. Dejamos abierta esta terminal y no intentamos conectarnos a ese puerto todavía.

  3. En otra terminal, intentamos iniciar MySQL:

    sudo systemctl start mysql

    El inicio debe fallar porque el puerto está ocupado. Consultamos el estado y los registros:

    sudo systemctl status mysql --no-pager
    sudo journalctl -u mysql -n 30 --no-pager
    sudo tail -n 30 /var/log/mysql/error.log

    Buscamos mensajes relacionados con el puerto ocupado, como Address already in use. Si el último archivo no existe, consultamos la ubicación del registro de errores de nuestra instalación.

  4. Identificamos el proceso que utiliza el puerto:

    sudo ss -ltnp 'sport = :3306'

    Anotamos el puerto, el proceso y su identificador. Explicamos por qué ese proceso impide iniciar MySQL.

  5. Volvemos a la primera terminal y pulsamos Ctrl + C para detener la simulación y liberar el puerto.

  6. Iniciamos MySQL y comprobamos su estado:

    sudo systemctl reset-failed mysql
    sudo systemctl start mysql
    systemctl status mysql --no-pager

    Debe aparecer active (running). El primer comando elimina el estado de fallo y restablece el límite de intentos de inicio, si se hubiera alcanzado.

🛠️ Windows · El configurador detecta un puerto ocupado​

Herramientas: Windows PowerShell, Servicios y MySQL Configurator o MySQL Installer.

  1. Si MySQL ya está funcionando, abrimos services.msc, anotamos el nombre de su servicio y lo detenemos.

  2. Abrimos Windows PowerShell y ocupamos temporalmente el puerto 3306:

    $listener = [System.Net.Sockets.TcpListener]::new([System.Net.IPAddress]::Any, 3306)
    $listener.Start()

    Mantenemos abierta esta ventana. Si Start() muestra un error, comprobamos que MySQL esté detenido.

  3. Abrimos el asistente de configuración de MySQL. Si ya está instalado, utilizamos MySQL Configurator o la opción Reconfigure de MySQL Installer.

    En Type and Networking, activamos TCP/IP e indicamos el puerto 3306. Registramos el aviso de puerto ocupado.

  4. En otra ventana de PowerShell, identificamos el proceso que utiliza el puerto:

    Get-NetTCPConnection -LocalPort 3306 -State Listen |
        Select-Object LocalAddress, LocalPort, State, OwningProcess

    Consultamos su nombre, sustituyendo 1234 por el identificador obtenido en OwningProcess:

    Get-Process -Id 1234

  5. Volvemos a la primera ventana y liberamos el puerto:

    $listener.Stop()

    Regresamos al configurador, volvemos a introducir 3306 y completamos la configuración conservando los datos de nuestra instalación. Comprobamos en Servicios que MySQL queda iniciado.

✅ Comprobamos y documentamos la solución​

En cualquiera de los dos sistemas, accedemos al cliente MySQL y ejecutamos:

SELECT VERSION(), @@hostname, @@port;
SELECT 2 + 3 AS resultado;

Comprobamos que el servidor responde, utiliza el puerto 3306 y devuelve 5 en la segunda consulta.

En el documento incluimos:

  • Intento fallido: qué estábamos haciendo y qué mensaje apareció.
  • Causa: por qué el puerto ocupado impide iniciar o configurar MySQL.
  • Solución: qué hicimos para liberar el puerto.
  • Comprobación final: cómo verificamos que MySQL funciona correctamente.

Acompañamos las evidencias con capturas explicadas brevemente e indicamos si la incidencia ha sido real o simulada.

Esta evidencia permite trabajar la resolución de incidencias de instalación y configuración del RA1, CE i.
