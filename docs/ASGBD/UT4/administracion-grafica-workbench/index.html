4.6. Administración gráfica con MySQL Workbench

En los apartados anteriores hemos administrado cuentas y privilegios mediante instrucciones SQL. Ahora realizaremos algunas de esas operaciones desde MySQL Workbench, utilizando su interfaz gráfica.

El objetivo no es aprender otra forma de hacer todas las prácticas, sino comprobar que las herramientas gráficas permiten administrar el mismo servidor y aplicar los mismos privilegios.

Dónde trabajamos
  • VM con Windows 11 Pro: instalamos MySQL Workbench si todavía no está disponible. Nos conectamos al MySQL Server de la propia VM con la cuenta administrativa local.
  • Base de datos: soporte_tic, que ya contiene las tablas y los registros utilizados durante la unidad.
  • Anfitrión: no lo utilizamos en esta práctica. Workbench permanece disponible allí para realizar conexiones remotas con cuentas limitadas, como en la UT3.

No habilitamos conexiones remotas de root ni modificamos la configuración de red.

1️⃣ Preparamos Workbench en la máquina virtual​

Si MySQL Workbench ya está instalado en la VM, podemos pasar directamente a la conexión.

En caso contrario, podemos instalarlo con MySQL Installer, seleccionando únicamente MySQL Workbench, o utilizar el instalador MSI de Workbench para Windows.

  • Descargar MySQL Workbench
  • Documentación oficial: instalación en Windows
warning

No vuelvas a instalar MySQL Server. El servidor ya está instalado y configurado desde las unidades anteriores; únicamente necesitamos añadir la herramienta gráfica.

La instalación en Windows puede requerir Microsoft Visual C++ Redistributable. Si el instalador indica que falta, instala el componente requerido antes de continuar.

🔶 Comprobamos la conexión administrativa local​

  1. Abre MySQL Workbench en la VM.

  2. Crea una conexión con el nombre Administracion_Local_UT4, utilizando los siguientes valores:

    CampoValor
    Connection MethodStandard (TCP/IP)
    Hostname127.0.0.1
    Port3306
    Usernameroot

  3. Pulsa Test Connection e introduce la contraseña cuando se solicite.

  4. Abre la conexión y ejecuta desde el editor SQL:

    SELECT COUNT(*) AS total_incidencias
    FROM soporte_tic.incidencias;

    Resultado esperado: 12 incidencias, si conservas los datos iniciales de la unidad.

en este ejemplo

La conexión utiliza la dirección de bucle local 127.0.0.1: Workbench y MySQL Server están en la misma VM. La cuenta administrativa no se está conectando desde el anfitrión.

2️⃣ Creamos una cuenta mediante la interfaz gráfica​

La empresa necesita una cuenta de consulta para una herramienta interna. La crearemos desde Workbench, en lugar de utilizar CREATE USER.

  1. Dentro de la conexión administrativa, abre Administration → Users and Privileges.

  2. En la pestaña Login, pulsa Add Account.

  3. Introduce los siguientes datos. Workbench puede proponer % por defecto en «Limit to Hosts Matching»; cámbialo por localhost para restringir esta cuenta a conexiones locales.

    CampoValor
    Login Namewb_consulta
    Limit to Hosts Matchinglocalhost
    Password / Confirm PasswordContraseña propia de laboratorio

  4. Pulsa Apply para guardar la cuenta.

Comprobación: abre una pestaña de consultas (SQL Editor) de la conexión administrativa y ejecuta:

SHOW GRANTS FOR 'wb_consulta'@'localhost';

Resultado esperado:

GRANT USAGE ON *.* TO `wb_consulta`@`localhost`
en este ejemplo

La cuenta ya existe, pero todavía no le hemos concedido acceso a los datos. Como vimos en el 4.1, crear una cuenta y conceder privilegios son operaciones diferentes.

3️⃣ Concedemos un privilegio desde Workbench​

La cuenta solo necesita consultar datos, no modificarlos.

  1. Vuelve a Administration → Users and Privileges y selecciona wb_consulta.
  2. Abre la pestaña Schema Privileges.
  3. Pulsa Add Entry y elige Selected schema: soporte_tic.
  4. En la entrada creada, marca únicamente el privilegio SELECT.
  5. Pulsa Apply para guardar los cambios.

Desde el editor SQL de la conexión administrativa, comprueba el resultado:

SHOW GRANTS FOR 'wb_consulta'@'localhost';

Resultado esperado (si la cuenta no tiene otros privilegios):

GRANT USAGE ON *.* TO `wb_consulta`@`localhost`
GRANT SELECT ON `soporte_tic`.* TO `wb_consulta`@`localhost`
Diferencia respecto a los ejemplos con SQL

En el 4.2 concedimos privilegios sobre la tabla soporte_tic.incidencias. En esta práctica, la pestaña Schema Privileges concede SELECT sobre toda la base de datos soporte_tic (soporte_tic.*).

Esto significa que la cuenta puede consultar también otras tablas de esa base de datos. Es importante comprobar siempre el alcance de un privilegio antes de concederlo.

4️⃣ Comprobamos las operaciones permitidas y denegadas​

Ahora debemos verificar que la configuración gráfica se aplica realmente.

Paso 1. Abrimos una conexión con la cuenta limitada

En Workbench, vuelve a la pantalla inicial y crea otra conexión:

CampoValor
Connection NameConsulta_Grafica_UT4
Connection MethodStandard (TCP/IP)
Hostname127.0.0.1
Port3306
Usernamewb_consulta

Conéctate utilizando la contraseña configurada en el apartado 2.

Paso 2. Probamos una operación permitida

Desde el editor SQL de Consulta_Grafica_UT4, ejecuta:

SELECT id_incidencia, titulo, estado
FROM soporte_tic.incidencias
WHERE id_incidencia = 1;

Resultado esperado: se muestra la incidencia 1.

Comprobamos también el alcance del permiso con otra tabla:

SELECT * FROM soporte_tic.usuarios;

Esta consulta también debería funcionar, aunque la cuenta solo necesitaba consultar incidencias: SELECT se ha concedido sobre toda la base de datos (soporte_tic.*). Es una comprobación práctica del principio de mínimo privilegio.

Paso 3. Probamos una operación denegada

Desde esa misma conexión limitada:

UPDATE soporte_tic.incidencias
SET estado = 'resuelta'
WHERE id_incidencia = 1;

Resultado esperado: MySQL rechaza la modificación porque wb_consulta no tiene el privilegio UPDATE (habitualmente, ERROR 1142 (42000)). En Workbench puedes consultar el error en el panel Output / Action Output.

en este ejemplo

Hemos creado la cuenta y concedido sus privilegios mediante la interfaz gráfica, pero el servidor sigue aplicando las mismas reglas de autorización que cuando utilizamos comandos SQL.

5️⃣ Retiramos el privilegio y comprobamos el resultado​

Una cuenta deja de necesitar acceso a los datos. En lugar de eliminarla, retiraremos su permiso de consulta.

  1. Regresa a la conexión administrativa Administracion_Local_UT4.
  2. Abre Administration → Users and Privileges → Schema Privileges y selecciona wb_consulta.
  3. Selecciona la entrada correspondiente a soporte_tic y retira el permiso SELECT. Si la entrada ya no necesita ningún privilegio, puedes utilizar Delete Entry para quitarla de la lista.
  4. Pulsa Apply para guardar los cambios.

Desde la conexión administrativa, verifica los privilegios restantes:

SHOW GRANTS FOR 'wb_consulta'@'localhost';

Cierra la pestaña o sesión Consulta_Grafica_UT4 y vuelve a conectarte con wb_consulta antes de repetir la prueba. Los cambios de privilegios a nivel de base de datos pueden no reflejarse inmediatamente en una sesión que ya estaba abierta.

Desde la nueva conexión, intenta:

SELECT id_incidencia, titulo
FROM soporte_tic.incidencias;

Resultado esperado: MySQL rechaza la consulta porque la cuenta ya no dispone de SELECT (habitualmente, ERROR 1142 (42000); consulta el panel Output / Action Output).

en este ejemplo

Retirar un privilegio no elimina la cuenta. La conexión sigue siendo posible, pero la operación sobre los datos se deniega. Es el mismo comportamiento que comprobamos con REVOKE en el 4.2.

🔶 Eliminamos la cuenta de prueba​

Una vez comprobada la retirada del privilegio, eliminamos la cuenta que ya no necesitamos, también desde la interfaz gráfica.

  1. Vuelve a la conexión administrativa Administracion_Local_UT4.

  2. Abre Administration → Users and Privileges y selecciona wb_consulta.

  3. Pulsa Delete y confirma o aplica la eliminación cuando Workbench lo solicite.

  4. Desde el editor SQL de la conexión administrativa, comprueba que la cuenta ya no existe:

    SELECT User, Host
    FROM mysql.user
    WHERE User = 'wb_consulta';

    Resultado esperado: ninguna fila (Empty set).

en este ejemplo

Hemos eliminado la cuenta con la herramienta gráfica y comprobado el resultado mediante SQL. Eliminar una cuenta no elimina las tablas ni los datos de soporte_tic.

Estado del laboratorio

Al finalizar la práctica, la cuenta de prueba wb_consulta ha sido eliminada. Las tablas y los registros de soporte_tic permanecen sin cambios.

🔎 Para saber más: opciones de administración en Workbench​

En Users and Privileges también aparecen opciones para asignar privilegios globales mediante Administrative Roles y modificar otros ajustes de las cuentas.

Estas opciones predefinidas de Workbench no son lo mismo que los roles de MySQL que creamos con CREATE ROLE en el 4.3. En esta práctica no necesitamos utilizarlas.
