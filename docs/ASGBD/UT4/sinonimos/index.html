4.5. Sinónimos de tablas y vistas

Hasta ahora hemos configurado quién puede acceder a los datos mediante cuentas, privilegios, roles y vistas. Los sinónimos sirven para algo diferente: administrar los nombres con los que las aplicaciones se refieren a las tablas y vistas. No son un mecanismo de seguridad y no conceden permisos.

Imaginemos que la empresa de soporte tiene una aplicación que utiliza el nombre tickets, mientras que la tabla real se llama incidencias. Un sinónimo permite mantener el nombre utilizado por la aplicación sin renombrar la tabla ni duplicar datos. Si el objeto cambia de esquema o de nombre, en determinados escenarios el administrador puede actualizar la referencia del sinónimo y evitar cambios en todas las consultas de la aplicación.

Dónde trabajamos

MySQL, nuestro gestor principal, no dispone de sinónimos nativos. Para este apartado utilizaremos «db<>fiddle» desde el navegador, seleccionando Oracle → 26ai → no sample DB. No instalaremos otro servidor ni modificaremos soporte_tic en la VM.

El entorno permite trabajar sin registro con datos de ejemplo. No introduzcas información personal o real en esta herramienta pública.

1️⃣ ¿Qué problema resuelve un sinónimo?​

Un sinónimo es un nombre alternativo que permite referirse a un objeto de la base de datos, como una tabla o una vista.

En una organización puede resultar útil para:

  • Simplificar nombres: consultar tickets en lugar de un nombre de objeto más largo.
  • Facilitar el mantenimiento: mantener el nombre utilizado por una aplicación si cambia el nombre o la ubicación del objeto original y se redefine el sinónimo.
  • Ofrecer nombres familiares: una aplicación puede utilizar tickets y otra incidencias para referirse al mismo objeto.

Un sinónimo no almacena una copia de los datos, no filtra filas ni concede permisos. Para utilizar el objeto original siguen siendo necesarios los privilegios correspondientes.

SinónimoVista
¿Qué define?Otro nombre para un objeto.Una consulta sobre una o varias tablas o vistas.
¿Puede filtrar filas o seleccionar columnas?No, por sí mismo.Sí.
¿Duplica los registros?No.No, en una vista convencional.

Por eso, un sinónimo de una tabla permite acceder a esa tabla con otro nombre, mientras que un sinónimo de una vista permite acceder a los resultados de la consulta definida por la vista.

2️⃣ ¿Por qué cambiamos de SGBD para esta práctica?​

Gestor¿Admite sinónimos nativos?
Oracle DatabaseSí, mediante CREATE SYNONYM.
Microsoft SQL ServerSí, mediante CREATE SYNONYM.
MySQLNo.
PostgreSQL estándarNo.

Para comprobarlos utilizaremos Oracle 26ai en una herramienta de navegador. No vamos a aprender a administrar Oracle: solo probaremos CREATE SYNONYM, su consulta y DROP SYNONYM. PostgreSQL estándar y MySQL no permiten demostrar este criterio con sinónimos nativos.

Preparación de «db<>fiddle»
  1. Abre «db<>fiddle».
  2. Selecciona Oracle, versión 26ai, y no sample DB.
  3. Coloca cada instrucción SQL en un bloque del editor. Puedes añadir bloques con + o utilizar split cuando haya varias instrucciones.
  4. Pulsa run para ejecutar los bloques en orden.

Importante: «db<>fiddle» ejecuta nuevamente el conjunto de bloques al pulsar run. Deja las consultas sobre los sinónimos antes de las instrucciones que los eliminan.

3️⃣ Creamos nombres alternativos para una tabla y dos vistas​

Trabajaremos con una pequeña tabla incidencias inspirada en nuestro gestor de soporte técnico. No necesitamos cargar toda la base de datos soporte_tic de MySQL.

🔶 Preparamos los datos de ejemplo​

Paso 1. Creamos la tabla

CREATE TABLE incidencias (
    id_incidencia NUMBER PRIMARY KEY,
    titulo VARCHAR2(100),
    estado VARCHAR2(20),
    id_tecnico NUMBER
);

Paso 2. Insertamos seis incidencias

INSERT ALL
    INTO incidencias VALUES (1, 'No se puede iniciar sesion', 'abierta', 1)
    INTO incidencias VALUES (2, 'Impresora sin conexion', 'en_proceso', 1)
    INTO incidencias VALUES (3, 'Red lenta', 'en_proceso', 2)
    INTO incidencias VALUES (4, 'Actualizacion pendiente', 'resuelta', 1)
    INTO incidencias VALUES (5, 'Correo no sincroniza', 'abierta', NULL)
    INTO incidencias VALUES (6, 'Pantalla sin imagen', 'en_proceso', NULL)
SELECT 1 FROM dual;

Al ejecutarlo, Oracle muestra 6 rows affected.

🔶 Creamos un sinónimo de una tabla​

Paso 1. Creamos el sinónimo

La sintaxis básica de Oracle es:

CREATE SYNONYM nombre_sinonimo FOR objeto_original;

En nuestro ejemplo:

CREATE SYNONYM tickets FOR incidencias;

Paso 2. Consultamos mediante el sinónimo

SELECT * FROM tickets;
en este ejemplo

La consulta devuelve las seis incidencias. tickets es otro nombre de la tabla incidencias: no crea una tabla nueva ni selecciona solo algunos registros.

🔶 Creamos un sinónimo de una vista de incidencias abiertas​

Paso 1. Creamos la vista

CREATE VIEW incidencias_abiertas AS
SELECT id_incidencia, titulo, estado
FROM incidencias
WHERE estado = 'abierta';

Paso 2. Creamos el sinónimo de la vista

CREATE SYNONYM tickets_abiertos
FOR incidencias_abiertas;

Paso 3. Consultamos mediante el sinónimo

SELECT * FROM tickets_abiertos;
en este ejemplo

Solo aparecen las incidencias 1 y 5, cuyo estado es abierta. La vista realiza el filtrado mediante WHERE; el sinónimo tickets_abiertos únicamente ofrece otro nombre para consultarla.

🔶 Comprobación complementaria: incidencias sin técnico asignado​

Paso 1. Creamos otra vista

CREATE VIEW incidencias_sin_asignar AS
SELECT id_incidencia, titulo, estado
FROM incidencias
WHERE id_tecnico IS NULL;

Paso 2. Creamos el sinónimo

CREATE SYNONYM tickets_sin_asignar
FOR incidencias_sin_asignar;

Paso 3. Consultamos los resultados

SELECT * FROM tickets_sin_asignar;
en este ejemplo

Ahora aparecen las incidencias 5 y 6, que no tienen técnico asignado. Los resultados son distintos de los de tickets_abiertos porque las vistas utilizan condiciones diferentes.

Idea clave: la vista determina qué información aparece; el sinónimo solo proporciona otro nombre para acceder a ella.

4️⃣ Comprobamos a qué objetos apuntan los sinónimos​

Oracle dispone de la vista del diccionario de datos USER_SYNONYMS, que permite consultar los sinónimos del esquema actual.

Paso 1. Consultamos los sinónimos creados

SELECT synonym_name, table_name
FROM user_synonyms
WHERE synonym_name IN (
    'TICKETS',
    'TICKETS_ABIERTOS',
    'TICKETS_SIN_ASIGNAR'
)
ORDER BY synonym_name;
en este ejemplo

La columna SYNONYM_NAME muestra el nombre alternativo; TABLE_NAME muestra el objeto al que hace referencia, tanto si es una tabla como si es una vista.

En este caso comprobamos que tenemos tres sinónimos distintos y que cada uno apunta al objeto previsto.

5️⃣ Eliminamos los nombres alternativos sin borrar los objetos​

Si ya no necesitamos un nombre alternativo, podemos eliminarlo con DROP SYNONYM.

Su sintaxis general es:

DROP SYNONYM nombre_sinonimo;

Paso 1. Eliminamos los sinónimos

DROP SYNONYM tickets;
DROP SYNONYM tickets_abiertos;
DROP SYNONYM tickets_sin_asignar;

Paso 2. Comprobamos que ya no existen

SELECT synonym_name, table_name
FROM user_synonyms
WHERE synonym_name IN (
    'TICKETS',
    'TICKETS_ABIERTOS',
    'TICKETS_SIN_ASIGNAR'
);
en este ejemplo

La consulta ya no devuelve filas: los tres sinónimos se han eliminado. Esto no significa que se hayan borrado las incidencias ni las vistas a las que hacían referencia.

Paso 3. Comprobamos que los objetos originales permanecen

SELECT * FROM incidencias;
SELECT * FROM incidencias_abiertas;
SELECT * FROM incidencias_sin_asignar;
en este ejemplo

Las tres consultas siguen funcionando y muestran los mismos registros. DROP SYNONYM elimina únicamente el nombre alternativo, no el objeto original.

🔎 Para saber más: sinónimos privados y públicos​

🔶 Sinónimos privados​

Son sinónimos definidos en un esquema concreto. Los que hemos creado con CREATE SYNONYM son privados.

CREATE SYNONYM tickets FOR incidencias;

📖 Documentación oficial de Oracle: CREATE SYNONYM

🔶 Sinónimos públicos​

Oracle permite crear sinónimos públicos, disponibles como nombres de referencia en la base de datos. No conceden por sí mismos permisos sobre el objeto original y su creación requiere privilegios especiales.

CREATE PUBLIC SYNONYM tickets_publicos FOR incidencias;

Es solo un ejemplo de sintaxis; no lo ejecutes en la práctica básica.

📖 Documentación oficial de Oracle: administración de sinónimos
