🔧 UT3. Poniendo a punto el motor

Configuración administrativa de MySQL Server

En la UT1 comprendimos qué vamos a administrar e identificamos nuestra instalación. En la UT2 creamos una máquina virtual, instalamos MySQL Server y comprobamos su funcionamiento. Ahora aprenderemos a adaptar su configuración a unos requisitos, verificar los cambios y documentar sus resultados.

Trabajaremos con MySQL Server instalado en la VM de VMware con Windows 11 Pro que hemos preparado en UT2. Conservamos este laboratorio para las siguientes unidades.

1️⃣ Resultado de aprendizaje y criterios de evaluación​

En esta unidad trabajamos la configuración administrativa del gestor, vinculada al siguiente resultado de aprendizaje:

RA2. Configura el sistema gestor de bases de datos interpretando las especificaciones técnicas y los requisitos de explotación.

Los criterios de evaluación asociados son:

  • a) Se han descrito las condiciones de inicio y parada del sistema gestor.
  • b) Se ha seleccionado el motor de base de datos.
  • f) Se han definido las características por defecto de las bases de datos.
  • g) Se han definido los parámetros relativos a las conexiones (tiempos de espera, número máximo de conexiones, entre otros).
  • h) Se ha documentado el proceso de configuración.

Al finalizar, debemos ser capaces de configurar MySQL Server según unos requisitos, comprobar el efecto de los ajustes y recuperar el estado inicial cuando corresponda.

El RA2 continuará en la UT4, donde trabajaremos la protección de las cuentas de administración, la configuración de clientes y la conectividad en red. La documentación acompañará también esas tareas.

2️⃣ ¿Qué debemos recordar?​

Para trabajar esta unidad necesitamos saber:

  • Diferenciar MySQL Server del cliente que utilizamos para conectarnos.
  • Acceder al servidor y ejecutar consultas y archivos SQL.
  • Comprobar el estado del servicio e iniciarlo o detenerlo desde Windows.
  • Identificar el servidor al que estamos conectados y su puerto.
  • Consultar el registro de errores e interpretar mensajes básicos.
  • Reconocer las tablas, claves, relaciones y transacciones trabajadas en UT0.
Consulta autónoma

Si necesitamos recuperar estos conocimientos, consultaremos la UT0, la UT1 y la guía de trabajo de la UT2. Los utilizaremos como punto de partida para configurar el laboratorio.

3️⃣ Nuestro caso: Centro Cívico La Estación​

El Centro Cívico La Estación organiza actividades culturales y formativas en dos sedes, Norte y Sur. Los usuarios se registran una sola vez y pueden inscribirse en actividades de cualquiera de ellas.

Inicialmente, toda la información se almacena en una base de datos centralizada gestionada por MySQL Server. Las dos sedes no implican que los datos estén distribuidos entre varios servidores.

Asumimos las tareas de administración técnica del sistema. En esta unidad recibiremos una ficha de requisitos y prepararemos la configuración del servidor para atenderlos.

Base de datos preparada

Utilizaremos unos scripts de creación, carga y comprobación de datos ficticios facilitados por el profesorado. Comprenderemos su estructura y comprobaremos su carga; el diseño de la base de datos estará resuelto para dedicar el trabajo a la administración del SGBD.

El caso nos acompañará en las siguientes unidades: gestionaremos accesos, automatizaremos tareas, analizaremos el rendimiento y trabajaremos la distribución y replicación de los datos.

4️⃣ Qué vamos a trabajar​

Partiremos de las necesidades del Centro Cívico La Estación para comprender qué debemos configurar en MySQL Server y qué precauciones tomamos antes de detenerlo o reiniciarlo.

Aprenderemos a consultar y modificar parámetros, diferenciando los que afectan a una sesión de los que afectan al conjunto del servidor. Comprobaremos también qué cambios son temporales y cuáles se conservan después de un reinicio.

Conoceremos los motores de almacenamiento y justificaremos la elección de InnoDB para nuestro caso. Definiremos el juego de caracteres y el cotejamiento por defecto de una base de prueba y utilizaremos el diccionario de datos para comprobar sus características.

Después ajustaremos parámetros relacionados con las conexiones, como su número máximo y los tiempos de espera, verificando el efecto de cada modificación.

Finalmente, aplicaremos los requisitos del centro en un laboratorio de configuración. Documentaremos los cambios, resolveremos una incidencia y recuperaremos el estado inicial cuando corresponda.

Idea clave

Antes de modificar un ajuste, debemos comprender qué controla y registrar su valor inicial. Después comprobaremos su efecto y dejaremos el laboratorio en el estado acordado.

Alcance de esta unidad

Nos conectaremos localmente, dentro de la VM. El acceso desde el anfitrión, los usuarios, los roles y los permisos se desarrollarán en la UT4. Utilizaremos los conocimientos de servicio, puerto y registros de las unidades anteriores cuando sean necesarios para verificar o diagnosticar los cambios.
