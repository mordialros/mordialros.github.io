📎 Anexo. Qué consultamos y dónde

En esta unidad utilizamos muchas variables, tablas e instrucciones. No necesitamos memorizarlas. Necesitamos saber qué tipo de información es cada una y dónde se encuentra. Volvemos a esta página siempre que aparezca algo que no sepamos situar.

1️⃣ Qué información nos da MySQL​

Todo lo que consultamos en la unidad pertenece a uno de estos cuatro grupos:

Tipo de informaciónQué respondeEjemplo
Variables del sistema¿Cómo está configurado el servidor?max_connections: límite de conexiones.
Variables de estado¿Qué está pasando o qué ha pasado?Threads_connected: conexiones abiertas ahora.
Metadatos¿Qué objetos existen y con qué propiedades?Motor y cotejamiento de cada tabla.
Variables de usuarioUn dato que guardamos nosotros mientras estamos conectados.@valor_inicial.

Las variables del sistema son ajustes: las cambiamos para configurar. Las de estado son contadores: solo las leemos para comprobar.

2️⃣ Una arroba o dos​

@@nombre@nombre
Qué esVariable del sistema: un ajuste del servidor.Variable de usuario: la creamos nosotros.
Quién le da valorMySQL: valor de fábrica, my.ini o un cambio administrativo.Nosotros, con SET @nombre = valor.
Cuánto duraSegún el ajuste: sesión, global o persistente.Solo mientras dura nuestra conexión.

Las combinamos para guardar un valor antes de cambiarlo:

SET @valor_inicial = @@SESSION.sql_safe_updates;

🔶 Global y sesión​

Una variable del sistema puede tener dos valores:

  • @@GLOBAL.nombre: el valor del servidor. En muchas variables, es el que reciben las conexiones nuevas.
  • @@SESSION.nombre: el valor de nuestra conexión. Si lo cambiamos, las demás conexiones no se enteran.

Si escribimos @@nombre sin indicar ámbito, MySQL devuelve el de sesión cuando existe y, si no, el global. Por eso indicamos siempre el ámbito. Algunas variables, como max_connections, solo tienen valor global.

🔶 Tres formas de consultar una variable​

Las tres devuelven el mismo dato con distinto formato:

FormaEjemploCuándo la usamos
SELECT @@SELECT @@GLOBAL.max_connections;Para ver uno o varios valores concretos.
SHOW VARIABLESSHOW GLOBAL VARIABLES LIKE '%timeout%';Para buscar por nombre con % como comodín.
Tablas de performance_schemaglobal_variables, variables_infoPara cruzar el valor con su origen o con lo guardado.

3️⃣ Los esquemas del sistema​

Además de nuestras bases, MySQL tiene esquemas propios. Los consultamos, pero no modificamos sus tablas directamente: para cambiar algo usamos las instrucciones administrativas.

EsquemaPara qué sirveTablas que usamos en la UT3
information_schemaDescribir los objetos: bases, tablas, columnas. Es la forma de consultar el diccionario de datos.SCHEMATA, TABLES, COLUMNS
performance_schemaInformar del funcionamiento del servidor: variables, sucesos, conexiones.global_variables, variables_info, persisted_variables, error_log, host_cache
mysqlGuardar información administrativa, como las cuentas.user, component
sysVistas que facilitan el diagnóstico.No la usamos en esta unidad.

🔶 Qué encontramos en cada tabla​

TablaQué contieneColumnas que miramosApartado
information_schema.SCHEMATAUna fila por base de datos.SCHEMA_NAME, DEFAULT_CHARACTER_SET_NAME, DEFAULT_COLLATION_NAME3.2, 3.4
information_schema.TABLESUna fila por tabla.TABLE_NAME, ENGINE, TABLE_COLLATION3.2, 3.4
information_schema.COLUMNSUna fila por columna.COLUMN_NAME, CHARACTER_SET_NAME, COLLATION_NAME3.4
performance_schema.global_variablesValor global actual de cada variable del sistema.VARIABLE_NAME, VARIABLE_VALUE3.2
performance_schema.variables_infoDe dónde salió el valor de cada variable.VARIABLE_SOURCE, VARIABLE_PATH3.2
performance_schema.persisted_variablesLo guardado con SET PERSIST para el siguiente arranque.VARIABLE_NAME, VARIABLE_VALUE3.2
performance_schema.error_logLos mensajes recientes del registro de errores, como tabla.LOGGED, PRIO, ERROR_CODE, DATA3.3
performance_schema.host_cacheInformación y errores de conexión por equipo de origen.Según el error que investiguemos.3.5
mysql.userUna fila por cuenta.User, Host3.6
mysql.componentComponentes instalados, como la política de contraseñas.component_urn3.6

Al consultar mysql.user aparecen cuentas como mysql.sys, mysql.session o mysql.infoschema. Son cuentas internas del servidor: no las usamos ni las borramos.

VariableQué indicaApartado

Threads_connectedConexiones abiertas ahora.3.2, 3.5
Max_used_connectionsMáximo de conexiones simultáneas alcanzado desde el arranque.3.5
Connection_errors_max_connectionsConexiones rechazadas por superar el límite.3.5
Aborted_connectsIntentos de conexión fallidos.3.5
Aborted_clientsConexiones cerradas sin terminar correctamente.3.5
Ssl_cipherCifrado de nuestra conexión. Si está vacío, no está cifrada.3.7

6️⃣ Instrucciones y funciones​

🔶 Para consultar​

Instrucción o funciónQué muestra
VERSION()Versión del servidor.
CONNECTION_ID()Número de nuestra conexión.
USER()Cuenta con la que nos presentamos y equipo de origen.
CURRENT_USER()Cuenta con la que MySQL nos ha autenticado.
SHOW PROCESSLISTConexiones abiertas y qué hace cada una.
SHOW ENGINESMotores disponibles y cuál es el predeterminado.
SHOW CHARACTER SET, SHOW COLLATIONJuegos de caracteres y cotejamientos disponibles.
SHOW WARNINGSAdvertencias de la última instrucción.
SHOW DATABASESBases visibles para nuestra cuenta.
SHOW GRANTS FORPermisos de una cuenta.
CHAR_LENGTH(), LENGTH()Longitud de un texto en caracteres y en bytes.
CONVERT(... USING utf8mb4)Interpreta unos bytes como texto. Lo usamos para escribir tildes sin teclearlas.

🔶 Para cambiar​

InstrucciónQué hace
SET SESSIONCambia un ajuste solo en nuestra conexión.
SET GLOBALCambia el valor del servidor hasta que se reinicie.
SET PERSISTLo cambia y lo guarda para los siguientes arranques.
SET PERSIST_ONLYLo guarda para el siguiente arranque sin cambiar el valor actual.
RESET PERSISTRetira lo guardado; no cambia el valor actual.
SET NAMESAjusta la codificación de nuestra conexión.
START TRANSACTION, COMMIT, ROLLBACKAgrupan cambios, los confirman o los deshacen.
SHUTDOWNDetiene el servidor desde SQL.
CREATE USER, ALTER USERCrean y modifican cuentas.

Dónde escribimos cada cosa

Las instrucciones SQL se escriben después de mysql>. Las herramientas de Windows se escriben en la ventana de cmd o PowerShell, no en el cuadro de Windows + R. Ese cuadro solo sirve para abrir programas como cmd, services.msc o wf.msc.
