3.4. Motores, juegos de caracteres y cotejamientos

Cuando creamos una base de datos o una tabla sin indicar todas sus características, MySQL aplica valores por defecto. En este apartado estudiaremos dos de los más importantes: el motor de almacenamiento y el juego de caracteres con su cotejamiento. Aprenderemos a elegirlos, a definirlos y a comprobar qué se ha aplicado realmente.

1️⃣ Motores de almacenamiento​

MySQL separa el procesamiento de las sentencias del almacenamiento de los datos. El componente que guarda y recupera los datos de una tabla es el motor de almacenamiento. Cada tabla utiliza un motor, y de él dependen características como las transacciones, las claves foráneas o la recuperación tras un fallo.

SHOW ENGINES;

[IMAGEN. Resultado de SHOW ENGINES con las columnas Engine, Support, Transactions y XA; InnoDB marcado como DEFAULT.]

La columna Support indica si el motor está disponible (YES), si es el motor por defecto (DEFAULT) o si no puede utilizarse (NO).

MotorTransaccionesClaves foráneasRecuperación tras falloUso habitual
InnoDBSíSíSíMotor general. Por defecto desde MySQL 5.5.
MyISAMNoNoLimitadaTablas heredadas de versiones antiguas.
MEMORYNoNoLos datos se pierden al reiniciarDatos temporales de acceso rápido.

BLACKHOLENoNo—Acepta escrituras y no guarda nada; uso en replicación.

Además de las transacciones, InnoDB bloquea filas en lugar de tablas completas cuando varias conexiones modifican datos a la vez. Esto permite que más usuarios trabajen simultáneamente.

🔸 Las transacciones marcan la diferencia​

Una transacción agrupa varias operaciones que deben completarse juntas o deshacerse juntas. Comprobamos la diferencia entre motores en una base de pruebas:

CREATE DATABASE pruebas_motores;
USE pruebas_motores;

CREATE TABLE t_innodb (id INT PRIMARY KEY) ENGINE = InnoDB;
CREATE TABLE t_myisam (id INT PRIMARY KEY) ENGINE = MyISAM;

START TRANSACTION;
INSERT INTO t_innodb VALUES (1);
INSERT INTO t_myisam VALUES (1);
ROLLBACK;

SHOW WARNINGS;
SELECT COUNT(*) FROM t_innodb;   -- 0: la inserción se ha deshecho
SELECT COUNT(*) FROM t_myisam;   -- 1: la inserción no se ha podido deshacer

ROLLBACK genera una advertencia: algunas tablas no transaccionales no han podido deshacerse.

[IMAGEN. Consola mysql con el ROLLBACK, la advertencia de SHOW WARNINGS y los dos recuentos (0 y 1).]

🔸 El motor por defecto​

Si creamos una tabla sin ENGINE, MySQL utiliza el valor de default_storage_engine:

SELECT @@default_storage_engine;

Para comprobar el motor de las tablas existentes utilizamos el diccionario:

SELECT TABLE_SCHEMA, TABLE_NAME, ENGINE
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'pruebas_motores';

Podemos cambiar el motor de una tabla existente. MySQL reconstruye la tabla, lo que en tablas grandes puede tardar:

ALTER TABLE t_myisam ENGINE = InnoDB;
Cómo justificamos la elección

Elegimos el motor a partir de los requisitos: si hay operaciones que deben completarse juntas, relaciones entre tablas que debemos proteger o varios usuarios modificando datos, necesitamos InnoDB. Un motor diferente solo se justifica con una necesidad concreta.

Las tablas del sistema de MySQL 8.0 también utilizan InnoDB.

2️⃣ Juegos de caracteres y cotejamientos​

Para guardar texto, el servidor necesita saber cómo representar cada carácter en bytes y cómo comparar y ordenar los textos.

  • Un juego de caracteres (character set) define qué caracteres se pueden guardar y cómo se codifican.
  • Un cotejamiento (collation) define cómo se comparan y ordenan los textos de un juego de caracteres.
SHOW CHARACTER SET LIKE 'utf8%';
SHOW COLLATION WHERE Charset = 'utf8mb4' AND Collation LIKE '%es%';

🔸 utf8mb4 frente a utf8​

JuegoBytes por carácterQué admite
utf8mb41 a 4Todo Unicode, incluidos emojis y muchos caracteres de otros idiomas. Por defecto en MySQL 8.0.
utf8mb31 a 3Solo parte de Unicode. Obsoleto.
utf8—En MySQL 8.0 es un alias de utf8mb3, no de utf8mb4.
utf8 no es UTF-8 completo

En MySQL, utf8 no admite todos los caracteres de UTF-8. Para guardar cualquier texto utilizamos utf8mb4.

La diferencia entre caracteres y bytes se comprueba con dos funciones:

SELECT CHAR_LENGTH(nombre) AS caracteres, LENGTH(nombre) AS bytes
FROM tabla;

En utf8mb4, las letras sin tilde ocupan 1 byte y las letras con tilde o la ñ ocupan 2. Si un texto con tildes muestra el mismo número de caracteres que de bytes, o aparecen caracteres deformados, se ha guardado con una codificación incorrecta.

🔸 Cómo se lee el nombre de un cotejamiento​

utf8mb4_es_0900_ai_ci se interpreta así:

ParteSignificado
utf8mb4Juego de caracteres.
esReglas del español. Sin idioma, se aplican reglas generales.
0900Versión del algoritmo Unicode utilizado (UCA 9.0.0).
ai / asSin distinguir acentos (accent insensitive) / distinguiéndolos (accent sensitive).
ci / csSin distinguir mayúsculas (case insensitive) / distinguiéndolas (case sensitive).
binCompara los códigos de los caracteres: lo distingue todo.

CotejamientoMayúsculasAcentosLa ñ

🔸 Comprobamos el efecto del cotejamiento​

Podemos indicar el cotejamiento de una comparación con COLLATE:

SELECT 'lopez' = 'LOPEZ' COLLATE utf8mb4_0900_ai_ci;   -- 1: no distingue mayúsculas
SELECT 'lopez' = 'LOPEZ' COLLATE utf8mb4_bin;          -- 0: lo distingue todo

Para comprobar acentos y ñ es más fiable consultar textos ya guardados que escribirlos en la consola:

-- Supongamos una columna apellidos con el valor 'Ibáñez'
SELECT apellidos FROM persona WHERE apellidos = 'ibanez' COLLATE utf8mb4_0900_ai_ci;     -- lo encuentra
SELECT apellidos FROM persona WHERE apellidos = 'ibanez' COLLATE utf8mb4_es_0900_ai_ci;  -- no lo encuentra: ñ ≠ n
SELECT apellidos FROM persona WHERE apellidos = 'ibanez' COLLATE utf8mb4_0900_as_ci;     -- no lo encuentra: distingue acentos
Tildes en la consola de Windows

Al escribir tildes o eñes directamente en la consola de Windows pueden producirse problemas de codificación entre el terminal y el cliente. Para pruebas con estos caracteres, utilizamos datos ya cargados, ejecutamos un archivo .sql guardado en UTF-8 o utilizamos una herramienta gráfica.

3️⃣ Dónde se definen: niveles y herencia​

El juego de caracteres y el cotejamiento se definen en varios niveles. Cada nivel toma el valor del anterior si no se indica otro:

Servidor  →  Base de datos  →  Tabla  →  Columna
NivelCómo se defineCómo se comprueba
Servidorcharacter_set_server, collation_serverSELECT @@character_set_server, @@collation_server;
Base de datosCREATE DATABASE ... CHARACTER SET ... COLLATE ...information_schema.SCHEMATA
TablaCREATE TABLE ... CHARACTER SET ... COLLATE ...information_schema.TABLES
Columnanombre VARCHAR(50) CHARACTER SET ... COLLATE ...information_schema.COLUMNS
-- Sin cláusulas: hereda los valores del servidor
CREATE DATABASE prueba_heredada;

-- Con cláusulas: valores explícitos
CREATE DATABASE prueba_explicita
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_es_0900_ai_ci;

SELECT SCHEMA_NAME, DEFAULT_CHARACTER_SET_NAME, DEFAULT_COLLATION_NAME
FROM information_schema.SCHEMATA
WHERE SCHEMA_NAME LIKE 'prueba_%';

[IMAGEN. Resultado de la consulta a SCHEMATA con prueba_heredada (utf8mb4_0900_ai_ci) y prueba_explicita (utf8mb4_es_0900_ai_ci).]

🔸 Cambiar los valores por defecto del servidor​

SET PERSIST character_set_server = 'utf8mb4';
SET PERSIST collation_server = 'utf8mb4_es_0900_ai_ci';
Qué cambia y qué no

Cambiar los valores del servidor solo afecta a las bases de datos que se creen después. Las bases existentes conservan los suyos, y sus tablas y columnas también.

Del mismo modo, ALTER DATABASE ... COLLATE ... solo afecta a las tablas nuevas de esa base. Convertir datos existentes es una operación distinta que requiere planificación y copia de seguridad.

🔸 El juego de caracteres de la conexión​

Además de cómo se guardan los textos, el servidor necesita saber en qué codificación le envía el cliente las sentencias y en cuál debe devolver los resultados:

SHOW SESSION VARIABLES LIKE 'character_set_c%';
SHOW SESSION VARIABLES LIKE 'character_set_results';

SET NAMES utf8mb4; indica al servidor que la conexión utiliza utf8mb4. Los scripts que cargan textos suelen empezar con esta sentencia, porque si el servidor interpreta mal los bytes recibidos, guardará textos deformados aunque la base sea utf8mb4.

Idea clave

Una base bien configurada no basta: también importa cómo llegan los textos. Comprobamos el resultado con CHAR_LENGTH y LENGTH sobre datos reales.
