3.3. Servicio y registros

En Windows, MySQL Server se ejecuta como un servicio: un programa que funciona en segundo plano, sin necesidad de que haya una sesión abierta. En este apartado aprenderemos a decidir cómo arranca, a detenerlo de forma controlada y a interpretar los registros donde el servidor deja constancia de lo que ocurre.

1️⃣ El servicio de MySQL Server​

El instalador registra el servidor como un servicio, normalmente llamado MySQL80. El servicio ejecuta mysqld.exe con el archivo de opciones indicado en --defaults-file.

Podemos gestionarlo de tres formas:

HerramientaCómo la abrimos
Consola de Serviciosservices.msc
Símbolo del sistema como administradorsc, net
PowerShell como administradorGet-Service, Set-Service, Start-Service, Stop-Service

🔸 Tipo de inicio​

El tipo de inicio determina si el servicio arranca con Windows:

TipoComportamientoCuándo lo utilizamos
AutomáticoArranca al iniciar Windows.Servidores que deben estar disponibles siempre.
Automático (inicio retrasado)Arranca poco después del inicio, cuando el sistema ya está cargado.Para no competir con otros servicios en el arranque.
ManualSolo arranca cuando lo iniciamos.Equipos de pruebas o desarrollo.
DeshabilitadoNo puede iniciarse.Servicios que no deben utilizarse.
sc qc MySQL80

El campo START_TYPE muestra AUTO_START (automático) o DEMAND_START (manual). Para cambiarlo:

sc config MySQL80 start= auto
sc config MySQL80 start= demand

En sc config hay que dejar un espacio después del signo igual.

[IMAGEN. Salida de sc qc MySQL80 en el Símbolo del sistema como administrador, con START_TYPE y BINARY_PATH_NAME señalados.]

🔸 Estado del servicio​

sc query MySQL80
Get-Service MySQL80

Que el servicio esté en ejecución no garantiza que podamos trabajar: también comprobamos que aceptamos conexiones y que el servidor responde.

SHOW GLOBAL STATUS LIKE 'Uptime';   -- segundos desde el último arranque

2️⃣ Detener e iniciar de forma controlada​

Una parada controlada permite al servidor terminar ordenadamente: deja de aceptar conexiones, cierra las existentes, escribe en disco la información pendiente y registra la parada. Disponemos de varias formas equivalentes:

DesdeDetenerIniciar
ServiciosBotón DetenerBotón Iniciar
Símbolo del sistema (administrador)net stop MySQL80net start MySQL80
PowerShell (administrador)Stop-Service MySQL80Start-Service MySQL80
Cliente de MySQLmysqladmin -u root -p shutdown—
Sesión SQLSHUTDOWN;—

mysqladmin shutdown y la sentencia SHUTDOWN detienen el servidor desde un cliente. Necesitan privilegios administrativos. El servicio de Windows aparecerá después como detenido.

Antes de detener, revisamos quién está conectado y qué está haciendo:

SHOW PROCESSLIST;
Parada controlada frente a terminación brusca

Terminar el proceso mysqld.exe desde el Administrador de tareas o con taskkill /F no es una parada: el servidor no puede cerrar ordenadamente. InnoDB está preparado para recuperarse, pero en el siguiente arranque tendrá que hacer una recuperación y lo indicará en el registro de errores. En un sistema real, las operaciones en curso pueden perderse.

Solo terminamos el proceso cuando el servicio no responde a una parada normal, y lo documentamos.

🔸 Después de iniciar​

  1. Comprobamos el estado del servicio.
  2. Nos conectamos e identificamos el servidor: SELECT VERSION(), @@hostname, @@port;
  3. Consultamos Uptime para confirmar que se ha reiniciado.
  4. Comprobamos los valores que motivaron el reinicio.
  5. Revisamos las últimas líneas del registro de errores.

3️⃣ Los registros del servidor​

MySQL Server puede escribir varios registros (logs). Cada uno tiene una función diferente:

RegistroQué guardaEstado habitual
Registro de erroresArranques, paradas, errores, advertencias y avisos del servidor.Siempre activo.
Registro generalCada conexión y cada sentencia recibida.Desactivado; se activa para diagnosticar.
Registro de consultas lentasConsultas que superan un tiempo determinado.Depende de la instalación. Lo trabajaremos en rendimiento.
Registro binarioLos cambios en los datos, para recuperación y replicación.Activo por defecto en MySQL 8.0. Lo trabajaremos en copias y replicación.

Comprobamos su estado y ubicación:

SHOW VARIABLES LIKE 'log_error%';
SHOW VARIABLES LIKE 'general_log%';
SHOW VARIABLES LIKE 'slow_query_log%';
SHOW VARIABLES LIKE 'log_bin%';
SELECT @@datadir;

Las rutas sin unidad son relativas a la carpeta de datos: C:\ProgramData\MySQL\MySQL Server 8.0\Data\.

4️⃣ El registro de errores​

A pesar de su nombre, el registro de errores no solo contiene errores. Cada línea tiene esta estructura:

2026-10-19T08:15:02.512345Z 0 [System] [MY-010931] [Server] C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqld.exe: ready for connections. Version: '8.0.46'  socket: ''  port: 3306  MySQL Community Server - GPL.
ParteSignificado
2026-10-19T08:15:02.512345ZFecha y hora en UTC (la Z final).
0Hilo que genera el mensaje. 0 es el propio servidor.
[System]Prioridad: System, ERROR, Warning o Note.
[MY-010931]Código del mensaje. Útil para buscarlo en la documentación.
[Server]Subsistema: Server, InnoDB, Repl…
RestoTexto del mensaje.
La hora del registro

La hora aparece en UTC. En España, en horario de invierno, hay que sumar una hora; en horario de verano, dos. Lo tenemos en cuenta al buscar un suceso concreto.

🔸 ¿Qué se registra? Verbosidad​

La variable log_error_verbosity decide qué mensajes se escriben:

ValorQué se escribe
1Errores.
2Errores y advertencias. Valor por defecto.
3Errores, advertencias y notas informativas.

Los mensajes de tipo [System], como el arranque, la disponibilidad para conexiones o la parada, se escriben siempre, con cualquier verbosidad.

SELECT @@log_error_verbosity;
SET GLOBAL log_error_verbosity = 3;   -- más detalle durante una intervención

Con verbosidad 3 veremos, por ejemplo, avisos sobre conexiones que se han cerrado de forma anómala. Durante un diagnóstico es útil; en funcionamiento normal genera más ruido.

🔸 Leer el registro​

Podemos abrir el archivo .err con el Bloc de notas o consultar sus últimas líneas desde PowerShell:

Get-Content "C:\ProgramData\MySQL\MySQL Server 8.0\Data\NOMBREPC.err" -Tail 20

Con el servidor en marcha, también podemos leerlo desde SQL:

SELECT LOGGED, PRIO, ERROR_CODE, SUBSYSTEM, DATA
FROM performance_schema.error_log
ORDER BY LOGGED DESC
LIMIT 15;

-- Solo errores y advertencias
SELECT LOGGED, PRIO, ERROR_CODE, DATA
FROM performance_schema.error_log
WHERE PRIO IN ('Error', 'Warning')
ORDER BY LOGGED DESC;

[IMAGEN. Resultado de la consulta a performance_schema.error_log, con mensajes System y Warning y la columna DATA legible.]

Si el servidor no arranca

La tabla performance_schema.error_log solo está disponible con el servidor en marcha. Si el servicio no arranca, abrimos el archivo .err.

Windows también registra el fallo del servicio en el Visor de eventos (Registros de Windows → Sistema), pero solo indica que el servicio se ha detenido. La causa está en el archivo .err.

🔸 Interpretar un fallo de arranque​

Si el archivo de opciones contiene una opción que el servidor no reconoce, el servicio no arranca y el registro muestra mensajes como estos:

2026-10-19T08:30:11.104512Z 0 [ERROR] [MY-000067] [Server] unknown variable 'max_conections=20'.
2026-10-19T08:30:11.105203Z 0 [ERROR] [MY-010119] [Server] Aborting

El primer error indica la causa: una opción mal escrita. El segundo indica la consecuencia: el servidor se detiene.

Leemos el registro de arriba abajo desde el último arranque y buscamos el primer [ERROR]. Los mensajes posteriores suelen ser consecuencias de él.

Ejemplo: el puerto ocupado

Si otro programa está utilizando el puerto del servidor al arrancar, el registro mostrará un error indicando que no puede utilizar el puerto TCP/IP.

Si provocamos esta situación y el registro no muestra nada, comprobamos primero si el servicio ha arrancado con sc query MySQL80. Si está en marcha, no hay error que registrar. Con netstat -ano | findstr :3306 vemos qué procesos están escuchando en ese puerto y en qué direcciones: en Windows, dos programas pueden escuchar en el mismo puerto si lo hacen en direcciones diferentes.

5️⃣ El registro general​

El registro general guarda cada conexión y cada sentencia que recibe el servidor. Es muy útil para comprobar qué hace un cliente o una aplicación, pero crece rápidamente y puede contener datos sensibles. Lo activamos solo durante una comprobación:

SHOW VARIABLES LIKE 'general_log%';   -- estado y archivo
SET GLOBAL general_log = 'ON';

-- ... realizamos la comprobación ...

SET GLOBAL general_log = 'OFF';

Cada línea indica la hora, el identificador de la conexión, el tipo de suceso (Connect, Query, Quit) y su contenido:

2026-10-26T09:12:40.118221Z	   15 Connect	consulta@192.168.10.1 on  using TCP/IP
2026-10-26T09:12:40.120057Z	   15 Query	SELECT VERSION()
2026-10-26T09:12:44.903311Z	   15 Quit

[IMAGEN. Archivo del registro general abierto en el Bloc de notas, con una conexión, varias consultas y la desconexión.]

Idea clave

El registro de errores nos dice qué le ha pasado al servidor. El registro general nos dice qué le han pedido los clientes. Ninguno sustituye al otro.
