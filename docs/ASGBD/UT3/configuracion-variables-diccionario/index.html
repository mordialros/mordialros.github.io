3.2. Configuración, variables y diccionario de datos

Antes de cambiar un ajuste necesitamos saber dónde se establece, qué valor tiene realmente y de dónde procede ese valor. En este apartado aprenderemos a localizar la configuración de MySQL Server, a consultar y modificar sus variables y a utilizar el diccionario de datos para comprobar los resultados.

1️⃣ Los archivos de configuración​

Cuando MySQL Server arranca, lee sus opciones de uno o varios archivos de opciones. En Windows, el instalador crea el archivo my.ini en la carpeta de datos del programa:

C:\ProgramData\MySQL\MySQL Server 8.0\my.ini

La carpeta ProgramData está oculta por defecto. Podemos escribir la ruta directamente en la barra de direcciones del Explorador.

¿Qué archivo utiliza realmente el servicio?

El servicio de Windows indica qué archivo debe leer el servidor mediante la opción --defaults-file. La comprobamos en las propiedades del servicio o con:

sc qc MySQL80

El campo BINARY_PATH_NAME muestra el ejecutable y el archivo de opciones. Si hubiera otro my.ini en otra carpeta, el servidor no lo utilizaría.

[IMAGEN. Propiedades del servicio MySQL80 en Servicios de Windows, pestaña General, con la «Ruta de acceso al ejecutable» que incluye --defaults-file y la ruta de my.ini.]

🔸 Estructura de my.ini​

El archivo se organiza en grupos de opciones. Cada grupo empieza con un nombre entre corchetes y se aplica a un programa concreto:

[client]
port=3306

[mysql]
no-beep

[mysqld]
port=3306
datadir=C:/ProgramData/MySQL/MySQL Server 8.0/Data
default-storage-engine=INNODB
max_connections=151
log-error="NOMBREPC.err"
GrupoA quién se aplica
[mysqld]Al servidor. Es el grupo que modificaremos en esta unidad.
[client]A todos los programas cliente de MySQL.
[mysql]Solo al cliente de consola mysql.

Las líneas que empiezan por # son comentarios. En los nombres de opción, el guion y el guion bajo son equivalentes: max-connections y max_connections indican la misma opción.

[IMAGEN. Fragmento del grupo [mysqld] de my.ini abierto en el Bloc de notas, mostrando port, datadir, default-storage-engine y las opciones de registros.]

Antes de editar my.ini
  • Hacemos una copia del archivo antes de modificarlo.
  • Lo editamos como administrador, porque está en una carpeta protegida.
  • No cambiamos su codificación al guardarlo.
  • Los cambios en my.ini solo se aplican al reiniciar el servicio. Un error en el archivo puede impedir que el servidor arranque.

2️⃣ Variables del sistema​

Cada opción de configuración se refleja en una variable del sistema mientras el servidor está en marcha. Las consultamos con SHOW VARIABLES o con la sintaxis @@:

SHOW VARIABLES LIKE 'max_connections';
SHOW VARIABLES LIKE '%timeout%';

SELECT @@max_connections, @@port, @@datadir;

SHOW VARIABLES admite el comodín % para buscar varias variables relacionadas.

🔸 Ámbito: global y de sesión​

Una variable puede existir en dos ámbitos:

ÁmbitoQué afectaEjemplo
GlobalAl servidor. Las conexiones nuevas toman su valor inicial de aquí.max_connections
SesiónSolo a la conexión actual. Desaparece al desconectarnos.sql_mode, wait_timeout

Algunas variables solo tienen ámbito global, otras solo de sesión y muchas tienen ambos.

SELECT @@global.wait_timeout, @@session.wait_timeout;
SHOW GLOBAL VARIABLES LIKE 'wait_timeout';
SHOW SESSION VARIABLES LIKE 'wait_timeout';
Ejemplo

Si cambiamos el valor global de wait_timeout, nuestra conexión actual conserva el valor de sesión que recibió al conectarse. Para comprobar el cambio necesitamos abrir una conexión nueva.

🔸 Variables dinámicas y de solo lectura​

  • Las variables dinámicas pueden modificarse con el servidor en marcha.
  • Las de solo lectura se establecen al arrancar: para cambiarlas hay que modificar la configuración y reiniciar.

Si intentamos modificar una variable de solo lectura o en un ámbito que no admite, MySQL nos lo indica:

ERROR 1238 (HY000): Variable 'port' is a read only variable
ERROR 1229 (HY000): Variable 'max_connections' is a GLOBAL variable and should be set with SET GLOBAL

La documentación de MySQL indica para cada variable si es dinámica, su ámbito, su valor por defecto y su rango.

3️⃣ Cómo modificamos una variable​

SentenciaQué cambia¿Se conserva tras reiniciar?
SET SESSION variable = valor;Solo nuestra conexión.No.
SET GLOBAL variable = valor;El valor global, para las conexiones nuevas.No.
SET PERSIST variable = valor;El valor global y lo guarda para los siguientes arranques.Sí.
SET PERSIST_ONLY variable = valor;Solo lo guarda para el siguiente arranque; no cambia el valor actual.Sí, al reiniciar.
RESET PERSIST variable;Elimina el valor guardado; no cambia el valor actual.Vuelve al valor de my.ini o al de por defecto en el siguiente arranque.
-- Cambio de prueba que se pierde al reiniciar
SET GLOBAL max_connections = 50;

-- Cambio que se conserva
SET PERSIST max_connections = 50;

-- Qué valores hemos guardado
SELECT * FROM performance_schema.persisted_variables;

SET GLOBAL y SET PERSIST necesitan privilegios administrativos. En esta unidad los ejecutamos con root, conectados localmente en la VM.

🔸 Dónde se guardan los valores persistentes​

SET PERSIST no modifica my.ini. Guarda los valores en el archivo mysqld-auto.cnf, en la carpeta de datos del servidor. Este archivo se lee después de my.ini, así que sus valores tienen prioridad.

Un cambio en my.ini que «no funciona»

Si un parámetro se ha persistido con SET PERSIST y después lo cambiamos en my.ini, al reiniciar prevalecerá el valor de mysqld-auto.cnf. Antes de modificar my.ini, comprobamos si el parámetro está persistido.

No editamos mysqld-auto.cnf a mano: lo gestionamos con SET PERSIST y RESET PERSIST.

🔸 Volver al estado inicial​

Para revertir completamente un cambio persistente necesitamos dos acciones:

RESET PERSIST max_connections;      -- deja de aplicarse en los siguientes arranques
SET GLOBAL max_connections = 151;   -- recupera ahora el valor inicial registrado

Por eso es imprescindible anotar el valor inicial antes de cambiarlo.

4️⃣ Valor efectivo y origen​

El valor efectivo es el que el servidor está utilizando ahora. Puede proceder del valor por defecto, de my.ini, de un valor persistido o de un cambio en marcha. La tabla performance_schema.variables_info nos indica el origen:

SELECT i.VARIABLE_NAME, g.VARIABLE_VALUE, i.VARIABLE_SOURCE, i.VARIABLE_PATH
FROM performance_schema.variables_info AS i
JOIN performance_schema.global_variables AS g USING (VARIABLE_NAME)
WHERE i.VARIABLE_NAME IN ('max_connections', 'wait_timeout', 'port', 'default_storage_engine');
VARIABLE_SOURCESignificado
COMPILEDValor por defecto del programa.
EXPLICITEstablecido en un archivo de opciones; VARIABLE_PATH indica cuál.
PERSISTEDEstablecido en mysqld-auto.cnf.
DYNAMICCambiado con el servidor en marcha, sin persistir.
COMMAND_LINEIndicado al arrancar el servidor desde la línea de comandos.

[IMAGEN. Resultado de la consulta anterior en la consola mysql, con al menos una variable EXPLICIT con la ruta de my.ini y otra COMPILED.]

Esta consulta es la mejor evidencia del estado inicial de un parámetro y de cómo ha quedado después de un cambio.

Variables de estado

Además de las variables del sistema, el servidor mantiene variables de estado que describen su actividad: tiempo en marcha, conexiones abiertas, errores… No se configuran: se consultan.

SHOW GLOBAL STATUS LIKE 'Uptime';
SHOW GLOBAL STATUS LIKE 'Threads_connected';

Las utilizaremos para comprobar el efecto de algunos ajustes.

5️⃣ El diccionario de datos​

El diccionario de datos contiene la descripción de todo lo que gestiona el servidor: bases de datos, tablas, columnas, restricciones, cuentas, juegos de caracteres… Desde MySQL 8.0 se almacena en tablas InnoDB internas que no consultamos directamente; accedemos a él mediante vistas y sentencias.

Base de datos del sistemaQué contieneEjemplo de uso
information_schemaVistas del diccionario según el estándar SQL.Motor y cotejamiento de cada tabla.
performance_schemaFuncionamiento interno del servidor en tiempo real.Origen de las variables, registro de errores, conexiones.
mysqlTablas del sistema: cuentas, privilegios, componentes.Cuentas existentes y desde dónde pueden conectarse.
sysVistas que resumen performance_schema en formato legible.Diagnóstico de rendimiento, en unidades posteriores.

No modificamos estas bases directamente. Las consultamos para comprobar lo que hemos configurado.

🔸 Consultas habituales en information_schema​

-- Bases de datos con su juego de caracteres y cotejamiento por defecto
SELECT SCHEMA_NAME, DEFAULT_CHARACTER_SET_NAME, DEFAULT_COLLATION_NAME
FROM information_schema.SCHEMATA;

-- Tablas de una base con su motor y su cotejamiento
SELECT TABLE_NAME, ENGINE, TABLE_COLLATION
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'nombre_base';

-- Columnas de texto con su juego de caracteres
SELECT TABLE_NAME, COLUMN_NAME, CHARACTER_SET_NAME, COLLATION_NAME
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'nombre_base' AND CHARACTER_SET_NAME IS NOT NULL;

-- Motores disponibles
SELECT ENGINE, SUPPORT, TRANSACTIONS FROM information_schema.ENGINES;

🔸 SHOW frente a information_schema​

Muchas sentencias SHOW son atajos para consultar el diccionario: SHOW DATABASES, SHOW TABLES, SHOW CREATE TABLE… Son cómodas para una consulta rápida.

Las vistas de information_schema permiten filtrar, combinar y ordenar con SELECT. Las utilizaremos cuando necesitemos comprobar varias tablas a la vez o guardar una evidencia clara en un script.

Idea clave

Configuramos con SET, archivos de opciones y herramientas del sistema. Comprobamos con el diccionario de datos y las variables de estado.
