1.1 ¿Qué vamos a administrar?

Hasta ahora hemos trabajado con tablas, relaciones e instrucciones SQL. En ASGBD ampliamos el foco: además de utilizar los datos, necesitamos comprender qué sistema los gestiona y cómo mantenerlo disponible, seguro y funcionando correctamente.

Tomaremos como referencia el centro cívico del repaso. Su base de datos guarda personas usuarias, actividades e inscripciones. Si una aplicación deja de conectarse, una consulta tarda demasiado o se pierde información, debemos saber qué revisar y cómo actuar.

¿Qué debemos recordar?

Una tabla organiza datos en filas y columnas. Las claves y las restricciones permiten identificar registros, relacionarlos y establecer condiciones que deben cumplirse. SQL nos permite definir estructuras, consultar y modificar datos y gestionar permisos. Si necesitamos recordar estas operaciones, consultamos la UT0.

1️⃣ Base de datos, SGBD y sistema de bases de datos​

Aunque a veces usamos estas expresiones como si fueran equivalentes, designan cosas diferentes.

ConceptoQué esEn nuestro entorno
Base de datos (BD).Un conjunto organizado de datos relacionados, con una estructura definida.Las tablas del centro cívico, sus datos y las relaciones y restricciones definidas.
Sistema gestor de bases de datos (SGBD).El software que permite definir, almacenar, consultar y modificar los datos, y controlar su acceso.MySQL Server.
Sistema de bases de datos.El conjunto formado por los datos, el SGBD y el entorno que permite utilizarlos: aplicaciones, personas, equipos y procedimientos.La base de datos del centro, MySQL Server, la aplicación de inscripciones, el personal que la utiliza y la infraestructura que la sostiene.

MySQL Workbench es una herramienta cliente: nos permite conectarnos a MySQL Server, enviar instrucciones y ver resultados. El servidor es quien gestiona los datos. Ambos programas pueden estar instalados en el mismo ordenador, pero desempeñan funciones diferentes.

Ejemplo

Si cerramos Workbench, cerramos nuestra herramienta de trabajo. El servidor puede seguir funcionando, y otras aplicaciones pueden continuar utilizando la base de datos. Si se detiene MySQL Server, las aplicaciones que dependen de él no podrán consultar esos datos hasta que vuelva a estar disponible.

2️⃣ ¿Qué funciones realiza un SGBD?​

Un SGBD hace más que guardar tablas. Coordina el acceso a los datos y ofrece mecanismos para trabajar con ellos de forma controlada.

FunciónPara qué sirveEjemplo en el centro cívico
Definir estructuras.Crear y modificar tablas, tipos de datos y restricciones.Establecer que cada actividad tenga un identificador único.
Consultar y modificar datos.Buscar información y realizar altas, cambios y bajas.Consultar las inscripciones de una actividad.
Mantener la integridad.Comprobar las reglas definidas en la base de datos.Rechazar una inscripción que haga referencia a una actividad inexistente mediante una clave foránea.
Controlar el acceso.Identificar a quien se conecta y comprobar qué puede hacer.Permitir que recepción gestione inscripciones sin poder administrar cuentas.
Gestionar transacciones y concurrencia.Coordinar operaciones y accesos simultáneos.Evitar que dos operaciones simultáneas dejen los datos en un estado incoherente.
Ofrecer mecanismos de recuperación.Facilitar la recuperación ante fallos mediante registros y herramientas de copia y restauración.Recuperar los datos a partir de una copia de seguridad comprobada.
Procesar las consultas de forma eficiente.Elegir cómo acceder a los datos y gestionar los recursos disponibles.Aprovechar un índice para localizar inscripciones sin recorrer siempre todos los registros.

Una transacción agrupa operaciones que tratamos como una unidad: confirmamos sus cambios con COMMIT o los deshacemos con ROLLBACK. La concurrencia aparece cuando varias conexiones trabajan con los datos al mismo tiempo.

El gestor no adivina las reglas del negocio

El SGBD aplica las restricciones y los mecanismos que hayamos definido. Tener una columna con el número de plazas no impide, por sí solo, superar el aforo de una actividad. Debemos diseñar el control correspondiente y contemplar las inscripciones simultáneas.

3️⃣ Los componentes de un SGBD y cómo trabajan juntos​

Podemos entender el gestor como un conjunto de componentes que colaboran. Son funciones internas, no necesariamente programas separados ni ventanas que podamos abrir. Su organización concreta depende del SGBD.

Componente o mecanismoDe qué se encarga
Gestión de conexiones y seguridad.Atiende conexiones, comprueba la identidad del usuario y verifica sus permisos.
Procesador de consultas.Analiza las instrucciones SQL, comprueba su validez, decide un plan de ejecución y coordina su ejecución.
Gestión del almacenamiento.Organiza el acceso a tablas, índices y páginas de datos, utilizando memoria y almacenamiento persistente.
Gestión de transacciones y concurrencia.Coordina confirmaciones y anulaciones, y controla la interacción entre operaciones simultáneas mediante mecanismos como bloqueos y versiones de los datos.
Diccionario de datos o catálogo.Conserva metadatos: información sobre tablas, columnas, tipos y otros objetos que el gestor necesita conocer.
Mecanismos de registro y recuperación.Registran información que ayuda a recuperar un estado coherente tras determinados fallos. Se complementan con una estrategia de copias de seguridad.

En esta unidad nos basta con reconocer la función general de estos componentes. El funcionamiento detallado de los bloqueos, las versiones de los datos, los registros y los procedimientos de recuperación se estudiará en unidades posteriores, cuando trabajemos la administración y la recuperación del servicio.

El optimizador forma parte del procesamiento de consultas. Compara posibles formas de obtener un resultado y elige un plan según sus estimaciones. Por ejemplo, puede decidir entre recorrer una tabla o utilizar un índice.

En MySQL encontramos motores de almacenamiento, como InnoDB. Un motor se ocupa de almacenar y recuperar los datos de las tablas que lo utilizan; InnoDB también proporciona mecanismos de transacciones, concurrencia y recuperación. No es otro servidor independiente: forma parte del funcionamiento de MySQL.

Datos y metadatos

En la tabla actividad, «Taller de fotografía» es un dato. Que la columna nombre admita hasta 150 caracteres y no permita valores nulos forma parte de los metadatos. El gestor necesita ambos para interpretar y controlar las operaciones.

Memoria y almacenamiento persistente

El gestor utiliza memoria para trabajar con rapidez y reducir accesos al disco. Los datos también necesitan almacenamiento persistente para conservarse al apagar el equipo. El momento y la forma de escribir los cambios dependen de los mecanismos del gestor; no debemos imaginar que cada instrucción equivale a escribir inmediatamente una fila en un fichero.

4️⃣ ¿Qué ocurre cuando ejecutamos una consulta?​

Supongamos que abrimos una conexión en Workbench y consultamos las actividades del centro:

SELECT nombre
FROM actividad
WHERE plazas_maximas > 20;
en este ejemplo

Pedimos el nombre de las actividades cuyo número máximo de plazas sea superior a 20. Para ejecutarla necesitamos seleccionar la base de datos del repaso y que existan la tabla y las columnas indicadas.

Al ejecutar la consulta, Workbench muestra dos informaciones:

  • Result Grid: presenta las filas que MySQL Server ha devuelto.
  • Action Output: registra la ejecución de la consulta, el número de filas devueltas y el tiempo emplead

De forma simplificada, el recorrido es el siguiente:

  1. El cliente envía la consulta. Workbench transmite el texto SQL al servidor a través de una conexión ya establecida.
  2. El servidor analiza y comprueba la petición. Verifica la sintaxis, resuelve los nombres de los objetos y comprueba los permisos necesarios, apoyándose en sus metadatos.
  3. El optimizador elige un plan. Decide cómo acceder a los datos. Que exista un índice no significa que siempre deba utilizarlo.
  4. Se ejecuta el plan. Los mecanismos de almacenamiento y de control de concurrencia permiten obtener los datos conforme a las reglas de la transacción. Parte de la información puede estar ya en memoria.
  5. El servidor devuelve el resultado. Workbench recibe las filas y las presenta en Result Grid. En Action Output queda registrado que la consulta se ha ejecutado correctamente, cuántas filas ha devuelto y cuánto ha tardado.

Este recorrido es una explicación general: los detalles y el orden de algunas comprobaciones dependen del gestor y de la operación.

Qué muestra cada zona de Workbench

Result Grid muestra los datos recibidos. Action Output muestra información básica sobre la ejecución en Workbench. Ninguna de las dos ventanas muestra todos los pasos internos que realiza MySQL Server.

5️⃣ El trabajo del administrador de bases de datos​

El administrador de bases de datos, también llamado DBA (Database Administrator), se ocupa de que el sistema esté preparado para prestar servicio y de mantenerlo durante su funcionamiento.

Sus tareas habituales incluyen:

  • Implantar y configurar el gestor. Preparar la instalación, comprobar el servicio y ajustar su configuración a las necesidades del entorno.
  • Gestionar accesos. Crear cuentas y asignar únicamente los permisos necesarios para cada función.
  • Proteger y recuperar los datos. Planificar copias de seguridad y comprobar que se pueden restaurar.
  • Supervisar el funcionamiento. Revisar errores, conexiones, espacio disponible y consumo de recursos.
  • Analizar el rendimiento. Investigar consultas lentas y valorar cambios en índices, consultas o configuración.
  • Mantener y documentar el sistema. Preparar actualizaciones y dejar constancia de los cambios y procedimientos de recuperación.

Una persona desarrolladora se centra en el comportamiento de la aplicación y en las operaciones que necesita realizar. El DBA se centra en el servicio de bases de datos que la sostiene. Ambas funciones colaboran y, en organizaciones pequeñas, pueden recaer en la misma persona.

Ejemplo: la aplicación no permite inscribir a nadie

No concluimos directamente que «la base de datos se ha roto». Comprobamos si el servidor está funcionando, si la aplicación puede conectarse, si su cuenta tiene permisos y qué error devuelve la operación. Cada comprobación nos ayuda a localizar la causa antes de cambiar nada.

Nos quedamos con estas ideas
  • La base de datos contiene la información; el SGBD la gestiona.
  • Workbench es una herramienta cliente y MySQL Server es el servidor al que nos conectamos.
  • El gestor coordina consultas, almacenamiento, permisos, transacciones y recuperación.
  • Administrar implica mantener el servicio, proteger los datos y saber diagnosticar problemas.
