0.4 Todo o nada

Hasta ahora hemos creado tablas, insertado datos, realizado consultas y modificado la información almacenada.

Pero algunas operaciones no deberían ejecutarse de forma independiente.

Hay situaciones en las que necesitamos que varias instrucciones se ejecuten como una única unidad: o se realizan todas correctamente o no se conserva ninguna.

Para eso utilizamos las transacciones.

La idea que vamos a recuperar es:

Iniciar → Ejecutar operaciones → Comprobar → Confirmar o deshacer

1️⃣ Trabajamos con transacciones​

Una transacción es un conjunto de operaciones que se tratan como una única unidad de trabajo.

Esto permite evitar que una operación quede realizada solo a medias.

Por ejemplo, imaginemos que al registrar un pedido necesitamos:

  • crear el pedido;
  • añadir una línea de pedido;
  • y descontar las unidades correspondientes del stock.

Estas operaciones están relacionadas. Si una de ellas falla, puede interesarnos que ninguna de las anteriores quede confirmada.

Para iniciar una transacción explícita utilizamos:

START TRANSACTION;

A partir de ese momento podemos ejecutar varias instrucciones antes de decidir qué hacer con los cambios.

Idea clave

Una transacción permite agrupar varias operaciones relacionadas y decidir al final si:

  • confirmamos todos los cambios;
  • o deshacemos todos los cambios realizados desde que comenzó la transacción.

2️⃣ Confirmamos los cambios con COMMIT​

Cuando todas las operaciones se han realizado correctamente utilizamos COMMIT.

COMMIT confirma los cambios de la transacción.

Por ejemplo:

START TRANSACTION;

UPDATE producto
SET stock = stock - 2
WHERE id_producto = 1;

COMMIT;
en este ejemplo

En este ejemplo:

  1. START TRANSACTION inicia una nueva transacción.
  2. UPDATE modifica el stock del producto.
  3. COMMIT confirma el cambio de forma definitiva.

Una vez realizado el COMMIT, ya no podemos utilizar ROLLBACK para deshacer ese cambio dentro de esa transacción.

COMMIT marca un punto de no retorno

COMMIT confirma todos los cambios pendientes de la transacción.

Antes de ejecutarlo conviene comprobar que las operaciones realizadas son realmente las que pretendíamos.

3️⃣ Deshacemos los cambios con ROLLBACK​

Si detectamos un problema antes de confirmar la transacción podemos utilizar ROLLBACK.

ROLLBACK deshace los cambios realizados desde el comienzo de la transacción.

START TRANSACTION;

UPDATE producto
SET stock = stock - 2
WHERE id_producto = 1;

ROLLBACK;
en este ejemplo

El UPDATE se ejecuta dentro de la transacción, pero ROLLBACK hace que el cambio no quede confirmado.

El stock recuperará el valor que tenía antes de iniciar la transacción.

ROLLBACK no viaja hacia atrás indefinidamente

ROLLBACK solo puede deshacer los cambios que todavía pertenecen a la transacción actual.

Los cambios que ya hayan sido confirmados mediante COMMIT no se deshacen con un ROLLBACK posterior.

4️⃣ Varias operaciones deben comportarse como una sola​

El verdadero valor de una transacción aparece cuando una operación necesita ejecutar varias instrucciones relacionadas.

Supongamos que queremos registrar un pedido.

Necesitamos:

  1. crear el pedido;
  2. registrar una línea de pedido;
  3. descontar del stock las unidades vendidas.

Podríamos hacerlo así:

START TRANSACTION;

INSERT INTO pedido
    (id_pedido, fecha_pedido, id_cliente)
VALUES
    (101, '2026-09-14', 1);

INSERT INTO linea_pedido
    (id_pedido, id_producto, cantidad, precio_unitario)
VALUES
    (101, 1, 2, 25.00);

UPDATE producto
SET stock = stock - 2
WHERE id_producto = 1;

COMMIT;
en este ejemplo

Las tres operaciones forman parte de la misma transacción.

Si todo es correcto, COMMIT confirma:

  1. el pedido;
  2. su línea de pedido;
  3. y la modificación del stock.

De esta forma, el conjunto completo se trata como una única unidad de trabajo.

Ahora imaginemos que alguna de las operaciones falla o que detectamos un dato incorrecto antes de confirmar.

Podemos ejecutar:

ROLLBACK;

y evitar que el pedido quede registrado solo de forma parcial.

Todo o nada

Esta es la idea fundamental de la atomicidad:

o se completan todas las operaciones que forman la transacción o no se conserva ninguna.

En este repaso nos centraremos especialmente en esta propiedad de las transacciones.

5️⃣ Comprobamos antes de confirmar​

No tenemos por qué ejecutar COMMIT inmediatamente después de modificar los datos.

Mientras la transacción siga abierta podemos realizar consultas para comprobar el resultado de las operaciones.

Por ejemplo:

START TRANSACTION;

UPDATE producto
SET stock = stock - 2
WHERE id_producto = 1;

SELECT id_producto, nombre, stock
FROM producto
WHERE id_producto = 1;

Después de comprobar el resultado podemos decidir:

COMMIT;

o:

ROLLBACK;
Primero comprueba, después decide

Cuando trabajes con una transacción:

  1. inicia la transacción;
  2. realiza las operaciones necesarias;
  3. consulta los datos si necesitas comprobar el resultado;
  4. utiliza COMMIT si todo es correcto;
  5. utiliza ROLLBACK si necesitas deshacer los cambios.

6️⃣ ¿Qué ocurre con AUTOCOMMIT?​

MySQL suele trabajar con autocommit activado.

Esto significa que, fuera de una transacción explícita, cada instrucción que modifica los datos puede quedar confirmada automáticamente al terminar.

Por ejemplo:

UPDATE producto
SET stock = 15
WHERE id_producto = 1;

Si esta instrucción se ejecuta con autocommit activado y no forma parte de una transacción explícita, el cambio queda confirmado.

Sin embargo, podemos iniciar una transacción mediante:

START TRANSACTION;

y agrupar varias instrucciones antes de decidir si utilizamos COMMIT o ROLLBACK.

No confundas ejecutar con confirmar

Una instrucción puede haberse ejecutado correctamente y, sin embargo, seguir formando parte de una transacción pendiente de confirmar.

Por eso es importante saber si estamos trabajando:

  • con operaciones independientes;
  • o dentro de una transacción explícita.

7️⃣ En resumen​

Las transacciones permiten tratar varias operaciones relacionadas como una única unidad de trabajo.

  • START TRANSACTION → inicia una transacción.
  • COMMIT → confirma todos los cambios realizados.
  • ROLLBACK → deshace los cambios pendientes de la transacción actual.
  • La atomicidad garantiza la idea de todo o nada.
  • Podemos consultar los datos antes de decidir si confirmamos o deshacemos.
  • Con autocommit activado, las operaciones realizadas fuera de una transacción explícita pueden confirmarse automáticamente.
Idea clave

Cuando varias modificaciones dependen unas de otras, no debemos pensar en ellas como instrucciones independientes.

Debemos preguntarnos:

¿Tiene sentido que una operación quede realizada si las demás fallan?

Si la respuesta es no, probablemente necesitamos una transacción.
