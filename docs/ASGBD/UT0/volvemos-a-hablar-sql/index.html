0.2 Volvemos a hablar SQL

Una vez definido el modelo relacional, llega el momento de trabajar con los datos. Para ello utilizaremos SQL, el lenguaje que nos permite comunicarnos con el sistema gestor de bases de datos.

En este apartado vamos a recuperar las instrucciones fundamentales que ya utilizamos en primero para crear la estructura de la base de datos, consultar información y modificar los datos almacenados.

Recorrido de trabajo
🛠️ Preparamos la estructura→📥 Introducimos los datos→🔎 Buscamos la información que necesitamos→🧭 La filtramos y la ordenamos→✏️ Actualizamos los datos→🗑️ Eliminamos lo que ya no necesitamos

1️⃣ Del modelo relacional a MySQL​

Ya tenemos definido qué tablas necesitamos, qué columnas tendrá cada una, qué tipo de información almacenará cada columna, cómo se relacionan y qué restricciones deben cumplir los datos.

El siguiente paso es trasladar ese diseño a MySQL, utilizando los tipos de datos y las restricciones que ofrece el SGBD.

Para ello utilizaremos MySQL Workbench para escribir y ejecutar instrucciones SQL. Estas instrucciones serán enviadas a MySQL Server, que será quien cree y gestione realmente la base de datos.

Recuerda

🔸 Creamos la base de datos​

Antes de crear las tablas necesitamos disponer de una base de datos que las contenga.

Para crear una nueva base de datos utilizamos la instrucción CREATE DATABASE.

    CREATE DATABASE nombre_base_datos;

Crear la base de datos no significa que MySQL vaya a utilizarla automáticamente para las siguientes instrucciones.

Debemos indicar sobre qué base de datos queremos trabajar mediante USE.

    USE nombre_base_datos;
¿Qué debemos preguntarnos?

¿Sobre qué base de datos estamos trabajando?

Antes de crear tablas o realizar cualquier otra operación, conviene comprobar que hemos seleccionado la base de datos correcta.

Nombres claros

Utiliza nombres que permitan reconocer fácilmente qué representa cada elemento y evita nombres demasiado genéricos.

Procura no usar espacios, tildes, la ñ u otros caracteres que puedan complicar los nombres. El guion bajo _ puede utilizarse para separar palabras.

Por ejemplo, tienda resulta más descriptivo que bd1.

🔸 Adaptamos los tipos de datos a MySQL​

En el apartado anterior ya hemos decidido qué tipo de información almacenará cada columna al definir el modelo relacional.

Ahora debemos trasladar esa decisión a los tipos de datos que utiliza MySQL.

Algunos de los que utilizaremos con más frecuencia son:

  • INT → números enteros.
  • VARCHAR(n) → cadenas de texto de longitud variable.
  • DATE → fechas.
  • DECIMAL(p,s) → números decimales en los que necesitamos controlar la precisión.
  • BOOLEAN → valores verdadero o falso.
¿Qué debemos preguntarnos?

La decisión principal ya está tomada: sabemos qué representa el dato.

Ahora debemos preguntarnos:

¿Qué tipo de MySQL permite almacenarlo de la forma más adecuada?

Por ejemplo, si durante el diseño hemos decidido que un teléfono se almacenará como texto, en MySQL podremos utilizar un tipo como VARCHAR.

🔸 Creamos las tablas​

Una vez creada y seleccionada la base de datos, podemos empezar a definir su estructura.

Para crear una tabla utilizamos la instrucción CREATE TABLE.

Cada columna debe indicar, como mínimo:

  • su nombre;
  • el tipo de dato que almacenará.

Por ejemplo, una tabla sencilla podría tener esta estructura:

    CREATE TABLE nombre_tabla (
    nombre_columna1 INT,
    nombre_columna2 VARCHAR(100)
);
en este ejemplo

En este ejemplo:

  • nombre_tabla representa el nombre que daremos a la tabla;
  • nombre_columna1 y nombre_columna2 representan las columnas;
  • INT y VARCHAR(100) indican el tipo de dato que almacenará cada columna.

Por ahora solo estamos definiendo la estructura básica. Las claves y restricciones se añadirán a continuación.

¿Qué debemos preguntarnos?

Antes de crear una tabla, conviene revisar:

  • ¿Qué columnas necesita?

  • ¿Qué tipo de dato corresponde a cada una?

  • ¿Cuál identificará cada fila?

  • ¿Qué restricciones tendremos que aplicar?

🔸 Trasladamos las restricciones a MySQL​

Al crear una tabla no solo debemos indicar sus columnas y tipos de datos.

También tenemos que trasladar a SQL las restricciones que definimos durante el diseño.

Las más habituales son:

  • PRIMARY KEY → identifica de forma única cada fila.
  • FOREIGN KEY → relaciona una tabla con otra.
  • NOT NULL → obliga a proporcionar un valor.
  • UNIQUE → impide que un valor se repita.
  • CHECK → establece una condición que debe cumplirse.
  • DEFAULT → asigna un valor cuando no se indica otro.

Podemos añadir estas restricciones directamente al crear la tabla.

CREATE TABLE nombre_tabla (
    nombre_columna1 INT PRIMARY KEY,
    nombre_columna2 VARCHAR(100) NOT NULL UNIQUE
);
en este ejemplo
  1. nombre_columna1 es la clave primaria de la tabla.
  2. nombre_columna2 es obligatorio porque utiliza NOT NULL.
  3. Además, no podrán existir dos filas con el mismo valor en nombre_columna2 gracias a UNIQUE.
Identificadores automáticos

Cuando una clave primaria utiliza un número entero como identificador, MySQL puede generar su valor automáticamente mediante AUTO_INCREMENT.

Por ejemplo:

CREATE TABLE nombre_tabla (
    id INT PRIMARY KEY AUTO_INCREMENT,
    ...
);

De esta forma, no es necesario indicar manualmente el valor del identificador cada vez que insertamos una nueva fila.

¿Qué debemos preguntarnos?

Antes de crear una tabla, revisa las decisiones tomadas durante el diseño:

  • ¿Cuál es su clave primaria?

  • ¿Qué columnas son obligatorias?

  • ¿Qué valores no deben repetirse?

  • ¿Qué condiciones deben cumplir determinados datos?

  • ¿La tabla necesita relacionarse con alguna otra?

🔸 Implementamos las relaciones con FOREIGN KEY​

Cuando una tabla necesita hacer referencia a otra utilizamos una clave foránea (FOREIGN KEY).

La clave foránea contiene valores que deben corresponderse con una clave primaria de la tabla relacionada.

Por ejemplo, supongamos que una tabla necesita hacer referencia a otra.

Primero debemos crear la tabla a la que se hará referencia:

CREATE TABLE tabla_1 (
    id_tabla_1 INT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL UNIQUE
);

Después podemos crear la tabla que contiene la clave foránea:

CREATE TABLE tabla_2 (
    id_tabla_2 INT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    id_tabla_1 INT NOT NULL,
    FOREIGN KEY (id_tabla_1)
        REFERENCES tabla_1(id_tabla_1)
);
en este ejemplo
  1. tabla_1 se crea primero porque será la tabla a la que se haga referencia.
  2. tabla_2 incluye la columna id_tabla_1.
  3. Esa columna se define como clave foránea mediante FOREIGN KEY.
  4. REFERENCES tabla_1(id_tabla_1) indica que sus valores deben existir previamente en la clave primaria de tabla_1.
¿Qué debemos preguntarnos?

¿Esta tabla necesita hacer referencia a otra?

Si es así:

  • ¿Qué columna almacenará esa referencia?

  • ¿A qué tabla debe apuntar?

  • ¿A qué clave primaria de esa tabla hace referencia?

El orden de creación importa

Una clave foránea no puede hacer referencia a una tabla que todavía no existe.

Por eso debemos crear primero las tablas independientes y después aquellas que dependen de ellas mediante claves foráneas.

En el ejemplo anterior, primero creamos tabla_1 y después tabla_2.

Antes de empezar a escribir las instrucciones SQL, observa el modelo relacional y localiza las dependencias entre las tablas para decidir en qué orden deben crearse.

🔸 Comprobamos la estructura creada​

Después de ejecutar las instrucciones CREATE TABLE, conviene comprobar que MySQL ha creado la estructura que habíamos diseñado.

Desde MySQL Workbench podemos revisar:

  • las tablas creadas;
  • las columnas de cada tabla;
  • los tipos de datos;
  • las claves primarias;
  • las claves foráneas;
  • y las restricciones definidas.

Esta comprobación nos permite detectar errores antes de empezar a introducir datos.

No te limites a comprobar que «no da error»

Que una instrucción se ejecute correctamente no significa necesariamente que el diseño sea el que queríamos.

Compara siempre la estructura creada en MySQL con el modelo relacional que habías definido previamente.

2️⃣ Añadimos datos​

Una vez creada la estructura de la base de datos, necesitamos introducir información en las tablas para poder trabajar con ella.

Para añadir nuevas filas utilizamos la instrucción INSERT INTO.

Su estructura básica es:

INSERT INTO nombre_tabla (columna1, columna2)
VALUES (valor1, valor2);
en este ejemplo

En este ejemplo:

  1. INSERT INTO indica la tabla en la que queremos añadir una nueva fila.
  2. Entre paréntesis indicamos las columnas para las que vamos a proporcionar valores.
  3. VALUES contiene los valores que se almacenarán.
  4. Los valores deben aparecer en el mismo orden que las columnas indicadas.

🔸 Insertamos datos con INSERT INTO​

Para añadir una única fila escribimos un conjunto de valores después de VALUES.

INSERT INTO nombre_tabla (columna1, columna2, columna3)
VALUES (1, 'Texto de ejemplo', '2026-09-15');
en este ejemplo

Cada valor se corresponde con una de las columnas indicadas.

Los valores de tipo texto y fecha se escriben entre comillas simples.

El orden importa

Si indicamos: (columna1, columna2, columna3)

los valores de VALUES deben corresponder exactamente con esas columnas y aparecer en el mismo orden.

También podemos insertar varias filas mediante una única instrucción.

INSERT INTO nombre_tabla (columna1, columna2)
VALUES
    (1, 'Valor A'),
    (2, 'Valor B'),
    (3, 'Valor C');
en este ejemplo

Cada pareja de paréntesis representa una fila diferente. De esta forma podemos introducir varios registros mediante una sola instrucción INSERT.

No siempre es necesario indicar todas las columnas de la tabla.

Si una columna admite NULL o tiene definido un valor mediante DEFAULT, podemos omitirla en la instrucción.

INSERT INTO nombre_tabla (columna1, columna2)
VALUES (1, 'Valor A');

Las columnas que no aparezcan utilizarán su valor por defecto, si lo tienen, o NULL si está permitido.

Las restricciones siguen aplicándose

Al insertar datos, MySQL comprobará las restricciones definidas en la tabla: PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE, CHECK, DEFAULT.

Si los datos no cumplen las reglas establecidas, la inserción no podrá realizarse correctamente.

🔸 Respetamos las dependencias entre tablas​

Cuando las tablas están relacionadas mediante claves foráneas, debemos tener en cuenta qué datos necesitan existir previamente.

Supongamos que tabla_2 contiene una clave foránea que hace referencia a tabla_1.

Primero debemos insertar el registro de tabla_1:

INSERT INTO tabla_1 (id_tabla_1, nombre)
VALUES (1, 'Valor A');

Después podremos insertar en tabla_2 una fila que haga referencia a ese registro:

INSERT INTO tabla_2 (id_tabla_2, nombre, id_tabla_1)
VALUES (1, 'Valor B', 1);
en este ejemplo

El valor 1 de id_tabla_1 en tabla_2 hace referencia a una fila que ya existe en tabla_1.

Si intentáramos realizar primero la segunda inserción, la clave foránea estaría haciendo referencia a un registro inexistente.

El orden de inserción importa

Cuando existen claves foráneas, debemos introducir primero los datos de las tablas referenciadas y después los datos de las tablas que dependen de ellas.

Antes de escribir los INSERT, observa las relaciones entre las tablas y decide qué datos deben existir antes.

3️⃣ Recuperamos información con SELECT​

Una vez que tenemos datos almacenados, podemos empezar a consultar la información de la base de datos.

Para recuperar datos utilizamos la instrucción SELECT.

Su estructura básica es:

SELECT columna1, columna2
FROM nombre_tabla;
en este ejemplo

En una consulta básica:

  1. SELECT indica qué columnas queremos recuperar.
  2. FROM indica de qué tabla proceden los datos.

🔸 Elegimos qué información queremos recuperar​

Si queremos recuperar todas las columnas de una tabla utilizamos *.

SELECT *
FROM nombre_tabla;
en este ejemplo

El carácter * representa todas las columnas de la tabla.

La consulta devolverá todas las filas y todas las columnas almacenadas en nombre_tabla.

Cuando solo necesitamos algunos datos, indicamos expresamente las columnas que queremos mostrar.

SELECT columna1, columna2
FROM nombre_tabla;

De esta forma obtenemos únicamente la información que necesitamos.

También podemos utilizar AS para asignar un alias a una columna y hacer que el resultado sea más fácil de interpretar.

SELECT columna1 AS nombre_mostrado,
       columna2 AS otro_nombre
FROM nombre_tabla;
en este ejemplo

Los alias modifican únicamente el nombre con el que aparecen las columnas en el resultado.

No cambian los nombres reales de las columnas de la tabla.

Si queremos evitar que aparezcan valores repetidos utilizamos DISTINCT.

SELECT DISTINCT columna1
FROM nombre_tabla;
en este ejemplo

DISTINCT hace que cada valor diferente aparezca una sola vez en el resultado.

No modifica ni elimina ningún dato de la tabla.

¿Qué debemos preguntarnos?

Antes de escribir una consulta, identifica:

¿Qué información necesito mostrar?

Esto nos ayudará a decidir qué columnas debemos incluir en SELECT.

🔸 Filtramos los resultados con WHERE​

Muchas veces no queremos recuperar todas las filas de una tabla, sino únicamente aquellas que cumplen una determinada condición.

Para ello utilizamos WHERE.

SELECT columna1, columna2
FROM nombre_tabla
WHERE columna3 = 10;
en este ejemplo

WHERE selecciona únicamente las filas que cumplen la condición indicada.

Después, SELECT determina qué columnas de esas filas aparecerán en el resultado.

Los operadores de comparación más habituales son:

  • = → igual que
  • <> → distinto de
  • > → mayor que
  • < → menor que
  • >= → mayor o igual que
  • <= → menor o igual que

Por ejemplo:

SELECT columna1, columna2
FROM nombre_tabla
WHERE columna3 > 20;

También podemos combinar varias condiciones mediante operadores lógicos:

  • AND → deben cumplirse todas las condiciones;
  • OR → debe cumplirse al menos una;
  • NOT → niega una condición.
SELECT columna1, columna2
FROM nombre_tabla
WHERE columna3 > 20
  AND columna4 = 'Valor';
en este ejemplo

Esta consulta recuperará únicamente las filas en las que se cumplan las dos condiciones.

Si utilizáramos OR, bastaría con que se cumpliera una de ellas.

Cuidado al combinar AND y OR

Cuando una condición contiene varios AND y OR, utiliza paréntesis cuando sea necesario para dejar claro qué condiciones deben evaluarse juntas.

🔸 Afinamos las condiciones​

SQL dispone de operadores que permiten expresar algunas búsquedas de forma más sencilla.

BETWEEN​

Permite comprobar si un valor se encuentra dentro de un intervalo.

SELECT *
FROM nombre_tabla
WHERE columna1 BETWEEN valor1 AND valor2;

BETWEEN incluye los dos extremos del intervalo.

También podemos utilizarlo con fechas:

SELECT *
FROM nombre_tabla
WHERE columna_fecha BETWEEN '2026-10-01' AND '2026-10-31';

IN​

Permite comprobar si un valor coincide con alguno de los valores indicados.

SELECT *
FROM nombre_tabla
WHERE columna1 IN ('Valor A', 'Valor B', 'Valor C');

Puede resultar más claro que escribir varias comparaciones unidas mediante OR.

LIKE​

Permite buscar patrones dentro de valores de texto.

SELECT *
FROM nombre_tabla
WHERE columna1 LIKE 'A%';

Los comodines más habituales son:

  • % → representa cero o más caracteres;
  • _ → representa exactamente un carácter.
SELECT *
FROM nombre_tabla
WHERE columna1 LIKE '%texto%';
en este ejemplo

El patrón '%texto%' permite localizar valores que contengan texto en cualquier posición.

IS NULL e IS NOT NULL​

Para comprobar si una columna contiene o no contiene un valor nulo utilizamos:

SELECT *
FROM nombre_tabla
WHERE columna1 IS NULL;

o:

SELECT *
FROM nombre_tabla
WHERE columna1 IS NOT NULL;
comparar con NULL

Para comprobar si un valor es NULL no debemos utilizar:columna1 = NULL

Debemos utilizar IS NULL o IS NOT NULL.

Antes de dar una consulta por correcta

Que una consulta se ejecute sin errores no significa necesariamente que responda a lo que queríamos obtener.

Comprueba siempre:

  • qué columnas aparecen;

  • qué filas se han recuperado;

  • si existen valores repetidos innecesarios;

  • y si el resultado responde realmente a la pregunta planteada.

4️⃣ Ordenamos y limitamos los resultados​

Una consulta puede devolver exactamente los datos que necesitamos y, aun así, resultar poco clara si aparecen en un orden que no nos ayuda a interpretarlos.

Para ordenar los resultados utilizamos ORDER BY.

🔸 Ordenamos los resultados con ORDER BY​

Podemos ordenar una consulta por una o varias columnas.

SELECT columna1, columna2
FROM nombre_tabla
ORDER BY columna1;
en este ejemplo

ORDER BY indica la columna que utilizaremos para ordenar el resultado.

Si no indicamos nada más, MySQL utiliza orden ascendente.

Podemos indicar expresamente el tipo de orden mediante:

  • ASC → orden ascendente;
  • DESC → orden descendente.
SELECT columna1, columna2
FROM nombre_tabla
ORDER BY columna1 DESC;

También podemos utilizar varias columnas como criterio de ordenación.

SELECT columna1, columna2, columna3
FROM nombre_tabla
ORDER BY columna1 ASC, columna2 DESC;
en este ejemplo

La consulta ordena primero por columna1.

Cuando varias filas tienen el mismo valor en esa columna, utiliza columna2 como segundo criterio de ordenación.

ORDER BY no modifica los datos

ORDER BY únicamente cambia el orden en el que se muestran las filas.

Los datos almacenados en la tabla no se modifican.

🔸 Limitamos el número de resultados​

Cuando una consulta devuelve muchas filas, puede interesarnos mostrar únicamente una parte.

Para ello utilizamos LIMIT.

SELECT columna1, columna2
FROM nombre_tabla
LIMIT 5;
en este ejemplo

LIMIT 5 hace que se muestren como máximo las cinco primeras filas del resultado.

LIMIT suele utilizarse junto con ORDER BY cuando queremos obtener, por ejemplo, los primeros o los últimos registros según algún criterio.

SELECT columna1, columna2
FROM nombre_tabla
ORDER BY columna2 DESC
LIMIT 3;
en este ejemplo

Primero se ordenan las filas por columna2 de mayor a menor.

Después, LIMIT 3 hace que únicamente se muestren las tres primeras filas de ese resultado ordenado.

El orden de las cláusulas

Cuando utilizamos varias cláusulas en una misma consulta, debemos escribirlas en el orden adecuado:

SELECT ...
FROM ...
WHERE ...
ORDER BY ...
LIMIT ...;

No siempre aparecerán todas, pero cuando se utilicen deben respetar este orden.

5️⃣ Modificamos datos con UPDATE​

Los datos almacenados en una base de datos pueden cambiar con el tiempo.

Para modificar valores existentes utilizamos la instrucción UPDATE.

Su estructura básica es:

UPDATE nombre_tabla
SET columna1 = nuevo_valor
WHERE condicion;
en este ejemplo

En esta instrucción:

  1. UPDATE indica qué tabla queremos modificar.
  2. SET establece el nuevo valor que tendrá una columna.
  3. WHERE determina qué filas deben modificarse.

🔸 Modificamos una o varias columnas​

Podemos modificar una única columna:

UPDATE nombre_tabla
SET columna1 = 'Nuevo valor'
WHERE columna2 = 10;

También podemos modificar varias columnas al mismo tiempo separándolas mediante comas:

UPDATE nombre_tabla
SET columna1 = 'Nuevo valor',
    columna2 = 25
WHERE columna3 = 5;
en este ejemplo

Solo se modificarán las filas que cumplan la condición indicada en WHERE.

En cada una de ellas se actualizarán los valores especificados en SET.

Las condiciones de WHERE funcionan igual que en una consulta SELECT, por lo que podemos utilizar operadores de comparación, AND, OR, BETWEEN, IN, etc.

Cuidado con UPDATE sin WHERE

Si ejecutamos:

UPDATE nombre_tabla
SET columna1 = 'Nuevo valor';

el cambio se aplicará a todas las filas de la tabla.

Antes de ejecutar un UPDATE, comprueba siempre si necesitas utilizar WHERE.

Primero consulta, después modifica

Antes de ejecutar un UPDATE, comprueba primero qué filas se verán afectadas utilizando un SELECT con la misma condición.

Por ejemplo:

SELECT *
FROM nombre_tabla
WHERE columna2 = 10;

Si el resultado contiene exactamente las filas que quieres modificar, puedes utilizar esa misma condición en el UPDATE:

UPDATE nombre_tabla
SET columna1 = 'Nuevo valor'
WHERE columna2 = 10;

Después de realizar el cambio, vuelve a consultar los datos para comprobar que la modificación se ha realizado correctamente.

6️⃣ Eliminamos datos con DELETE​

Cuando un registro deja de ser necesario podemos eliminarlo de una tabla mediante la instrucción DELETE.

Su estructura básica es:

DELETE FROM nombre_tabla
WHERE condicion;
en este ejemplo

En esta instrucción:

  1. DELETE FROM indica de qué tabla queremos eliminar datos.
  2. WHERE determina qué filas deben eliminarse.

🔸 Eliminamos las filas que cumplen una condición​

Podemos utilizar en WHERE las mismas condiciones que ya hemos utilizado en SELECT y UPDATE.

Por ejemplo:

DELETE FROM nombre_tabla
WHERE columna1 = 10;
en este ejemplo

Esta instrucción eliminará únicamente las filas que cumplan la condición indicada.

Si ninguna fila cumple la condición, no se eliminará ningún registro.

También podemos utilizar condiciones más complejas:

DELETE FROM nombre_tabla
WHERE columna2 = 'Valor'
  AND columna3 < 5;
Cuidado con DELETE sin WHERE

Si ejecutamos:

DELETE FROM nombre_tabla;

se eliminarán todas las filas de la tabla.

La tabla seguirá existiendo, pero quedará vacía.

Antes de ejecutar un DELETE, comprueba siempre si necesitas utilizar WHERE.

Primero consulta, después elimina

Antes de ejecutar un DELETE, utiliza un SELECT con la misma condición para comprobar qué filas se verán afectadas.

SELECT *
FROM nombre_tabla
WHERE columna1 = 10;

Si el resultado contiene exactamente las filas que quieres eliminar, puedes utilizar esa misma condición:

DELETE FROM nombre_tabla
WHERE columna1 = 10;

Después, vuelve a consultar la tabla para comprobar el resultado.

Las claves foráneas pueden impedir la eliminación

Si una fila está siendo utilizada desde otra tabla mediante una clave foránea, MySQL puede impedir su eliminación.

Esto evita que queden referencias a datos que ya no existen y ayuda a mantener la integridad de la base de datos.

7️⃣ En resumen​

En este apartado hemos recuperado las operaciones SQL fundamentales para trabajar con una base de datos relacional:

  • CREATE → crear la estructura de la base de datos.
  • INSERT → añadir nuevos datos.
  • SELECT → consultar la información almacenada.
  • WHERE → filtrar las filas que cumplen una condición.
  • ORDER BY → ordenar los resultados.
  • LIMIT → limitar el número de filas mostradas.
  • UPDATE → modificar datos existentes.
  • DELETE → eliminar filas.
Idea clave

Antes de ejecutar una instrucción SQL, conviene tener claro:

qué queremos hacer, sobre qué tabla y sobre qué filas.

Especialmente con UPDATE y DELETE, una condición mal planteada puede afectar a más registros de los previstos.
