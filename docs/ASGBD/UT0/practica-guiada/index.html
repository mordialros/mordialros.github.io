🧩 Práctica guiada

En esta práctica aplicaremos de forma progresiva los contenidos recuperados en la UT0 sobre un mismo caso.

El objetivo es recorrer de nuevo el proceso completo:

Problema → modelo E/R → modelo relacional → MySQL → datos → consultas → transacciones

No se trata de realizar actividades independientes. Cada actividad parte del trabajo realizado en las anteriores, por lo que conviene conservar los diagramas, scripts y consultas que vayamos creando.

1️⃣ De la realidad a las tablas​

🔸 Actividad 1. Analizamos el problema​

El Centro Cívico La Estación organiza durante todo el año talleres, cursos y otras actividades de ocio dirigidas a los vecinos del municipio.

Entre las actividades que ofrece hay propuestas relacionadas con naturaleza, música, videojuegos y actividades deportivas.

Actualmente, las inscripciones se gestionan mediante hojas de cálculo y el centro quiere disponer de una base de datos que permita organizar mejor la información.

De cada usuario necesitan conocer su nombre, correo electrónico y teléfono de contacto.

De cada actividad necesitan registrar su nombre, fecha de realización, lugar y número máximo de plazas disponibles.

Además, el centro quiere clasificar las actividades mediante un catálogo de tipos de actividad, para evitar utilizar nombres diferentes para una misma categoría. De cada tipo interesa guardar su nombre. Un mismo tipo puede agrupar varias actividades, pero cada actividad pertenece a un único tipo.

Un usuario puede apuntarse a varias actividades y una misma actividad puede tener inscritos a distintos usuarios.

Además, el centro necesita conocer la fecha en la que cada usuario realizó su inscripción.

Antes de empezar a dibujar, responde:

  1. ¿Qué necesita gestionar el centro?
  2. ¿Qué elementos principales aparecen en el problema?
  3. ¿Qué información necesitamos almacenar de cada uno?
  4. ¿Qué relaciones existen entre esos elementos?
  5. ¿Qué cardinalidad tiene cada relación?
  6. ¿Existe algún dato que pertenezca a una relación y no únicamente a una entidad?
Antes de continuar

Resume el problema con una frase que comience por:

“El centro necesita gestionar…”

🔸 Actividad 2. Diseñamos el modelo E/R​

A partir del enunciado anterior, realiza el modelo entidad-relación (E/R) que represente la información que necesita gestionar el centro.

Para construirlo tendrás que:

  1. identificar las entidades necesarias;
  2. determinar sus atributos;
  3. decidir qué atributo identificará cada entidad;
  4. establecer las relaciones entre las entidades;
  5. indicar sus cardinalidades;
  6. decidir si alguna relación necesita atributos propios.

Realiza el diagrama utilizando diagrams.net (draw.io).

Guarda el archivo editable

Conserva el archivo .drawio además de la imagen exportada. Lo necesitaremos si tenemos que modificar el diseño.

🔸 Actividad 3. Transformamos al modelo relacional​

Transforma el diagrama E/R del Centro Cívico La Estación en su correspondiente modelo relacional.

Para cada tabla, indica:

  • nombre de la tabla;
  • columnas;
  • clave primaria;
  • claves foráneas.

Comprueba también que:

☐ Todas las entidades se han convertido en tablas.

☐ Cada tabla tiene una clave primaria.

☐ Las relaciones 1:N están representadas mediante una clave foránea.

☐ Las relaciones N:M se han convertido en una tabla intermedia.

☐ Los atributos propios de las relaciones se han trasladado correctamente.

🔸 Actividad 4. Definimos las restricciones​

Vuelve al modelo relacional y decide qué restricciones deben aplicarse a sus columnas.

Debes valorar, cuando corresponda:

  • PRIMARY KEY;
  • FOREIGN KEY;
  • NOT NULL;
  • UNIQUE;
  • CHECK;
  • DEFAULT.

Para cada decisión, no basta con indicar la restricción: justifica qué situación incorrecta o incoherente pretende evitar.

Puedes ayudarte de estas preguntas:

  1. ¿Qué datos deben ser obligatorios?
  2. ¿Qué valores no deberían poder repetirse?
  3. ¿Qué valores deben cumplir alguna condición?
  4. ¿Existe algún dato para el que tenga sentido definir un valor por defecto?

2️⃣ Volvemos a hablar SQL​

🔸 Actividad 5. Creamos la base de datos en MySQL​

Implementa en MySQL el modelo relacional que has diseñado.

Debes:

  1. crear una base de datos para almacenar la información del centro;
  2. seleccionar la base de datos sobre la que vas a trabajar;
  3. crear todas las tablas necesarias;
  4. elegir el tipo de dato adecuado para cada columna;
  5. definir las claves primarias;
  6. añadir las claves foráneas;
  7. incorporar las restricciones decididas en la actividad anterior;
  8. respetar el orden de creación de las tablas según sus dependencias.

Al terminar, utiliza MySQL Workbench para comprobar:

☐ Tablas creadas.

☐ Columnas y tipos de datos.

☐ Claves primarias.

☐ Claves foráneas.

☐ Restricciones.

Conserva el script

Guarda las instrucciones utilizadas para crear la base de datos y las tablas. Seguiremos trabajando sobre ellas durante el resto de la práctica.

🔸 Actividad 6. Insertamos los datos​

Introduce datos suficientes para poder realizar las actividades posteriores.

Tipos de actividad

Utiliza los siguientes:

  • Naturaleza
  • Música
  • Videojuegos
  • Actividades deportivas
Actividades

Introduce estas actividades:

  • Ruta de senderismo — Naturaleza — 03/10/2026 — Parque del Río — 20 plazas
  • Taller de orientación — Naturaleza — 17/10/2026 — Parque Municipal — 15 plazas
  • Iniciación a la mezcla DJ — Música — 08/10/2026 — Aula de música — 12 plazas
  • Sesión práctica de DJ — Música — 05/11/2026 — Aula de música — 12 plazas
  • Torneo de videojuegos — Videojuegos — 22/10/2026 — Aula de informática — 16 plazas
  • Taller de creación de videojuegos — Videojuegos — 12/11/2026 — Aula de informática — 16 plazas
  • Torneo de fútbol sala — Actividades deportivas — 10/10/2026 — Pabellón municipal — 20 plazas
  • Sesión de calistenia — Actividades deportivas — 24/10/2026 — Zona deportiva exterior — 18 plazas
  • Reto solidario de kilómetros en bicicleta estática — Actividades deportivas — 14/11/2026 — Gimnasio municipal — 25 plazas
Usuarios e inscripciones

Elige los datos de los usuarios y de las inscripciones.

Procura que permitan encontrar situaciones diferentes al realizar consultas:

  • usuarios inscritos en varias actividades;
  • actividades con varios usuarios inscritos;
  • usuarios que todavía no se hayan inscrito en ninguna actividad;
  • actividades que todavía no tengan ninguna inscripción;
  • inscripciones realizadas en fechas diferentes.
Antes de insertar

Decide primero en qué orden deben introducirse los datos teniendo en cuenta las claves foráneas.

🔸 Actividad 7. Consultamos y filtramos información​

Escribe consultas que permitan obtener:

  1. todos los datos almacenados de los usuarios;
  2. únicamente el nombre y el correo electrónico de los usuarios;
  3. el nombre, la fecha, el lugar y el número de plazas de todas las actividades;
  4. los distintos lugares en los que se realizan actividades, sin repetir valores;
  5. las actividades que tengan más de 15 plazas;
  6. las actividades que se realicen durante octubre de 2026;
  7. las actividades cuyo nombre contenga la palabra Taller;
  8. las actividades que se realicen en dos lugares diferentes que elijas;
  9. las actividades que tengan más de 15 plazas y se celebren durante octubre;
  10. las actividades que no se celebren en el Aula de música;
  11. alguna de las consultas anteriores utilizando alias para que los encabezados resulten más claros.
Antes de escribir cada consulta

Identifica:

  • qué información necesitas mostrar;
  • de qué tabla procede;
  • qué columnas necesitas;
  • qué condición deben cumplir las filas.

🔸 Actividad 8. Ordenamos y limitamos resultados​

Escribe consultas que permitan:

  1. mostrar las actividades ordenadas alfabéticamente por su nombre;
  2. mostrar las actividades ordenadas por fecha, comenzando por la más próxima;
  3. mostrar las actividades ordenadas de mayor a menor número de plazas;
  4. mostrar las actividades ordenadas primero por lugar y después por fecha;
  5. mostrar únicamente las tres actividades con mayor número de plazas;
  6. mostrar las dos actividades que se celebrarán primero;
  7. mostrar las actividades de octubre ordenadas por fecha;
  8. mostrar las actividades con más de 15 plazas ordenadas de mayor a menor capacidad.

🔸 Actividad 9. Modificamos y eliminamos datos​

Modificamos datos

Antes de cada UPDATE, ejecuta un SELECT con la misma condición para comprobar qué filas se van a modificar.

Después realiza estas operaciones:

  1. cambia el número máximo de plazas de Ruta de senderismo a 25;
  2. cambia el lugar de Sesión práctica de DJ a Sala multimedia;
  3. modifica la fecha de Torneo de videojuegos al 29/10/2026;
  4. aumenta a 20 las plazas de Sesión de calistenia;
  5. modifica alguno de los datos de un usuario que hayas introducido.

Después de cada modificación, vuelve a consultar los datos para comprobar el resultado.

Eliminamos datos

Antes de cada DELETE, ejecuta un SELECT con la misma condición.

Después:

  1. elimina una de las inscripciones que hayas creado anteriormente;
  2. comprueba que se ha eliminado correctamente;
  3. intenta eliminar un usuario que todavía tenga alguna inscripción asociada y observa qué ocurre;
  4. elimina primero las inscripciones necesarias y, a continuación, elimina ese usuario;
  5. elimina alguna actividad que ya no vaya a realizarse, teniendo en cuenta las relaciones existentes con otras tablas.
Antes de eliminar

Comprueba siempre si existen otras tablas que hagan referencia al registro que quieres eliminar.

3️⃣ Los datos están relacionados​

🔸 Actividad 10. Relacionamos varias tablas​

Utiliza las relaciones del modelo para escribir consultas con JOIN.

Obtén:

  1. el nombre de cada actividad junto con el nombre de su tipo;
  2. el nombre de cada usuario junto con las actividades en las que está inscrito;
  3. el nombre de la actividad, el nombre del usuario y la fecha en la que realizó la inscripción;
  4. todas las actividades, aunque todavía no tengan ninguna inscripción;
  5. todos los usuarios, aunque todavía no se hayan inscrito en ninguna actividad;
  6. únicamente las actividades que todavía no tengan usuarios inscritos;
  7. únicamente los usuarios que todavía no tengan ninguna inscripción.

En las consultas que lo necesiten, utiliza alias para que resulten fáciles de leer.

Sigue las relaciones del modelo

Antes de escribir cada JOIN, localiza qué tablas necesitas y qué claves permiten pasar de una a otra.

🔸 Actividad 11. Resumimos y agrupamos información​

Utiliza funciones de agregación y GROUP BY para obtener:

  1. el número total de usuarios;
  2. el número total de actividades;
  3. el número total de inscripciones;
  4. el número de actividades de cada tipo;
  5. el número de usuarios inscritos en cada actividad;
  6. el número de actividades en las que está inscrito cada usuario;
  7. la media de plazas máximas de las actividades;
  8. la actividad con mayor número de plazas;
  9. la actividad con menor número de plazas;
  10. únicamente los tipos que tengan más de dos actividades;
  11. únicamente las actividades que tengan más de dos usuarios inscritos.
WHERE o HAVING

Antes de filtrar, decide si quieres eliminar:

  • filas antes de agrupar → WHERE;
  • grupos después de agrupar → HAVING.

🔸 Actividad 12. Trabajamos con subconsultas​

Resuelve las siguientes consultas utilizando subconsultas:

  1. muestra las actividades cuyo número de plazas sea superior a la media de plazas de todas las actividades;
  2. muestra las actividades cuyo número de plazas sea igual al máximo registrado;
  3. muestra los usuarios que estén inscritos en alguna actividad de tipo Naturaleza;
  4. muestra los usuarios que estén inscritos en alguna actividad que se celebre durante noviembre;
  5. muestra las actividades en las que esté inscrito algún usuario cuyo nombre comience por una letra que elijas.

Para cada ejercicio:

  1. identifica primero qué debe devolver la subconsulta;
  2. ejecuta la subconsulta por separado y comprueba su resultado;
  3. incorpórala después dentro de la consulta exterior.
Lee de dentro hacia fuera

Primero responde:

¿Qué devuelve la consulta interior?

Después:

¿Cómo utiliza ese resultado la consulta exterior?

4️⃣ Todo o nada​

🔸 Actividad 13. Utilizamos transacciones​

En esta actividad comprobaremos la diferencia entre ejecutar cambios y confirmarlos.

Primera parte · Probamos COMMIT y ROLLBACK
  1. Consulta el número de plazas de una actividad y anota su valor.
  2. Inicia una transacción.
  3. Modifica temporalmente el número de plazas de esa actividad.
  4. Consulta de nuevo el registro y comprueba el cambio.
  5. Ejecuta ROLLBACK.
  6. Vuelve a consultar la actividad y comprueba que recupera el valor anterior.

Repite el proceso, pero esta vez finaliza con COMMIT.

Comprueba qué ocurre cuando intentas realizar posteriormente un ROLLBACK.

Segunda parte · Varias operaciones como una sola

Realiza una nueva inscripción de un usuario en una actividad dentro de una transacción.

Antes de confirmar:

  1. consulta los datos afectados;
  2. comprueba que la información es correcta;
  3. utiliza COMMIT si todo está bien.

Después repite el proceso con otra inscripción, pero utiliza ROLLBACK antes de confirmar.

Comprueba que los cambios de esa segunda operación no quedan almacenados.

Todo o nada

Al terminar, explica brevemente por qué una transacción resulta útil cuando varias modificaciones forman parte de una misma operación.

✅ Comprobación final​

Antes de dar por terminada la práctica, comprueba:

☐ El modelo E/R representa correctamente el problema.

☐ El modelo relacional corresponde al modelo E/R.

☐ Las claves y restricciones mantienen la integridad de los datos.

☐ Las tablas se han creado respetando sus dependencias.

☐ Los datos permiten realizar todas las consultas planteadas.

☐ Las consultas con JOIN recorren correctamente las relaciones.

☐ Las funciones de agregación y GROUP BY producen el resultado esperado.

☐ Se distingue correctamente entre WHERE y HAVING.

☐ Las subconsultas se han interpretado de dentro hacia fuera.

☐ Se comprende la diferencia entre COMMIT y ROLLBACK.
