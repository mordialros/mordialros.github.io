🧩 Práctica guiada

En esta práctica aplicaremos de forma progresiva los contenidos recuperados en la UT0 sobre un mismo caso.

El objetivo es recorrer de nuevo el proceso completo:

Problema → modelo E/R → modelo relacional → MySQL → datos → consultas → transacciones

No se trata de realizar actividades independientes. Cada actividad parte del trabajo realizado en las anteriores, por lo que conviene conservar los diagramas, scripts y consultas que vayamos creando.

📤 Entregas en Classroom​

Las actividades de esta práctica se realizarán de forma progresiva, pero no todas tendrán una entrega independiente en Classroom.

Las entregas se organizarán de la siguiente forma:

Entrega en ClassroomActividades de los apuntes
1. Diseño de la base de datosActividades 1, 2 y 3
2. Creamos y cargamos la base de datosActividades 4 y 5
3. Consultamos y modificamos los datosActividades 6, 7 y 8
4. Relacionamos tablasActividad 9
5. Resumimos información y trabajamos con subconsultasActividades 10 y 11
6. Todo o nada: trabajamos con transaccionesActividad 12

En cada tarea de Classroom se indicará qué archivos o documentos deben entregarse.

Calificación

Cada entrega se calificará como: APTO = 10 / NO APTO = 0

1️⃣ De la realidad a las tablas​

🔸 Actividad 1. Analizamos el problema​

El Centro Cívico La Estación organiza durante todo el año talleres, cursos y otras actividades de ocio dirigidas a los vecinos del municipio.

Entre las actividades que ofrece hay propuestas relacionadas con naturaleza, música, videojuegos y actividades deportivas.

Actualmente, las inscripciones se gestionan mediante hojas de cálculo y el centro quiere disponer de una base de datos que permita organizar mejor la información.

De cada usuario necesitan conocer su nombre, correo electrónico y teléfono de contacto.

De cada actividad necesitan registrar su nombre, fecha de realización, lugar y número máximo de plazas disponibles.

Además, el centro quiere clasificar las actividades mediante un catálogo de tipos de actividad, para evitar utilizar nombres diferentes para una misma categoría. De cada tipo interesa guardar su nombre. Un mismo tipo puede agrupar varias actividades, pero cada actividad pertenece a un único tipo.

Un usuario puede apuntarse a varias actividades y una misma actividad puede tener inscritos a distintos usuarios.

Además, el centro necesita conocer la fecha en la que cada usuario realizó su inscripción.

Antes de empezar a dibujar, responde:

  1. ¿Qué necesita gestionar el centro?
  2. ¿Qué elementos principales aparecen en el problema?
  3. ¿Qué información necesitamos almacenar de cada uno?
  4. ¿Qué relaciones existen entre esos elementos?
  5. ¿Qué cardinalidad tiene cada relación?
  6. ¿Existe algún dato que pertenezca a una relación y no únicamente a una entidad?
Antes de continuar

Resume el problema con una frase que comience por:

“El centro necesita gestionar…”

🔸 Actividad 2. Diseñamos el modelo E/R​

A partir del enunciado anterior, realiza el modelo entidad-relación (E/R) que represente la información que necesita gestionar el centro.

Para construirlo tendrás que:

  1. identificar las entidades necesarias;
  2. determinar sus atributos;
  3. decidir qué atributo identificará cada entidad;
  4. establecer las relaciones entre las entidades;
  5. indicar sus cardinalidades;
  6. decidir si alguna relación necesita atributos propios.

Realiza el diagrama utilizando diagrams.net (draw.io).

Guarda el archivo editable

Conserva el archivo .drawio además de la imagen exportada. Lo necesitaremos si tenemos que modificar el diseño.

🔸 Actividad 3. Definimos el modelo relacional​

A partir del modelo E/R que has elaborado para el Centro Cívico La Estación, construye su correspondiente modelo relacional.

Para cada tabla deberás indicar:

  • su nombre;
  • las columnas que la forman;
  • el tipo de dato que almacenará cada columna;
  • la clave primaria;
  • las claves foráneas;
  • y las restricciones necesarias.
Plantilla de trabajo

Utiliza la siguiente plantilla para documentar cada una de las tablas de tu modelo.

Tabla: __________________________________________________________________________________________________​

ColumnaTipo de datoPKFK / ReferenciaNOT NULLUNIQUECHECKDEFAULT

Restricciones o decisiones que necesitan explicación:

Repite la plantilla para cada tabla necesaria.

Antes de continuar

Comprueba:

☐ Todas las entidades se han convertido en tablas.

☐ Cada tabla tiene una clave primaria.

☐ Se ha indicado un tipo de dato adecuado para cada columna.

☐ Las relaciones están correctamente representadas.

☐ Se han definido las restricciones necesarias.

☐ El modelo permite representar las reglas indicadas en el enunciado.

2️⃣ Volvemos a hablar SQL​

🔸 Actividad 4. Creamos la base de datos en MySQL​

Implementa en MySQL el modelo relacional definido en la actividad anterior.

Debes:

  1. crear una base de datos para almacenar la información del centro;
  2. seleccionar la base de datos sobre la que vas a trabajar;
  3. crear todas las tablas necesarias;
  4. utilizar los tipos de datos de MySQL adecuados para implementar los definidos en el modelo relacional;
  5. implementar las claves primarias, claves foráneas y restricciones;
  6. utilizar AUTO_INCREMENT en los identificadores numéricos cuando corresponda;
  7. respetar las dependencias entre las tablas al decidir el orden de creación.

Al terminar, comprueba en MySQL Workbench que la estructura creada coincide con el modelo relacional.

Conserva el script

Guarda las instrucciones utilizadas para crear la base de datos y las tablas. Seguiremos trabajando sobre ellas durante el resto de la práctica.

🔸 Actividad 6. Consultamos y filtramos información​

Escribe consultas que permitan obtener:

  1. todos los datos almacenados de los usuarios
  2. únicamente el nombre y el correo electrónico de los usuarios
  3. el nombre, la fecha, el lugar y el número de plazas de todas las actividades
  4. los distintos lugares en los que se realizan actividades, sin repetir valores
  5. las actividades que tengan más de 15 plazas
  6. las actividades que se realicen durante octubre de 2026

  10. las actividades que no se celebren en el Aula de música

3️⃣ Los datos están relacionados​

🔸 Actividad 9. Relacionamos varias tablas​

Realiza las siguientes consultas utilizando las relaciones entre las tablas:

  1. Muestra el nombre de cada actividad junto con el nombre de su tipo.
  2. Muestra el nombre de cada usuario junto con las actividades en las que está inscrito.
  3. Muestra el nombre de la actividad, su tipo, el nombre del usuario y la fecha en la que realizó la inscripción.
  4. Muestra todas las actividades, aunque no tengan ningún usuario inscrito.
  5. Muestra todos los usuarios, aunque no estén inscritos en ninguna actividad.
  6. Muestra únicamente las actividades que no tengan usuarios inscritos.
  7. Muestra únicamente los usuarios que no tengan ninguna inscripción.

Utiliza alias para que las consultas resulten más fáciles de leer.

🔸 Actividad 10. Resumimos y agrupamos información​

Realiza las siguientes consultas utilizando funciones de agregación, GROUP BY y HAVING.

Funciones de agregación
  1. Obtén el número total de usuarios.
  2. Obtén el número total de actividades.
  3. Obtén el número total de inscripciones.
  4. Calcula el número total de plazas ofertadas entre todas las actividades.
  5. Calcula la media, el máximo y el mínimo del número de plazas de las actividades.
Agrupamos con GROUP BY
  1. Muestra el número de actividades de cada tipo.
  2. Muestra el número de usuarios inscritos en cada actividad, incluyendo aquellas que no tengan ninguna inscripción.
  3. Muestra el número de actividades en las que está inscrito cada usuario, incluyendo aquellos que no tengan ninguna inscripción.
Recuerda

Cuando utilices composiciones externas como LEFT JOIN, piensa qué diferencia existe entre utilizar COUNT(*) y COUNT(columna).

Filtramos grupos con HAVING
  1. Muestra los tipos que tengan más de dos actividades.
  2. Muestra las actividades que tengan más de dos usuarios inscritos.
  3. De las actividades que se celebran durante octubre, muestra únicamente los tipos que tengan más de una actividad.

🔸 Actividad 11. Trabajamos con subconsultas​

Resuelve las siguientes consultas utilizando subconsultas.

Subconsultas que devuelven un único valor
  1. Muestra las actividades cuyo número de plazas sea superior a la media de plazas de todas las actividades.
  2. Muestra las actividades cuyo número de plazas sea igual al máximo número de plazas existente.
Subconsultas que devuelven varios valores
  1. Muestra los usuarios que estén inscritos en alguna actividad de tipo Naturaleza.
  2. Muestra los usuarios que estén inscritos en alguna actividad que se celebre durante noviembre.
  3. Muestra las actividades que pertenezcan a tipos que tengan más de dos actividades.
Antes de escribir la consulta

Cuando trabajes con una subconsulta, piensa primero:

  1. ¿Qué debe devolver la consulta interior?
  2. ¿Cómo utilizará ese resultado la consulta exterior?

4️⃣ Todo o nada​

🔸 Actividad 12. Utilizamos transacciones​

En esta actividad comprobaremos cómo podemos realizar cambios, revisar su resultado y decidir después si queremos confirmarlos o deshacerlos.

Probamos ROLLBACK
  1. Consulta el número de plazas de una actividad y anota su valor.
  2. Inicia una transacción.
  3. Modifica temporalmente el número de plazas de esa actividad.
  4. Consulta de nuevo el registro y comprueba que el cambio se ha realizado.
  5. Ejecuta ROLLBACK.
  6. Vuelve a consultar la actividad.

Comprueba que el número de plazas vuelve a tener el valor que tenía antes de iniciar la transacción.

Probamos COMMIT

Crea un usuario de prueba que utilizaremos únicamente en esta actividad.

  1. Inicia una nueva transacción.
  2. Inserta el usuario.
  3. Comprueba que aparece en la tabla.
  4. Confirma la transacción con COMMIT.
  5. Ejecuta después un ROLLBACK.
  6. Consulta de nuevo el usuario.

Comprueba qué ocurre y explica por qué ROLLBACK ya no puede deshacer esa inserción.

Varias operaciones como una sola

Ahora utilizaremos el usuario de prueba para realizar una operación formada por varios cambios relacionados.

  1. Inicia una nueva transacción.
  2. Modifica algún dato del usuario de prueba.
  3. Inscríbelo en una actividad.
  4. Consulta las tablas afectadas y comprueba el resultado.
  5. Ejecuta ROLLBACK.
  6. Vuelve a consultar ambas tablas.

Comprueba que ninguno de los cambios realizados dentro de la transacción se conserva.

Repite el proceso realizando de nuevo las dos operaciones, pero esta vez termina con COMMIT.

Comprueba que ambas quedan confirmadas.

Todo o nada

Al terminar, explica con tus propias palabras qué ocurriría si una de las operaciones de la transacción no pudiera realizarse correctamente y por qué resulta útil poder deshacer el conjunto completo.

Dejamos los datos como estaban

Elimina la inscripción y el usuario de prueba utilizados en esta actividad.

Comprueba al terminar que la base de datos contiene de nuevo únicamente los datos utilizados durante el resto de la práctica.
