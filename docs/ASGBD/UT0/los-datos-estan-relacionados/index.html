0.3 Los datos están relacionados

Hasta ahora hemos realizado consultas sobre una sola tabla.

Sin embargo, en una base de datos relacional la información suele estar repartida entre varias tablas relacionadas entre sí. Para responder a muchas preguntas necesitaremos combinar datos, resumir información y, en algunos casos, utilizar el resultado de una consulta dentro de otra.

En este apartado vamos a recuperar tres ideas fundamentales:

Relacionar tablas → Resumir información → Utilizar subconsultas

1️⃣ El ejemplo que utilizaremos​

En este apartado trabajaremos con un ejemplo genérico de gestión de productos y pedidos.

Partiremos del siguiente modelo relacional:

Tablas del ejemplo

CATEGORIA

  • id_categoria → clave primaria.
  • nombre → obligatorio y no repetido.

PRODUCTO

  • id_producto → clave primaria.
  • nombre → obligatorio.
  • precio → obligatorio.
  • stock → obligatorio.
  • id_categoria → clave foránea que referencia a CATEGORIA.
  • precio → debe ser mayor que 0.
  • stock → debe ser mayor o igual que 0.

CLIENTE

  • id_cliente → clave primaria.
  • nombre → obligatorio.
  • correo → obligatorio y no repetido.

PEDIDO

  • id_pedido → clave primaria.
  • fecha_pedido → obligatoria.
  • id_cliente → clave foránea que referencia a CLIENTE.

LINEA_PEDIDO

  • id_pedido → clave foránea que referencia a PEDIDO.
  • id_producto → clave foránea que referencia a PRODUCTO.
  • cantidad → obligatoria.
  • precio_unitario → obligatorio.
  • clave primaria compuesta: (id_pedido, id_producto)
  • cantidad → debe ser mayor que 0.
  • precio_unitario → debe ser mayor que 0.
Relaciones del ejemplo
  • Una categoría puede tener varios productos.
  • Un producto pertenece a una sola categoría.
  • Un cliente puede realizar varios pedidos.
  • Un pedido pertenece a un solo cliente.
  • Un pedido puede incluir varios productos.
  • Un producto puede aparecer en varios pedidos.
  • La relación entre PEDIDO y PRODUCTO se representa mediante LINEA_PEDIDO.

A partir de este modelo iremos construyendo los ejemplos del tema.

2️⃣ Relacionamos información de varias tablas​

Cuando los datos que necesitamos se encuentran en tablas diferentes debemos indicar:

  • qué tablas intervienen;
  • qué columnas queremos recuperar;
  • y cómo están relacionadas esas tablas.

Para combinar filas relacionadas utilizaremos principalmente JOIN.

🔸 Recuperamos las filas relacionadas con INNER JOIN​

INNER JOIN devuelve únicamente las filas que tienen correspondencia en las dos tablas.

Su estructura básica es:

SELECT tabla_1.columna1, tabla_2.columna2
FROM tabla_1
INNER JOIN tabla_2
    ON tabla_1.clave = tabla_2.clave;
en este ejemplo
  • la palabra reservada INNER es opcional;
  • en la cláusula ON se especifica la condición que relaciona las tablas;
  • si no indicamos ninguna condición de unión, MySQL combina cada fila de una tabla con todas las filas de la otra, obteniendo el producto cartesiano.

Por ejemplo, si queremos mostrar cada producto junto a su categoría:

SELECT producto.nombre, categoria.nombre
FROM producto
INNER JOIN categoria
    ON producto.id_categoria = categoria.id_categoria;
en este ejemplo

En este ejemplo:

  1. producto y categoria son las tablas que necesitamos consultar.
  2. ON indica cómo se relacionan ambas tablas.
  3. Solo aparecerán los productos cuyo id_categoria tenga correspondencia con una fila de categoria.
  4. El resultado puede mostrar columnas procedentes de ambas tablas.
La condición de unión es fundamental

La cláusula ON debe expresar correctamente la relación entre las tablas.

Normalmente relacionaremos una clave foránea con la clave primaria a la que hace referencia.

🔸 Utilizamos alias para las tablas​

Cuando intervienen varias tablas, escribir sus nombres completos puede hacer que la consulta resulte difícil de leer.

Podemos utilizar alias:

SELECT p.nombre, c.nombre
FROM producto p
INNER JOIN categoria c
    ON p.id_categoria = c.id_categoria;
en este ejemplo

Los alias p y c son nombres temporales que utilizamos únicamente dentro de la consulta. No modifican los nombres reales de las tablas.

👉 Los alias resultan especialmente útiles cuando distintas tablas contienen columnas con el mismo nombre.

🔸 Podemos relacionar más de dos tablas​

Una consulta puede incorporar tantos JOIN como sean necesarios.

Por ejemplo, si queremos ver qué cliente ha realizado cada pedido:

SELECT cl.nombre, pe.id_pedido, pe.fecha_pedido
FROM cliente cl
INNER JOIN pedido pe
    ON cl.id_cliente = pe.id_cliente;

Y si queremos mostrar los productos que aparecen en cada pedido:

SELECT pe.id_pedido, pr.nombre, lp.cantidad
FROM pedido pe
INNER JOIN linea_pedido lp
    ON pe.id_pedido = lp.id_pedido
INNER JOIN producto pr
    ON lp.id_producto = pr.id_producto;
en este ejemplo
  1. pedido se relaciona con linea_pedido mediante id_pedido.
  2. linea_pedido se relaciona con producto mediante id_producto.
  3. La tabla linea_pedido actúa como enlace entre los pedidos y los productos.
  4. El resultado muestra, para cada línea de pedido:
    • el identificador del pedido;
    • el nombre del producto;
    • y la cantidad solicitada.
Sigue las relaciones del modelo

Antes de escribir una consulta con varias tablas, localiza en el modelo relacional el camino que conecta los datos que necesitas.

No se trata de añadir tablas hasta que la consulta funcione, sino de entender qué relación permite pasar de una a otra.

3️⃣ No siempre hay una fila relacionada​

INNER JOIN solo muestra las filas que tienen correspondencia en ambas tablas.

En ocasiones necesitamos conservar también filas aunque no exista una coincidencia en la otra tabla.

Para ello podemos utilizar una composición externa.

🔸 Conservamos todas las filas de la tabla izquierda con LEFT JOIN​

LEFT JOIN devuelve:

  • todas las filas de la tabla situada a la izquierda;
  • y los datos coincidentes de la tabla situada a la derecha.

Cuando no existe correspondencia, las columnas de la tabla derecha aparecen con valor NULL.

Por ejemplo, para ver todas las categorías, aunque alguna todavía no tenga productos asociados:

SELECT c.nombre, p.nombre
FROM categoria c
LEFT JOIN producto p
    ON c.id_categoria = p.id_categoria;
en este ejemplo

Esta consulta mostrará todas las categorías, tengan o no productos asociados.

Cuando una categoría no tenga ningún producto, las columnas procedentes de producto aparecerán como NULL.

Esto permite responder preguntas como:

  • ¿qué categorías todavía no tienen productos?;
  • ¿qué clientes no han realizado pedidos?;
  • ¿qué productos no han aparecido en ningún pedido?

Por ejemplo, para localizar únicamente las categorías sin productos:

SELECT c.nombre
FROM categoria c
LEFT JOIN producto p
    ON c.id_categoria = p.id_categoria
WHERE p.id_producto IS NULL;
INNER JOIN o LEFT JOIN

Antes de elegir, pregúntate:

¿Quiero únicamente las filas que tienen correspondencia o necesito conservar también las que no la tienen?

  • Si solo interesan las coincidencias → INNER JOIN.
  • Si deben aparecer todas las filas de la tabla izquierda → LEFT JOIN.

🔸 RIGHT JOIN aplica la misma idea desde el otro lado​

RIGHT JOIN conserva todas las filas de la tabla situada a la derecha y añade las coincidencias de la tabla izquierda.

SELECT p.nombre, c.nombre
FROM producto p
RIGHT JOIN categoria c
    ON p.id_categoria = c.id_categoria;
en este ejemplo
  1. producto es la tabla situada a la izquierda del RIGHT JOIN.
  2. categoria es la tabla situada a la derecha, por lo que se conservarán todas sus filas.
  3. La condición ON p.id_categoria = c.id_categoria indica cómo se relacionan ambas tablas.
  4. Cuando una categoría tiene productos asociados, se muestran sus nombres junto al nombre de la categoría.
  5. Si una categoría no tiene ningún producto relacionado, seguirá apareciendo en el resultado y las columnas procedentes de producto tendrán valor NULL.

Este tipo de consulta puede resultar útil cuando queremos revisar todo el contenido de la tabla situada a la derecha, incluso cuando algunos de sus registros no tienen correspondencia en la tabla de la izquierda.

Por ejemplo:

  • categorías sin productos;
  • clientes sin pedidos;
  • productos que nunca se han incluido en un pedido;
  • departamentos sin empleados;
  • cursos sin alumnado matriculado.

En muchos casos podemos expresar la misma necesidad intercambiando el orden de las tablas y utilizando LEFT JOIN.

Prioriza consultas fáciles de leer

Si dos consultas permiten obtener el mismo resultado, suele ser preferible utilizar la que exprese con mayor claridad qué conjunto de datos queremos conservar.

Por ejemplo, estas dos consultas pueden utilizarse para mostrar todas las categorías, tengan o no productos asociados:

SELECT c.nombre, p.nombre
FROM categoria c
LEFT JOIN producto p
ON c.id_categoria = p.id_categoria;

SELECT p.nombre, c.nombre
FROM producto p
RIGHT JOIN categoria c
ON p.id_categoria = c.id_categoria;

Ambas permiten conservar todas las filas de categoria, pero la primera suele resultar más fácil de leer, porque deja más claro desde el principio que queremos partir de la tabla categoria y mantener todas sus filas.

4️⃣ Resumimos información​

No siempre necesitamos recuperar filas individuales.

En muchas ocasiones queremos obtener información resumida: contar registros, calcular medias, obtener máximos o sumar valores.

Para ello utilizamos funciones de agregación.

Las más habituales son:

  • COUNT() → cuenta filas o valores;
  • SUM() → suma valores;
  • AVG() → calcula la media;
  • MIN() → obtiene el valor mínimo;
  • MAX() → obtiene el valor máximo.

Por ejemplo, para contar el número total de productos:

SELECT COUNT(*) AS total_productos
FROM producto;
en este ejemplo

COUNT(*) cuenta el número de filas devueltas por la consulta.

El resultado será una única fila con el número total de productos.

También podemos calcular otros valores:

SELECT
    MIN(precio) AS precio_minimo,
    MAX(precio) AS precio_maximo,
    AVG(precio) AS precio_medio
FROM producto;

👉 Las funciones de agregación trabajan sobre un conjunto de filas y devuelven un valor resumen.

🔸 Agrupamos filas con GROUP BY​

Cuando queremos obtener un resultado de resumen para cada grupo de filas, utilizamos GROUP BY.

Por ejemplo, para saber cuántos productos hay en cada categoría:

SELECT id_categoria, COUNT(*) AS total_productos
FROM producto
GROUP BY id_categoria;
en este ejemplo

GROUP BY id_categoria forma un grupo con todos los productos que tienen el mismo id_categoria.

Después, COUNT(*) calcula cuántas filas contiene cada grupo.

El resultado contiene una fila por categoría.

Podemos combinar GROUP BY con JOIN para mostrar información más comprensible:

SELECT c.nombre, COUNT(*) AS total_productos
FROM categoria c
INNER JOIN producto p
    ON c.id_categoria = p.id_categoria
GROUP BY c.id_categoria, c.nombre;

Otro ejemplo interesante consiste en saber cuántos pedidos ha realizado cada cliente:

SELECT cl.nombre, COUNT(*) AS total_pedidos
FROM cliente cl
INNER JOIN pedido pe
    ON cl.id_cliente = pe.id_cliente
GROUP BY cl.id_cliente, cl.nombre;
Piensa qué representa cada fila del resultado

Cuando utilizamos GROUP BY, cada fila del resultado ya no representa necesariamente una fila de la tabla original.

Puede representar, por ejemplo:

  • una categoría;
  • un cliente;
  • un producto;
  • un pedido;
  • o cualquier otro grupo que hayamos definido.

🔸 Filtramos grupos con HAVING​

WHERE y HAVING no realizan la misma función.

  • WHERE filtra filas antes de agrupar.
  • HAVING filtra grupos después de realizar el GROUP BY.

Por ejemplo, para mostrar únicamente las categorías con más de dos productos:

SELECT c.nombre, COUNT(*) AS total_productos
FROM categoria c
INNER JOIN producto p
    ON c.id_categoria = p.id_categoria
GROUP BY c.id_categoria, c.nombre
HAVING COUNT(*) > 2;
en este ejemplo

Primero se agrupan los productos por categoría.

Después se calcula COUNT(*) para cada grupo.

Finalmente, HAVING conserva únicamente los grupos cuyo recuento es superior a 2.

WHERE o HAVING

Pregúntate qué quieres filtrar:

  • una fila individual → WHERE;
  • el resultado de una agrupación → HAVING.

En una misma consulta pueden aparecer ambos.

5️⃣ Utilizamos una consulta dentro de otra​

En ocasiones necesitamos conocer el resultado de una consulta para poder resolver otra.

Una subconsulta es una instrucción SELECT incluida dentro de otra instrucción SQL.

La consulta interior se ejecuta para proporcionar un valor o un conjunto de valores que utilizará la consulta exterior.

🔸 Subconsultas que devuelven un único valor​

Supongamos que queremos recuperar los productos cuyo precio es superior al precio medio.

Primero podríamos calcular la media:

SELECT AVG(precio)
FROM producto;

Ese resultado puede utilizarse directamente en otra consulta:

SELECT nombre, precio
FROM producto
WHERE precio > (
    SELECT AVG(precio)
    FROM producto
);
en este ejemplo

La subconsulta:

SELECT AVG(precio) FROM producto

devuelve un único valor.

La consulta exterior compara el precio de cada producto con ese valor y conserva únicamente los productos cuyo precio es superior a la media.

🔸 Subconsultas que devuelven varios valores​

Cuando la subconsulta puede devolver varios valores no podemos tratar su resultado como un único dato.

Una posibilidad es utilizar IN.

Por ejemplo, para recuperar los productos cuya categoría empieza por la letra A:

SELECT nombre
FROM producto
WHERE id_categoria IN (
    SELECT id_categoria
    FROM categoria
    WHERE nombre LIKE 'A%'
);
en este ejemplo

La subconsulta obtiene los identificadores de las categorías cuyo nombre comienza por A.

La consulta exterior recupera los productos cuyo id_categoria se encuentra entre esos valores.

Lee las subconsultas de dentro hacia fuera

Cuando una consulta contiene otra consulta, suele resultar más fácil interpretarla comenzando por la parte más interna:

  1. ¿Qué devuelve la subconsulta?
  2. ¿Cómo utiliza ese resultado la consulta exterior?

🔸 JOIN o subconsulta​

En algunos problemas podemos obtener el mismo resultado mediante un JOIN o mediante una subconsulta.

No existe una regla que obligue a utilizar siempre una de las dos formas.

En este repaso interesa recuperar sobre todo el razonamiento:

  • si necesitamos mostrar columnas de varias tablas, normalmente un JOIN resulta natural;
  • si necesitamos utilizar el resultado de una consulta como condición de otra, una subconsulta puede expresar mejor el problema.
Prioriza la claridad

Una consulta correcta no solo debe devolver el resultado esperado, también debe permitir entender con facilidad qué información se está buscando y cómo se obtiene.

6️⃣ En resumen​

Cuando la información necesaria está repartida entre varias tablas, debemos utilizar las relaciones definidas en el modelo para recuperarla correctamente.

  • INNER JOIN → combina únicamente filas relacionadas.
  • LEFT JOIN → conserva todas las filas de la tabla izquierda.
  • RIGHT JOIN → conserva todas las filas de la tabla derecha.
  • COUNT, SUM, AVG, MIN, MAX → permiten obtener información resumida.
  • GROUP BY → agrupa filas para calcular resultados por grupos.
  • HAVING → filtra los grupos obtenidos.
  • Las subconsultas permiten utilizar el resultado de una consulta dentro de otra.
Idea clave

Las claves primarias y foráneas no sirven únicamente para mantener la integridad de los datos.

También nos indican cómo podemos recorrer las relaciones entre las tablas para recuperar la información que necesitamos.
