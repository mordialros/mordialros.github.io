Proyecto Intermodular

2.º ASIR · Curso 2026-2027

El Proyecto Intermodular nos permitirá integrar y aplicar conocimientos y habilidades adquiridos en los diferentes módulos del ciclo para abordar una necesidad o problema relacionado con el ámbito profesional de ASIR.

A lo largo del curso tendremos que analizar una situación, plantear y diseñar una propuesta, planificar cómo llevarla a cabo, desarrollarla y comprobar los resultados obtenidos.

El proyecto podrá incorporar elementos de investigación, innovación o emprendimiento, pero siempre deberá estar relacionado con las competencias profesionales propias de Administración de Sistemas Informáticos en Red.

1️⃣ ¿Qué vamos a hacer?​

A lo largo del curso aprenderemos a desarrollar un proyecto técnico relacionado con el ámbito profesional de ASIR.

Nuestro objetivo será ser capaces de:

  • identificar una necesidad o problema
  • analizar la situación y comprender qué hace falta realmente
  • buscar información y valorar distintas alternativas
  • plantear una propuesta viable
  • planificar cómo llevarla a cabo
  • implantar, configurar, investigar o desarrollar la solución propuesta
  • comprobar los resultados obtenidos
  • documentar el trabajo realizado
  • presentar y defender técnicamente el proyecto

El proyecto no consistirá únicamente en conseguir que algo funcione; también será importante saber por qué se ha elegido esa solución, cómo se ha organizado el trabajo, qué decisiones se han tomado y qué evidencias permiten comprobar los resultados obtenidos.

Idea clave

En este módulo no se trata solo de hacer, sino también de analizar, justificar, comprobar y comunicar el trabajo realizado.

2️⃣ ¿Qué es un proyecto de ASIR?​

Un proyecto de ASIR debe estar relacionado principalmente con la administración, configuración, despliegue, seguridad y mantenimiento de sistemas, redes y servicios.

El proyecto puede consistir, por ejemplo, en diseñar e implantar una infraestructura, mejorar la seguridad de una organización, desplegar servicios, automatizar tareas de administración, trabajar con bases de datos o investigar y comparar diferentes soluciones técnicas.

En algunos proyectos podrá aparecer una pequeña aplicación, una interfaz web o scripts propios, pero no es necesario desarrollar software para realizar un proyecto de ASIR.

Lo importante será que el proyecto permita resolver una necesidad relacionada con ámbitos como:

  • servidores y sistemas operativos
  • redes y comunicaciones
  • servicios de red
  • usuarios, grupos y permisos
  • bases de datos
  • virtualización
  • almacenamiento
  • seguridad
  • copias de seguridad y recuperación
  • monitorización
  • automatización
  • alta disponibilidad
  • despliegue y mantenimiento de servicios
Idea clave

El centro del proyecto debe estar en una necesidad propia del ámbito profesional de ASIR.

Puede ser una infraestructura, un servicio, una mejora, una automatización o una investigación técnica.

3️⃣ De una idea a un proyecto de ASIR​

Muchas veces una idea inicial puede sonar más cercana al desarrollo de software que al ámbito de ASIR.

Eso no significa que no pueda servir, lo importante será reformularla para que el centro del proyecto esté en la infraestructura, los servicios, la seguridad, la administración o la investigación técnica.

Videojuego

Un posible interés inicial puede ser el mundo del videojuego.

En lugar de centrar el proyecto en desarrollar un videojuego, podríamos plantearlo desde preguntas como:

  • ¿qué infraestructura necesita un servidor de juego?
  • ¿cómo se gestionan los usuarios y accesos?
  • ¿cómo se protegen los datos y configuraciones?
  • ¿cómo se monitoriza el servicio?
  • ¿cómo se automatizan tareas de mantenimiento o copia?
  • ¿cómo se garantiza la disponibilidad del sistema?

De este modo, el proyecto pasaría a centrarse en la infraestructura y administración del servicio, no en el desarrollo del juego.

Web o app para reservas de un gimnasio

La idea inicial puede surgir de una necesidad real: mejorar la gestión de reservas, actividades o entrenamientos.

En ASIR el proyecto no se centraría principalmente en programar la aplicación, sino en cuestiones como:

  • qué servicios necesita para funcionar
  • dónde se desplegará
  • cómo se conectarán los distintos componentes
  • cómo se almacenarán y protegerán los datos
  • cómo se gestionarán usuarios y permisos
  • cómo se realizarán copias de seguridad
  • cómo se monitorizará el sistema
  • cómo se garantizará un acceso seguro

Aquí el centro del proyecto estaría en el despliegue, la administración y la seguridad de la solución.

Servicio para agilizar pedidos en terrazas

También puede surgir una idea relacionada con la hostelería, por ejemplo mejorar la atención en una terraza o la gestión de pedidos.

De nuevo, el proyecto de ASIR no tendría por qué centrarse en desarrollar la aplicación de pedidos, sino en diseñar la solución técnica que la hace posible:

  • red local o conectividad
  • acceso desde distintos dispositivos
  • base de datos
  • usuarios y permisos
  • seguridad
  • copias de seguridad
  • monitorización
  • disponibilidad del servicio

El interés está en cómo se implanta y administra la infraestructura que permite dar ese servicio.

Idea clave

No se trata de abandonar una idea porque “suene a aplicación”.

Se trata de preguntarnos si podemos reformularla para que el núcleo del proyecto esté en el ámbito profesional de ASIR.

4️⃣ ¿Qué enfoques puede tener nuestro proyecto?​

No todos los proyectos tienen que resolverse de la misma manera.

Dependiendo del problema o la necesidad que queramos abordar, podremos enfocar el proyecto de formas diferentes.

Resolver una necesidad técnica

Partimos de una situación concreta que necesita una solución.

Por ejemplo:

Una pequeña empresa necesita mejorar la gestión de usuarios, compartir recursos y permitir un acceso remoto seguro.

El proyecto puede centrarse en diseñar e implantar la infraestructura y los servicios necesarios para resolver esa necesidad.

Investigar y comparar soluciones

Partimos de una pregunta que queremos responder mediante pruebas y evidencias.

Por ejemplo:

¿Qué solución de monitorización se adapta mejor a una determinada infraestructura?

En este caso tendremos que:

  • definir qué queremos comparar
  • establecer criterios
  • preparar un entorno de pruebas
  • realizar experimentos
  • recoger datos
  • analizar resultados
  • obtener conclusiones
note

Investigar no significa únicamente buscar información. Una investigación aplicada debe permitirnos obtener y analizar evidencias propias.

Mejorar o automatizar una situación existente

Partimos de un proceso que ya existe, pero que puede hacerse de forma más eficiente, segura o fiable.

Por ejemplo:

Automatizar determinadas tareas de administración para reducir errores y tiempo de intervención.

Aquí pueden aparecer scripts, herramientas de automatización o pequeños desarrollos, pero siempre al servicio de la administración del sistema.

Diseñar un servicio tecnológico

Podemos plantear una solución que pudiera ofrecerse a una organización o a distintos usuarios.

Por ejemplo:

Diseñar un servicio de copias de seguridad y recuperación para pequeñas empresas.

En este caso tendremos que definir tanto la parte técnica como las condiciones necesarias para que el servicio pueda funcionar correctamente.

Idea clave

Un mismo proyecto puede combinar varios enfoques.

Lo importante será que el problema esté bien definido y que el trabajo realizado tenga una relación clara con el ámbito profesional de ASIR.

5️⃣ ¿Cómo vamos a trabajar?​

Desarrollaremos el proyecto de forma progresiva, avanzando desde la identificación de una necesidad hasta la elaboración de la memoria y la defensa final.

Nos organizaremos en cinco grandes fases que nos ayudarán a analizar la necesidad, diseñar el proyecto, planificar el trabajo, llevarlo a cabo y evaluar sus resultados.

En cada fase realizaremos diferentes tareas y generaremos evidencias que utilizaremos posteriormente para construir la memoria final.

🔎 Fase 1. Analizamos la necesidad

El primer paso será comprender bien el problema o necesidad que queremos abordar.

Tendremos que analizar:

  • cuál es la situación de partida
  • quién tiene esa necesidad
  • qué se está haciendo actualmente
  • qué queremos resolver, mejorar o estudiar
  • qué requisitos o condicionantes existen
  • qué alternativas podemos encontrar

El objetivo será definir correctamente qué problema queremos abordar y por qué merece la pena hacerlo.

🧩 Fase 2. Diseñamos el proyecto

Una vez comprendida la necesidad, tendremos que decidir qué propuesta queremos plantear.

En esta fase definiremos:

  • los objetivos
  • el alcance
  • la solución o enfoque elegido
  • las posibles alternativas
  • los recursos necesarios
  • la viabilidad técnica
  • los criterios que utilizaremos para valorar el resultado.

En un proyecto de investigación también habrá que concretar qué queremos estudiar o comparar y cómo vamos a obtener evidencias.

🗂️ Fase 3. Planificamos cómo llevarlo a cabo

Antes de empezar el trabajo técnico será necesario organizar el proyecto.

Tendremos que decidir:

  • qué tareas hay que realizar
  • en qué orden
  • qué recursos necesitamos
  • qué tiempos estimamos
  • cómo se repartirán las responsabilidades
  • qué riesgos o dificultades pueden aparecer
  • qué evidencias iremos generando

El objetivo será disponer de un plan de trabajo claro, viable y realista.

⚙️ Fase 4. Desarrollamos, seguimos y evaluamos el proyecto

En esta fase llevaremos a cabo el trabajo técnico definido.

Dependiendo del proyecto podremos:

  • instalar
  • configurar
  • desplegar
  • integrar
  • automatizar
  • experimentar
  • realizar pruebas
  • recoger datos
  • comparar soluciones
  • registrar incidencias
  • introducir cambios
  • analizar resultados

Durante todo el proceso tendremos que comprobar si el proyecto avanza según lo previsto y si la solución responde realmente a la necesidad inicial.

No bastará con decir que algo funciona: tendremos que aportar evidencias que permitan comprobarlo.

🎤 Fase 5. Elaboramos la memoria y defendemos el proyecto

La última fase consistirá en organizar y comunicar todo el trabajo realizado.

La memoria final recogerá, de forma estructurada:

  • la necesidad o problema de partida
  • el análisis realizado
  • la propuesta diseñada
  • la planificación
  • el desarrollo del proyecto
  • las incidencias y cambios
  • las pruebas y evidencias
  • los resultados obtenidos
  • las conclusiones
  • las posibles mejoras

La memoria no se elaborará desde cero al final del curso. Se irá construyendo a partir del trabajo realizado y de las evidencias generadas en las fases anteriores.

También tendremos que preparar la defensa del proyecto, explicando y justificando las decisiones tomadas y respondiendo a las preguntas que puedan plantearse.

Idea clave

El proyecto irá creciendo fase a fase.

Cada etapa generará trabajo y evidencias que utilizaremos después para construir la memoria y defender el resultado final.

Para quedarnos con una idea

El Proyecto Intermodular no consiste en aplicar una tecnología concreta, sino en partir de una necesidad y construir una respuesta técnica propia del ámbito de ASIR.
