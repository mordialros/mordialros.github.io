5.3. Creación de tablas y tipos de datos

Ya tenemos creada la base de datos techrepair. Ahora vamos a construir sus tablas. Para ello, debemos decidir qué tipo de dato utilizará cada columna y cómo se almacenará la información.

1️⃣ Creamos una tabla​

La sentencia CREATE TABLE permite definir la estructura de una tabla: su nombre, sus columnas, sus tipos de datos y sus restricciones.

CREATE TABLE nombre_tabla (
    columna1 tipo_de_dato,
    columna2 tipo_de_dato
) ENGINE = InnoDB;

Cada definición de columna se separa mediante una coma. La última no lleva coma. Con ENGINE = InnoDB indicamos el motor de almacenamiento, aunque no es obligatorio especificarlo si ya es el predeterminado.

Vamos a crear nuestra primera tabla de TechRepair: cliente.

USE techrepair;

CREATE TABLE cliente (
    id_cliente INT,
    nombre VARCHAR(80),
    email VARCHAR(150),
    telefono VARCHAR(20)
) ENGINE = InnoDB;
Una estructura todavía incompleta

Por ahora solo hemos definido las columnas y sus tipos de datos. Todavía no hemos indicado la clave primaria, la unicidad del correo ni los campos obligatorios. Completaremos la tabla en el apartado 5.4 sin perder los registros válidos que introduzcamos aquí.

2️⃣ Elegimos los tipos de datos​

El tipo de dato determina qué clase de valores puede almacenar una columna. No debemos elegirlo únicamente por su tamaño: también importa el significado del dato y las operaciones que realizaremos con él.

🔶 Datos numéricos​

TipoUsoEjemplo
TINYINTEnteros pequeños (de -128 a 127)Indicador de estado operativo
SMALLINTEnteros de menor rango que INT (de -32768 a 32767)Minutos de una intervención
INTEnteros (de -2147483648 a 2147483647)Identificador de un cliente
BIGINTEnteros de rango muy amplioIdentificador en una tabla de gran volumen
DECIMAL(p,s)Números decimales exactosPresupuesto de una reparación
FLOAT / DOUBLENúmeros decimales aproximadosMediciones de sensores

UNSIGNED permite utilizar únicamente valores no negativos en tipos enteros y amplía su rango positivo. Por ejemplo, SMALLINT UNSIGNED admite valores de 0 a 65535. No impide almacenar el cero.

En DECIMAL(p,s), p indica el número total de dígitos y s los dígitos decimales. Por ejemplo, DECIMAL(8,2) admite hasta seis dígitos enteros y dos decimales: 999999.99 como valor positivo máximo.

Para importes monetarios utilizaremos DECIMAL, no FLOAT ni DOUBLE, para evitar errores de aproximación propios de estos últimos.

🔶 Cadenas de caracteres​

TipoUsoEjemplo
CHAR(n)Cadenas de longitud fijaCódigo de longitud fija
VARCHAR(n)Cadenas de longitud variable, con un máximo de n caracteresNombre, correo, teléfono
TEXTTextos más extensosDescripción de una avería

Un teléfono o un número de serie no son necesariamente datos numéricos: no realizamos cálculos con ellos y pueden contener ceros iniciales, signos o letras. Por eso los almacenaremos como cadenas.

🔶 Fechas y horas​

TipoUsoEjemplo
DATEFecha'2026-11-25'
TIMEHora o intervalo temporal'15:30:00'
DATETIMEFecha y hora'2026-11-25 15:30:00'
TIMESTAMPFecha y hora con conversión según la zona horaria de la sesiónInstante de registro

En nuestros ejemplos utilizaremos DATE para fechas y DATETIME cuando necesitemos registrar también la hora.

🔶 Valores booleanos​

BOOLEAN (o BOOL) permite representar valores de verdadero y falso. En MySQL es un alias de TINYINT(1): TRUE equivale a 1 y FALSE a 0.

BOOLEAN no limita los valores

MySQL también permite almacenar otros enteros dentro del rango de TINYINT. Si queremos admitir exclusivamente 0 y 1, necesitaremos una restricción CHECK, que veremos en el siguiente apartado.

3️⃣ Comprobamos la estructura y los datos​

Ejecuta estas sentencias para inspeccionar la tabla que acabamos de crear:

SHOW TABLES;
DESCRIBE cliente;
SHOW CREATE TABLE cliente;

DESCRIBE muestra las columnas y sus propiedades. SHOW CREATE TABLE muestra la sentencia que representa la definición de la tabla, incluido su motor de almacenamiento.

🔶 Introducimos los primeros registros​

Para comprobar que la tabla funciona, vamos a utilizar INSERT INTO. Indicamos las columnas y, en el mismo orden, los valores que queremos guardar.

INSERT INTO cliente (id_cliente, nombre, email, telefono)
VALUES (1, 'Lucía Martín', 'lucia@example.com', '612345678');

INSERT INTO cliente (id_cliente, nombre, email, telefono)
VALUES (2, 'Álex Ruiz', 'alex@example.com', NULL);

Los textos y las fechas se escriben entre comillas simples; los valores numéricos no las necesitan. NULL, sin comillas, indica que no se dispone de un valor.

Comprueba los registros:

SELECT * FROM cliente;

Esta consulta muestra todas las columnas y filas de la tabla. De momento utilizaremos INSERT y SELECT únicamente para comprobar nuestra implementación. Estudiaremos el lenguaje de manipulación y consulta de datos más adelante.

No repitas las inserciones sin comprobar los datos

Todavía no hemos definido la clave primaria. Si ejecutas varias veces los INSERT anteriores, MySQL puede admitir registros duplicados. Ejecuta las inserciones una sola vez y conserva los datos para el siguiente apartado.

4️⃣ Creamos una tabla mediante Workbench​

Vamos a crear la tabla tecnico utilizando las herramientas gráficas. Su estructura inicial será:

ColumnaTipo
id_tecnicoINT
nombreVARCHAR(80)
especialidadVARCHAR(80)
fecha_altaDATE

En el panel Schemas, localiza techrepair y busca la opción de creación de tablas. Introduce el nombre, añade las cuatro columnas y selecciona InnoDB si el formulario permite elegir el motor. No añadas todavía las restricciones del modelo. Si se muestra el SQL generado, compáralo con el ejemplo anterior antes de confirmar.

Comprueba el resultado con:

DESCRIBE tecnico;
SHOW CREATE TABLE tecnico;

La sentencia equivalente es:

CREATE TABLE tecnico (
    id_tecnico INT,
    nombre VARCHAR(80),
    especialidad VARCHAR(80),
    fecha_alta DATE
) ENGINE = InnoDB;

No ejecutes esta última sentencia si ya has creado la tabla con el asistente.

5️⃣ Comenzamos el diccionario de datos​

El diccionario de datos documenta qué información almacena cada columna y cómo está definida. Lo iremos completando a medida que construyamos la base de datos.

6️⃣ Ponlo en práctica​

Antes de seguir, elige qué tipos de datos utilizarías para estos atributos de TechRepair y justifica brevemente tu elección: equipo.numero_serie, reparacion.presupuesto, reparacion.fecha_entrada, intervencion.fecha_hora e intervencion.minutos.

Guarda las sentencias de creación de cliente y tecnico en un script llamado 02-techrepair-tablas.sql. Puedes copiar la definición de la tabla creada gráficamente desde SHOW CREATE TABLE. Guarda las inserciones de prueba aparte o como un bloque claramente separado.

Proyecto individual: CyberArena

Ya puedes ir seleccionando los tipos de datos de las columnas de CyberArena y comenzar su diccionario de datos. Todavía no tienes que entregar nada: la entrega E2 se realizará cuando hayamos trabajado las claves, las restricciones y la integridad referencial.
