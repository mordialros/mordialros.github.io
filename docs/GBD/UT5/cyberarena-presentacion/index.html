🎮 CyberArena: del diseño a la implementación

1️⃣ El encargo​

CyberArena es un centro de ocio tecnológico que dispone de zonas de videojuegos, simuladores de conducción y realidad virtual. Necesita una base de datos para gestionar sus puestos, clientes, reservas y pagos.

Tu tarea será implementar en MySQL el modelo relacional que te proporciona la empresa, comprobar que funciona correctamente y adaptar su estructura cuando aparezcan nuevas necesidades.

No tendrás que elaborar el modelo E/R ni normalizarlo: el diseño lógico ya está realizado.

2️⃣ Modelo relacional de partida​

TablaAtributosClaves
ZONAid_zona, nombre, capacidadPK: id_zona; alternativa: nombre
PUESTOid_zona, num_puesto, descripcion, operativoPK: (id_zona, num_puesto); FK: id_zona → ZONA
CLIENTEid_cliente, dni, nombre, email, telefonoPK: id_cliente; alternativa: dni
RESERVAid_reserva, id_cliente, id_zona, num_puesto, inicio, fin, importe, estado, observacionesPK: id_reserva; FK: id_cliente → CLIENTE; FK: (id_zona, num_puesto) → PUESTO
PAGOid_pago, id_reserva, fecha_pago, importe, metodoPK: id_pago; alternativa: id_reserva; FK: id_reserva → RESERVA

Recuerda que una clave compuesta está formada por varios atributos que actúan conjuntamente.

3️⃣ Reglas del problema​

🔶 Zonas y puestos​

  • Cada zona tiene un identificador y un nombre único. Su capacidad debe ser un número entero positivo.
  • Cada puesto pertenece a una zona. Su número es un entero positivo y es único dentro de esa zona, pero puede repetirse en otras zonas.
  • De cada puesto se guarda una descripción y si está operativo o no. Por defecto, está operativo.

🔶 Clientes​

  • Cada cliente tiene un identificador y un DNI único.
  • El nombre y el correo electrónico son obligatorios. El teléfono es opcional.

🔶 Reservas​

  • Cada reserva corresponde a un único cliente y a un único puesto.
  • Se registra la fecha y hora de inicio y de fin. El fin debe ser posterior al inicio.
  • El importe debe ser positivo y expresarse en euros con dos decimales.
  • Los estados admitidos son pendiente, confirmada y cancelada. Por defecto, la reserva está pendiente.
  • Las observaciones son opcionales.

🔶 Pagos​

  • Cada pago corresponde a una única reserva. Una reserva puede no tener todavía un pago, pero no puede tener más de uno.
  • Se registra la fecha y hora del pago, su importe positivo con dos decimales y el método utilizado: efectivo, tarjeta o bizum.

🔶 Reglas generales​

  • Todos los atributos son obligatorios salvo aquellos indicados expresamente como opcionales.
  • Los identificadores simples id_zona, id_cliente, id_reserva e id_pago se generarán automáticamente. El número de puesto se asignará dentro de cada zona.
  • No se podrán eliminar ni modificar las claves de zonas, puestos, clientes o reservas mientras existan registros que las referencien.
  • La empresa también necesita evitar reservas activas que se solapen para un mismo puesto y que el número de puestos supere la capacidad de su zona. Estas reglas se tendrán en cuenta al analizar las limitaciones del DDL, pero no se exige automatizarlas en este proyecto.
Del modelo lógico al físico

El modelo indica qué información debe almacenarse y qué condiciones debe cumplir. A lo largo de la unidad decidirás los tipos de datos, tamaños y demás características físicas necesarias para implementarlo.

4️⃣ ¿Cómo vas a desarrollar el proyecto?​

Trabajarás de forma individual y aplicarás en CyberArena lo que vayamos aprendiendo con TechRepair.

EntregaEncargo
E1. Creamos la base de datosCrear la base de datos y definir sus características.
E2. Construimos las tablasImplementar las tablas, claves, relaciones y restricciones.
E3. Adaptamos la base de datosModificar la estructura según nuevos requisitos y utilizar las herramientas gráficas.
E4. Comprobamos y documentamos el resultadoCargar datos, comprobar las restricciones y completar el diccionario de datos.

Utilizarás MySQL Server y MySQL Workbench. Guardarás los scripts SQL de cada entrega y completarás progresivamente el diccionario de datos a partir de la creación de las primeras tablas. Las instrucciones concretas de cada entrega se facilitarán conforme avancemos.

¿Qué tienes que hacer ahora?

Lee el modelo relacional y las reglas del problema. Comprueba que entiendes las claves y las relaciones entre las tablas. Todavía no tienes que crear la base de datos ni entregar ningún archivo.
