🛠️ UT5. Manos a la obra

Diseño físico y lenguaje DDL

Hasta ahora hemos aprendido a representar la información mediante el modelo entidad/relación, transformarla en un modelo relacional y organizarla aplicando las reglas de normalización.

Pero un modelo relacional, por muy bien diseñado que esté, todavía no es una base de datos operativa. Para utilizarlo necesitamos implementarlo en un sistema gestor de bases de datos (SGBD).

En esta unidad vamos a dar ese paso: convertir un diseño lógico normalizado en una base de datos real, funcional y documentada.

1️⃣ ¿Qué vamos a aprender?​

Al finalizar la unidad, el alumnado será capaz de:

  • Definir las estructuras físicas básicas de almacenamiento de una base de datos.
  • Crear, modificar y eliminar bases de datos y tablas.
  • Seleccionar los tipos de datos adecuados para cada columna.
  • Implementar claves primarias, alternativas y foráneas.
  • Trasladar las restricciones del diseño lógico a la base de datos y aplicar la integridad referencial.
  • Utilizar el lenguaje de definición de datos (DDL) y las herramientas gráficas del SGBD.
  • Comprobar mediante datos de prueba que la implementación se ajusta al modelo.
  • Definir y documentar el diccionario de datos.

2️⃣ Nuestro entorno de trabajo​

Utilizaremos MySQL Server como sistema gestor y MySQL Workbench como aplicación cliente, tanto para escribir y ejecutar sentencias SQL como para trabajar mediante herramientas gráficas.

Conviene recordar que no son lo mismo:

ElementoFunción
MySQL ServerAlmacena y gestiona los datos, ejecuta las sentencias y controla las restricciones.
MySQL WorkbenchPermite conectarse al servidor, enviar sentencias SQL y trabajar con herramientas gráficas.
SQLLenguaje que utilizamos para comunicarnos con el SGBD.

Estos conceptos ya se introdujeron en la UT1: Nuestro entorno de trabajo: MySQL. Ahora instalaremos las herramientas y las utilizaremos de forma práctica.

3️⃣ Nuestro caso práctico: TechRepair​

TechRepair es una empresa ficticia dedicada a la reparación y mantenimiento de equipos informáticos. Necesita una base de datos para gestionar sus clientes, los equipos que recibe, su personal técnico, las reparaciones y las intervenciones realizadas.

Partiremos de un modelo relacional normalizado y, a medida que avancemos en la unidad, iremos construyendo su base de datos en MySQL.

No se trata únicamente de conseguir que las sentencias se ejecuten sin errores. También tendremos que comprobar que la base de datos almacena la información correctamente, respeta las reglas del negocio y evita datos incoherentes.

4️⃣ ¿Cómo vamos a trabajar?​

A lo largo de esta unidad aprenderemos a implementar bases de datos utilizando SQL y las herramientas gráficas de MySQL Workbench. Para ello, trabajaremos con TechRepair, nuestro caso práctico de referencia, a través de ejemplos guiados y pequeños ejercicios que nos permitirán poner en práctica los nuevos conocimientos.

En paralelo, desarrollarás tu propio proyecto práctico individual: CyberArena, un centro de ocio tecnológico que necesita una base de datos para gestionar sus instalaciones, clientes, reservas y pagos.

Construirás la base de datos paso a paso, aplicando lo aprendido en cada sesión. Realizarás entregas progresivas que te permitirán comprobar tus avances, detectar errores y corregirlos antes de continuar.

Al finalizar la unidad, habrás implementado una base de datos funcional, elaborado su script SQL, comprobado que cumple las restricciones del diseño y documentado su estructura mediante un diccionario de datos.
