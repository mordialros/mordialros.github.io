1.5. Tipos de bases de datos y clasificación de los SGBD

No todas las bases de datos organizan la información de la misma forma ni almacenan necesariamente todos sus datos en un único lugar.

Además, los Sistemas Gestores de Bases de Datos (SGBD) también pueden clasificarse según el tipo de bases de datos que son capaces de gestionar.

En este apartado utilizaremos dos criterios:

  • cómo se organizan y relacionan los datos.
  • dónde se encuentra almacenada la información.

La idea importante es distinguir entre:

  • la base de datos, que contiene la información organizada.
  • el SGBD, que es el software que permite gestionarla.

1️⃣ Según el modelo de datos​

Un modelo de datos establece una forma de organizar los datos y representar las relaciones que existen entre ellos.

A lo largo de la historia se han utilizado distintos modelos.

🌳 Bases de datos jerárquicas​

Organizan los datos mediante una estructura similar a un árbol.

Los elementos se distribuyen en distintos niveles y cada elemento depende normalmente de otro situado en un nivel superior.

en este ejemplo

En la imagen se representa una empresa organizada en niveles. En la parte superior aparece la empresa, debajo sus departamentos y, en el nivel inferior, los empleados de cada departamento.

Esta estructura nos permite ver que cada elemento depende de otro situado en un nivel superior, lo que caracteriza al modelo jerárquico.

📌 Ejemplo de usoUn catálogo organizado como categoría → subcategoría → producto.
✅ Puede encajar cuando...La información sigue una jerarquía clara y estable, como el organigrama de una empresa, la estructura de carpetas de un sistema o un catálogo con categorías y subcategorías.
🧰 Ejemplo de SGBDIBM IMS.

🕸️ Bases de datos en red​

El modelo en red permite que un elemento pueda estar relacionado con varios elementos diferentes.

La estructura deja de ser un árbol estricto y se parece más a una red de conexiones.

en este ejemplo

En la imagen se representa una red de relaciones entre profesorado, asignaturas, grupos y aulas. Un mismo profesor puede impartir varias asignaturas, una asignatura puede estar en varios grupos y distintos grupos pueden utilizar diferentes aulas.

La imagen muestra, por tanto, que un mismo elemento puede estar conectado con varios otros, lo que caracteriza al modelo en red.

📌 Ejemplo de usoUna red de transportes en la que estaciones, líneas y recorridos mantienen múltiples conexiones entre sí.
✅ Puede encajar cuando...Necesitamos representar una realidad con muchas relaciones cruzadas, como una red de transportes o las relaciones entre profesorado, asignaturas, grupos y aulas.
🧰 Ejemplo de SGBDIDMS.

📊 Bases de datos relacionales​

Organizan los datos principalmente mediante tablas relacionadas entre sí.

Cada tabla almacena información sobre un determinado conjunto de elementos y las relaciones permiten conectar la información de distintas tablas.

en este ejemplo

En la imagen se representan varias tablas de una tienda: Clientes, Pedidos, DetallePedido y Productos. Las flechas muestran cómo se relacionan entre sí.

Esto nos permite ver que la información se organiza en tablas y que las relaciones conectan unas tablas con otras, lo que caracteriza al modelo relacional.

📌 Ejemplo de usoLa gestión de una tienda mediante información relacionada sobre clientes, pedidos, productos y líneas de pedido.
✅ Puede encajar cuando...Necesitamos gestionar datos estructurados y relacionados, como en un instituto con alumnado, grupos y matrículas, o una tienda con clientes, pedidos y productos.
🧰 Ejemplos de SGBDMySQL, MariaDB, PostgreSQL, Oracle Database y Microsoft SQL Server.
Idea clave

Este es el modelo con el que trabajaremos principalmente durante el módulo.

🧱 Bases de datos orientadas a objetos​

Organizan la información siguiendo principios similares a los utilizados en la programación orientada a objetos.

Los datos pueden almacenarse formando estructuras que representan objetos junto con sus características y, en algunos casos, también su comportamiento.

en este ejemplo

En la imagen se representan los objetos Alumno, Matrícula y Curso. Cada uno muestra sus atributos y, además, aparecen relaciones entre ellos.

La imagen nos sirve para ver que la información se organiza mediante objetos, una idea próxima a la utilizada en programación orientada a objetos.

📌 Ejemplo de usoUna aplicación de simulación que necesita almacenar directamente objetos complejos con sus propiedades y relaciones.
✅ Puede encajar cuando...La aplicación trabaja con objetos complejos y queremos almacenar estructuras parecidas a las que usamos en programación.
🧰 Ejemplo de SGBDObjectDB.

📦 Bases de datos NoSQL​

El término NoSQL agrupa distintas bases de datos que no utilizan necesariamente el modelo relacional tradicional.

Pueden organizar la información de formas diferentes, por ejemplo mediante documentos, pares clave-valor o grafos.

en este ejemplo

En la imagen se representan tres formas habituales de organización dentro del mundo NoSQL: un modelo de documentos, un modelo de clave-valor y un modelo de grafos.

La imagen nos permite ver que NoSQL no es un único modelo, sino un conjunto de soluciones que pueden organizar la información de formas diferentes.

📌 Ejemplos de uso

Fichas de productos con estructuras diferentes (documentos).
Sesiones de usuario o caché (clave-valor).
Relaciones entre personas en una red social (grafos).

✅ Puede encajar cuando...

Necesitamos estructuras flexibles, accesos muy rápidos por clave o trabajar especialmente con relaciones entre elementos.

🧰 Ejemplos de SGBD

MongoDB para documentos.
Redis para clave-valor.
Neo4j para grafos.

Idea clave

El modelo de datos nos permite clasificar tanto la base de datos como el SGBD que está preparado para gestionarla.

Por ejemplo, podemos hablar de una base de datos relacional y de un SGBD relacional como MySQL.

2️⃣ Según la ubicación de la información​

También podemos clasificar las bases de datos atendiendo a dónde se encuentran almacenados sus datos.

🖥️ Bases de datos centralizadas​

En una base de datos centralizada, la información se encuentra en una ubicación principal.

Los usuarios y aplicaciones pueden acceder desde diferentes equipos, pero los datos se concentran en un único sistema.

🌐 Bases de datos distribuidas​

En una base de datos distribuida, la información se encuentra repartida entre varios sistemas o ubicaciones conectados entre sí.

en este ejemplo

En la parte izquierda de la imagen se representa una base de datos centralizada: varios equipos acceden a un servidor principal donde se encuentra la información.

En la parte derecha se representa una base de datos distribuida: la información aparece repartida entre varios nodos o servidores conectados entre sí.

📌 Ejemplo centralizadoLa base de datos de una pequeña empresa almacenada en un único servidor al que acceden todos los equipos.
✅ Puede encajar cuando...Un centro educativo o una pequeña empresa trabaja con un único servidor donde se concentra la información.
📌 Ejemplo distribuidoUna empresa con varias sedes que mantiene información repartida entre servidores situados en distintas ubicaciones.
✅ Puede encajar cuando...La organización necesita repartir la información entre distintos nodos o ubicaciones conectadas.

🔸 ¿Y los SGBD?​

También podemos hablar de configuraciones de SGBD centralizadas o distribuidas según cómo se encuentre desplegado el sistema que gestiona los datos.

  • En una configuración centralizada, el SGBD gestiona la información desde un único servidor o sistema principal.
  • En una configuración distribuida, la gestión de los datos se reparte entre varios nodos conectados.
Ejemplo

Si instalamos MySQL Server en un único equipo del aula y todos los clientes se conectan a él, trabajamos con una configuración centralizada.

Idea clave

Una misma herramienta puede utilizarse de formas diferentes según cómo se instale y configure.

Por eso debemos distinguir entre clasificar el producto SGBD por el modelo que gestiona y describir cómo está desplegado el sistema.

3️⃣ Podemos combinar las clasificaciones​

Los criterios anteriores describen características diferentes.

Por ejemplo, una solución puede ser:

  • relacional y centralizada.
  • relacional y distribuida.
  • NoSQL y centralizada.
  • NoSQL y distribuida.
Ejemplo

Decir que MySQL es relacional nos informa sobre el modelo de datos que gestiona.

Decir que nuestra instalación está centralizada nos informa sobre cómo hemos desplegado el sistema.

Son dos características diferentes.

para pensar

Relaciona cada situación con la clasificación que corresponda y explica qué característica te ha permitido identificarla:

  • Un sistema organiza la información mediante tablas relacionadas.
  • Una aplicación almacena documentos con estructuras flexibles.
  • Todos los equipos de una empresa acceden a un único servidor de base de datos.
  • La información se reparte entre servidores de varias sedes.
  • Utilizamos MySQL para gestionar tablas de clientes, pedidos y productos.
  • Utilizamos Neo4j para representar relaciones entre personas de una red social.

No buscamos memorizar nombres, sino distinguir qué estamos clasificando y qué criterio estamos utilizando.

4️⃣ En resumen​

Podemos clasificar las bases de datos y los SGBD utilizando distintos criterios.

Según el modelo de datos, podemos encontrar soluciones:

  • jerárquicas.
  • en red.
  • relacionales.
  • orientadas a objetos.
  • NoSQL.

Según la ubicación de la información, podemos distinguir entre:

  • bases de datos centralizadas.
  • bases de datos distribuidas.

Los SGBD también pueden clasificarse según el modelo que gestionan. Algunos ejemplos son:

  • MySQL, MariaDB, PostgreSQL, Oracle Database y SQL Server → SGBD relacionales.
  • MongoDB → SGBD NoSQL documental.
  • Redis → SGBD NoSQL clave-valor.
  • Neo4j → SGBD NoSQL de grafos.
Idea clave

La base de datos es la información organizada.

El SGBD es el software que permite crearla y gestionarla.

Podemos utilizar criterios relacionados para clasificarlos, pero debemos tener claro qué elemento estamos describiendo en cada momento.
