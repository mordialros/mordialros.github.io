0.6. Nuestra primera comunicación

Ya sabemos reconocer una red sencilla y sus elementos principales. Ahora vamos a comprobar algo esencial: si dos equipos conectados pueden comunicarse.

Para hacerlo necesitamos introducir únicamente dos ideas nuevas: una dirección IP y la herramienta ping.

1️⃣ Una dirección para identificar el destino​

En una red IP, los dispositivos utilizan direcciones IP para identificar las interfaces que participan en la comunicación.

En esta UT no estudiaremos cómo se construyen esas direcciones ni qué significa cada una de sus partes. Solo necesitamos comprender que, para intentar comunicarnos con otro equipo, debemos saber qué dirección IP tiene configurada.

Por ejemplo, podemos trabajar con estos dos equipos:

EquipoDirección IPMáscara proporcionada
PC1192.168.10.10255.255.255.0
PC2192.168.10.11255.255.255.0

La máscara aparece porque Packet Tracer necesita ese parámetro para configurar la red. En esta UT la copiamos tal como se proporciona; todavía no necesitamos interpretarla ni calcularla.

warning

No intentamos deducir todavía si una dirección es pública, privada, de red o de host. El direccionamiento IP se estudiará con detalle en la UT4.

2️⃣ Comprobamos la comunicación con ping​

ping es una herramienta que utilizamos para comprobar si un equipo puede obtener respuesta de otro dispositivo a través de la red.

Si estamos en PC1 y queremos comprobar la comunicación con PC2, utilizamos la dirección de PC2:

ping 192.168.10.11
en este ejemplo

El comando intenta contactar con la dirección indicada. Si recibimos respuestas, sabemos que existe comunicación entre ambos equipos en ese momento. Si no recibimos respuesta, sabemos que debemos investigar qué está fallando, pero ping por sí solo no nos dice cuál es la causa.

No necesitamos estudiar todavía el protocolo que utiliza internamente ping.

tip

En Packet Tracer es habitual que la primera respuesta del primer ping falle (Request timed out) y las siguientes funcionen. No es un error: antes de enviar el primer mensaje, el equipo necesita averiguar a quién entregarlo. Lo estudiaremos más adelante.

3️⃣ Qué significa que un ping funcione​

Un resultado correcto nos permite afirmar algo concreto: el equipo desde el que hacemos la prueba consigue comunicarse con el destino indicado y recibe respuesta.

Sin embargo, no debemos sacar conclusiones más amplias de las necesarias. Que un ping funcione no significa que todos los servicios de una red funcionen correctamente.

Tampoco ocurre lo contrario: que un ping falle no siempre significa que no haya conexión.

warning

En equipos reales, el cortafuegos de Windows bloquea por defecto las respuestas al ping. Dos equipos pueden estar perfectamente conectados y, aun así, el ping fallar. En Packet Tracer no nos ocurrirá, pero lo tendremos en cuenta cuando trabajemos con equipos y máquinas virtuales reales.

Ejemplo

Si PC1 obtiene respuesta de PC2, hemos comprobado la conectividad entre esos dos equipos. Todavía no estamos comprobando si existe acceso a Internet, si funciona una página web o si una impresora está correctamente instalada.

para pensar

Si PC1 puede hacer ping a PC2 pero no sabemos nada más de la red, ¿qué podemos afirmar con seguridad y qué cosas todavía no podemos asegurar?

Idea clave

En esta UT utilizamos la dirección IP únicamente para identificar el destino de una prueba de conectividad y ping para comprobar si obtenemos respuesta. El funcionamiento completo del direccionamiento se estudiará más adelante.

Si vienes de SMR

Recupera lo que sabes: ¿qué protocolo utiliza ping y qué mensajes envía y recibe? ¿Qué nos dice la máscara 255.255.255.0 sobre PC1 y PC2? Lo retomaremos en la UT4.
