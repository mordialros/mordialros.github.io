1.2. Cómo se comunican los equipos

En la UT0 seguimos el recorrido de un mensaje entre dos equipos. Ahora vamos a identificar qué interviene en esa comunicación, en qué sentidos puede circular la información y qué papel desempeña cada equipo cuando utiliza un servicio de red.

1️⃣ Elementos de la comunicación​

En una comunicación entre equipos podemos identificar los siguientes elementos:

ElementoQué esEjemplo en una red
EmisorQuien envía un mensajeUn PC que envía una solicitud
ReceptorQuien recibe el mensajeUn servidor que recibe esa solicitud
MensajeLa información que se transmiteUna solicitud web, un archivo o un correo
Medio o canalPor donde se transmite la informaciónCable de cobre, fibra óptica u ondas de radio
ProtocoloConjunto de reglas que permite intercambiar e interpretar la informaciónHTTP, IP o Ethernet
Ejemplo

CCuando conversamos por teléfono intervienen dos personas que intercambian información, un sistema que permite transmitirla y unas reglas compartidas para entenderse. En una red ocurre algo parecido: tener los equipos conectados no basta. También necesitan protocolos compatibles para intercambiar información.

Un mismo equipo puede actuar como emisor en un momento y como receptor en otro. Por ejemplo, cuando solicitamos una página web, nuestro ordenador envía una petición y después recibe la respuesta.

2️⃣ Modos de comunicación​

Según el sentido en el que puede circular la información a través de un enlace, distinguimos tres modos:

ModoCómo funcionaEjemplo
SimplexLa información circula en un único sentidoUna emisión de radio tradicional: la emisora transmite y el receptor escucha
Half-duplexPuede circular en ambos sentidos, pero no simultáneamenteDos personas que utilizan un walkie-talkie por turnos
Full-duplexPuede circular en ambos sentidos al mismo tiempoUna conversación telefónica en la que ambos pueden hablar y escuchar simultáneamente
Idea clave

En las conexiones Ethernet actuales entre un ordenador y un switch es habitual el funcionamiento full-duplex. Estos modos describen cómo se transmite la información en un enlace; no indican si una aplicación utiliza el modelo cliente-servidor o P2P.

3️⃣ Cliente-servidor y comunicación entre iguales​

Además del sentido de transmisión, podemos distinguir las comunicaciones según qué papel desempeñan los equipos al compartir servicios y recursos.

🔶 Modelo cliente-servidor​

Un cliente solicita un recurso o servicio, y un servidor atiende esa solicitud. Es el modelo que encontramos habitualmente al consultar una página web, acceder a una plataforma educativa o utilizar un servicio de correo.

Por ejemplo, al entrar en la web del centro, nuestro navegador actúa como cliente y el servidor web responde a su petición.

  • Ventajas: permite administrar de forma centralizada los servicios y facilita aplicar controles y realizar copias de seguridad.
  • Limitaciones: si un servicio depende de un único servidor y este falla, puede dejar de estar disponible. También necesita administración y recursos adecuados.

🔶 Modelo entre iguales (P2P, peer-to-peer)​

En una comunicación entre iguales, los equipos pueden solicitar y ofrecer recursos a otros equipos sin depender necesariamente de un servidor central para ese intercambio.

Por ejemplo, dos ordenadores pueden compartir archivos directamente mediante una aplicación preparada para ello. Algunos sistemas P2P también utilizan servidores auxiliares para localizar otros equipos o coordinar conexiones.

  • Ventajas: permite compartir recursos entre equipos sin centralizar necesariamente todo el intercambio.
  • Limitaciones: la administración, la disponibilidad de los recursos y el control de acceso pueden resultar más complejos.
Idea clave

Cliente y servidor son funciones que realizan los programas, no tipos fijos de ordenador. Un equipo puede ser cliente de un servicio y servidor de otro.

La imagen representa las relaciones de intercambio de recursos. No significa que todos los equipos P2P deban estar conectados físicamente entre sí.

4️⃣ Un ejemplo completo: abrimos una página web​

Veamos cómo se combinan estos conceptos en una acción cotidiana: abrir una página web alojada en un servidor de Internet.

  1. Escribimos la dirección de una página en el navegador, que actúa como cliente.
  2. El navegador envía una solicitud que sale de nuestra red local, pasa por el router y viaja por Internet hasta el servidor web.
  3. El servidor web recibe y procesa la solicitud, y envía una respuesta con el contenido solicitado.
  4. La respuesta también viaja por la red hasta nuestro ordenador, aunque no tiene por qué seguir exactamente el mismo recorrido de ida.
  5. El navegador interpreta la respuesta y muestra la página.

En este ejemplo, el cliente y el servidor intercambian mensajes siguiendo protocolos de comunicación. Más adelante estudiaremos cómo se organizan esos protocolos en capas (UT2).
