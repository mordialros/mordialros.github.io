1.3. Red local, Internet y cliente-servidor

Ya sabemos qué es una red y qué elementos intervienen para que exista comunicación.

El siguiente paso es distinguir dos ideas que suelen confundirse al principio: tener una red y tener acceso a Internet. También veremos qué papel pueden asumir los equipos cuando intercambian información.

1️⃣ Red local e Internet​

🔸 ¿Qué es una red local?​

Una red local conecta dispositivos que se encuentran en un entorno limitado, como una vivienda, un aula, una oficina o un edificio.

Por ejemplo, en un aula podemos tener varios ordenadores conectados a un switch y una impresora compartida.

Todos esos dispositivos pueden comunicarse entre sí aunque la red no tenga conexión con el exterior.

Esto significa que una red local puede seguir funcionando aunque no haya acceso a Internet.

Ejemplo

Imaginemos un aula con veinte ordenadores conectados a un switch y una impresora de red.

Aunque desconectemos la salida a Internet, los equipos podrían seguir:

  • comunicándose entre ellos.
  • accediendo a recursos compartidos dentro de la red.
  • utilizando la impresora.
  • accediendo a un servidor local del centro.

La red local seguiría existiendo y funcionando.

🔸 ¿Qué es Internet?​

Internet es una enorme infraestructura formada por multitud de redes conectadas entre sí.

Por eso suele describirse como una red de redes.

Nuestra red doméstica, la red de un centro educativo o la red de una empresa pueden conectarse a otras redes a través de dispositivos capaces de comunicar unas redes con otras.

Cuando accedemos a una página web alojada fuera de nuestra red, la información tiene que abandonar nuestra red local y recorrer otras redes hasta llegar al servidor de destino.

Idea clave

Red local e Internet no son lo mismo.

Podemos tener una red local sin acceso a Internet.

Internet aparece cuando nuestra red se conecta con otras redes y puede intercambiar información con ellas.

2️⃣ Formas de organizar la comunicación​

Cuando varios dispositivos se comunican, no siempre lo hacen de la misma manera.

Una de las formas más habituales consiste en que un equipo o programa solicita un recurso o servicio y otro se encarga de proporcionarlo.

En este modelo aparecen dos papeles:

  • Cliente: solicita un recurso o servicio.
  • Servidor: recibe las peticiones y proporciona el recurso o servicio solicitado.

Por ejemplo, cuando abrimos una página web, nuestro navegador actúa como cliente y el servidor donde está alojada la página actúa como servidor.

🔸 Arquitectura cliente-servidor​

Cuando la comunicación se organiza de esta forma hablamos de una arquitectura cliente-servidor.

Podemos representarla de forma sencilla así:

cliente → solicita un servicio → servidor

cliente ← recibe una respuesta ← servidor

Un servidor puede atender simultáneamente las peticiones de muchos clientes.

Además, cliente y servidor describen un papel dentro de una comunicación, no necesariamente un tipo concreto de dispositivo. Un mismo equipo puede actuar como cliente en unas situaciones y como servidor en otras.

🔸 Comunicación entre iguales​

En una comunicación peer-to-peer (P2P) no existe necesariamente un servidor central que proporcione todos los recursos.

Los equipos pueden comunicarse directamente entre sí y compartir información o recursos.

En este modelo, cada equipo puede actuar tanto como cliente como servidor según la comunicación que se esté realizando.

Idea clave

Podemos encontrar dos formas básicas de organizar la comunicación:

  • Cliente-servidor: unos equipos solicitan servicios y otros los proporcionan.
  • Peer-to-peer: los equipos comparten recursos directamente entre iguales.

3️⃣ Un ejemplo completo: accedemos a una página web​

Imaginemos que desde un ordenador del aula abrimos una página web alojada en un servidor externo.

El proceso, visto de forma muy general, sería:

en este ejemplo

En la imagen podemos observar una comunicación cliente-servidor completa. El navegador de nuestro ordenador actúa como cliente: envía una solicitud a un servidor web situado fuera de nuestra red local. La solicitud atraviesa la red local, el router e Internet hasta llegar al servidor. Después, la respuesta realiza el recorrido de vuelta hasta nuestro equipo.

El proceso puede resumirse así:

  1. Nuestro ordenador forma parte de la red local y el navegador actúa como cliente.
  2. El navegador genera una solicitud para obtener una página web.
  3. La solicitud sale de la red local a través del router, que permite comunicar nuestra red con otras redes.
  4. La información atraviesa Internet hasta llegar al servidor web.
  5. El servidor recibe la solicitud, la procesa y genera una respuesta.
  6. La respuesta recorre el camino de vuelta hasta llegar al navegador de nuestro ordenador.

Fíjate en que Internet no sustituye a nuestra red local: para acceder al servidor externo, la comunicación comienza en nuestra red y después sale hacia otras redes.

Todavía no sabemos cómo se identifica exactamente el servidor, cómo se decide el camino que debe seguir la información ni qué protocolos intervienen en cada paso.

Esas cuestiones las iremos resolviendo en los siguientes apartados.

para pensar

Imaginemos estas situaciones:

  • imprimimos un documento en la impresora del aula.
  • accedemos a una página web.
  • copiamos un archivo desde un servidor del centro.
  • dos equipos intercambian directamente un archivo.

Para cada caso, intentad decidir:

  • si la comunicación puede producirse únicamente dentro de una red local o necesita acceder a otras redes.
  • qué equipo o programa actúa como cliente.
  • qué equipo o programa proporciona el recurso o servicio.
  • si encaja mejor en un modelo cliente-servidor o peer-to-peer.
Idea clave

Una red local permite comunicar dispositivos cercanos sin necesidad de Internet.

Internet conecta multitud de redes entre sí.

Dentro de esas redes, los dispositivos pueden asumir distintos papeles: normalmente solicitar servicios como clientes o proporcionarlos como servidores.
