1.5. Arquitecturas, capas y protocolos

Ya sabemos cómo se organizan las conexiones de una red. Ahora veremos cómo se organiza la comunicación: qué reglas deben seguir los equipos para entenderse y por qué las tareas necesarias se distribuyen en capas.

En esta unidad construiremos una visión general. En la UT2 estudiaremos con más detalle cómo viajan los datos y qué ocurre cuando pasan por las diferentes capas.

1️⃣ ¿Qué es un protocolo?​

Un protocolo de comunicación es un conjunto de reglas acordadas que permite a los dispositivos intercambiar información e interpretarla.

Esas reglas pueden establecer:

  • Formato (sintaxis): cómo se representa y organiza la información.
  • Significado (semántica): qué representa cada dato y cómo debe actuar el receptor.
  • Orden y tiempos de intercambio (temporización): cuándo se envían mensajes, en qué orden y cómo se gestionan determinadas respuestas o esperas.
Ejemplo

Para enviar una carta debemos seguir unas convenciones: escribir una dirección reconocible, identificar al destinatario y utilizar el servicio postal de la forma prevista. Si cada persona empleara un sistema distinto, sería mucho más difícil repartir las cartas.

En una red ocurre algo parecido: los equipos necesitan reglas comunes, aunque sean de fabricantes diferentes.

A lo largo del módulo conoceremos protocolos y tecnologías que cumplen funciones distintas:

Protocolo o tecnologíaFunción general
EthernetOrganizar la comunicación en muchas redes locales cableadas.
IPIdentificar los destinos y permitir el envío de paquetes (unidades de información) entre redes.
TCPProporcionar un transporte orientado a conexión y fiable entre aplicaciones.
UDPTransportar mensajes entre aplicaciones sin establecer una conexión ni garantizar su entrega.
HTTP / HTTPSPermitir la comunicación entre navegadores y servidores web. HTTPS añade protección mediante TLS.
DNSAyudar a obtener la dirección IP asociada a un nombre de dominio.
Idea clave

Un protocolo no hace lo mismo que otro. Por ejemplo, HTTP se relaciona con la petición de una página web, mientras que IP permite llevar paquetes hacia otras redes. Ambos pueden intervenir en una misma comunicación.

2️⃣ ¿Qué es una arquitectura de red?​

Para que dos dispositivos puedan comunicarse no basta con utilizar un único protocolo. Durante una comunicación intervienen diferentes protocolos que realizan funciones específicas, como identificar los dispositivos, determinar a dónde debe enviarse la información, transportarla y permitir que las aplicaciones intercambien datos. Todos ellos deben trabajar de forma coordinada.

Una arquitectura de red establece cómo se organizan esas funciones y cómo se relacionan los protocolos que permiten intercambiar información entre dispositivos.

🔶 Protocolos y arquitecturas de red​

Los protocolos establecen las reglas necesarias para realizar determinadas funciones de comunicación. Una arquitectura de red organiza esas funciones y define cómo colaboran entre sí.

Por ejemplo, cuando accedemos a una página web intervienen distintos protocolos:

  • HTTP o HTTPS: permiten solicitar y recibir los contenidos de la página web.
  • TCP: proporciona un transporte fiable y ordenado de los datos cuando se utiliza este protocolo.
  • IP: permite dirigir los paquetes hacia su destino a través de las redes.

Cada protocolo tiene una función diferente, pero todos colaboran para hacer posible la comunicación.

Idea clave

Un protocolo define las reglas para realizar una función de comunicación, mientras que una arquitectura de red organiza las funciones y los protocolos que intervienen en ella.

🔶 ¿Por qué organizamos la comunicación en capas?​

Las arquitecturas de red suelen organizar las funciones de comunicación en capas. Cada capa se ocupa de determinadas tareas y utiliza los servicios que le proporciona la capa inferior.

Esta separación permite abordar una comunicación compleja mediante funciones más sencillas y facilita que dispositivos y tecnologías diferentes puedan trabajar conjuntamente.

La organización en capas ofrece varias ventajas:

  • Simplifica la comunicación: cada capa se ocupa de unas funciones concretas.
  • Facilita el mantenimiento: podemos localizar y analizar problemas en diferentes partes de la comunicación.
  • Favorece la interoperabilidad: permite que equipos de distintos fabricantes se comuniquen utilizando protocolos y estándares comunes.
  • Facilita la evolución tecnológica: pueden modificarse determinadas tecnologías sin necesidad de rediseñar toda la comunicación.
Ejemplo

Un ordenador puede conectarse a una red mediante un cable Ethernet o utilizando Wi-Fi.

Aunque cambie la tecnología empleada para conectarse, podemos seguir utilizando las mismas aplicaciones y protocolos de comunicación, como HTTP e IP.

Esto es posible porque las funciones están organizadas de forma que los cambios en una parte de la comunicación no tienen por qué afectar al resto.

Para representar y estudiar esta organización utilizamos modelos de capas.

En los siguientes apartados conoceremos el modelo OSI, que describe las funciones de comunicación mediante siete capas, y la arquitectura TCP/IP, utilizada en Internet y representada habitualmente mediante cuatro capas.

3️⃣ El modelo OSI: siete capas para comprender una red​

El modelo OSI (Open Systems Interconnection, Interconexión de Sistemas Abiertos) es un modelo de referencia desarrollado por la Organización Internacional de Normalización (ISO) para describir cómo se organizan las funciones necesarias para comunicar dispositivos a través de una red.

Divide la comunicación en siete capas, cada una con unas responsabilidades determinadas. Esta separación facilita comprender cómo se comunican los equipos y permite identificar en qué parte del proceso puede producirse un problema.

Las capas se numeran desde la capa 1 (Física), relacionada con la transmisión de señales, hasta la capa 7 (Aplicación), que proporciona servicios de red a las aplicaciones.

CapaNombreFunción principal
7AplicaciónProporciona servicios de comunicación a las aplicaciones.
6PresentaciónSe ocupa de la representación y transformación de los datos.
5SesiónOrganiza y controla las sesiones de comunicación.
4TransporteGestiona la comunicación entre aplicaciones de distintos equipos.
3RedPermite enviar información entre redes diferentes.
2Enlace de datosGestiona la comunicación a través de un enlace de red.
1FísicaTransmite bits mediante señales por el medio físico.

Vamos a recorrer las capas desde la 7 hasta la 1, relacionando sus funciones con ejemplos y elementos que podemos encontrar en una red.

🔶 Capa 7. Aplicación​

La capa de aplicación proporciona los servicios de comunicación que necesitan las aplicaciones para intercambiar información a través de una red.

Es la capa más cercana a las aplicaciones utilizadas por el usuario, aunque no debemos confundirla con los propios programas. Por ejemplo, un navegador web es una aplicación, mientras que HTTP es un protocolo que puede utilizar para comunicarse con un servidor.

Algunos protocolos relacionados con esta capa son:

  • HTTP y HTTPS: utilizados para acceder a páginas y servicios web.
  • DNS: permite obtener direcciones IP a partir de nombres de dominio.
  • SMTP: utilizado para enviar correo electrónico.
Ejemplo

Cuando escribimos la dirección de una página web en el navegador, este utiliza protocolos de aplicación, como HTTP o HTTPS, para comunicarse con el servidor y solicitar el contenido.

El navegador es el programa que utilizamos, mientras que el protocolo establece las reglas para intercambiar la información.

🔶 Capa 6. Presentación​

La capa de presentación se ocupa de que los datos tengan una representación adecuada para que los sistemas que se comunican puedan interpretarlos.

Entre sus funciones se encuentran la codificación de la información, la conversión entre formatos y, en determinadas arquitecturas, la compresión y el cifrado de los datos.

Podemos relacionar estas funciones con elementos como:

  • UTF-8: codificación utilizada para representar caracteres.
  • JPEG y PNG: formatos de representación de imágenes.
  • Cifrado: mecanismos que permiten proteger el contenido de la información.

Estos elementos no son necesariamente protocolos propios de una capa de presentación independiente. Son ejemplos de funciones que el modelo OSI sitúa en este nivel.

Ejemplo

Cuando accedemos a una página web que contiene texto e imágenes, los dispositivos necesitan interpretar correctamente los caracteres y los formatos de los archivos recibidos.

Si el texto está codificado mediante UTF-8, el sistema debe conocer esa codificación para representar correctamente sus caracteres.

🔶 Capa 5. Sesión​

La capa de sesión se encarga de organizar y controlar el diálogo entre las aplicaciones que intercambian información.

Entre las funciones que el modelo OSI relaciona con esta capa se encuentran el establecimiento, mantenimiento y finalización de sesiones, así como la coordinación de determinados intercambios de datos.

Una sesión representa una interacción de comunicación entre aplicaciones, aunque no debe confundirse necesariamente con una conexión de transporte ni con una sesión de usuario iniciada mediante contraseña.

En las redes actuales, estas funciones pueden estar integradas en protocolos de otras capas.

Ejemplo

Imaginemos una aplicación que necesita mantener un intercambio de información durante varias operaciones.

Para organizar ese intercambio puede ser necesario identificar cuándo comienza, cómo se mantiene la comunicación y cuándo finaliza.

El modelo OSI agrupa este tipo de funciones en la capa de sesión.

🔶 Capa 4. Transporte​

La capa de transporte proporciona servicios para la comunicación entre aplicaciones que se ejecutan en equipos diferentes.

Se ocupa de funciones como distinguir las comunicaciones de distintas aplicaciones y, según el protocolo utilizado, controlar la entrega, el orden y la recuperación de datos perdidos.

Dos protocolos fundamentales de esta capa son:

  • TCP: proporciona una comunicación fiable y ordenada mientras la conexión funciona correctamente.
  • UDP: permite enviar unidades de información llamadas datagramas, sin establecer una conexión previa ni garantizar su entrega.

También encontramos los puertos, que permiten identificar los puntos de comunicación utilizados por las aplicaciones.

Ejemplo

En un ordenador podemos tener abierto un navegador web mientras utilizamos una aplicación de mensajería.

La capa de transporte permite diferenciar las comunicaciones correspondientes a cada aplicación mediante mecanismos como los números de puerto.

🔶 Capa 3. Red​

La capa de red se encarga de permitir que la información llegue desde un equipo hasta otro, incluso cuando se encuentran en redes diferentes.

Para ello, utiliza direcciones lógicas, como las direcciones IP, que permiten identificar el origen y el destino de los paquetes.

Uno de los protocolos fundamentales de esta capa es IP.

Los routers trabajan principalmente en esta capa, ya que permiten interconectar redes y seleccionar por dónde deben reenviarse los paquetes para acercarlos a su destino.

Ejemplo

Cuando abrimos una página web desde un ordenador del instituto, la información debe viajar desde nuestra red local hasta el servidor donde está alojada.

Durante ese recorrido, los routers utilizan las direcciones IP y sus tablas de enrutamiento para decidir a dónde enviar los paquetes.

🔶 Capa 2. Enlace de datos​

La capa de enlace de datos organiza la comunicación a través de un enlace de red y establece mecanismos para transmitir información entre dispositivos conectados mediante una determinada tecnología.

En las redes Ethernet, las direcciones MAC se utilizan para identificar las interfaces que intervienen en la comunicación local.

Entre los elementos relacionados con esta capa encontramos:

  • Ethernet: tecnología habitual en redes locales cableadas.
  • Direcciones MAC: identificadores utilizados en determinadas tecnologías de enlace.
  • Switches: dispositivos que, en su funcionamiento habitual de capa 2, utilizan direcciones MAC para reenviar tramas.
Ejemplo

En un aula de informática, varios ordenadores pueden estar conectados a un mismo switch.

Cuando un ordenador envía información a otro de la misma red local, el switch puede utilizar las direcciones MAC para decidir por qué puerto debe reenviar la trama.

🔶 Capa 1. Física​

La capa física se encarga de transmitir los bits mediante señales a través de un medio de comunicación.

Define características relacionadas con las señales eléctricas, ópticas o de radio, así como otros aspectos físicos necesarios para la transmisión.

Entre los elementos relacionados con esta capa encontramos:

  • Cable de par trenzado: transmite señales eléctricas.
  • Fibra óptica: utiliza señales luminosas.
  • Comunicación inalámbrica: utiliza ondas electromagnéticas.
  • Conectores y elementos físicos: permiten establecer las conexiones necesarias.
Ejemplo

Cuando conectamos un ordenador a un switch mediante un cable Ethernet de par trenzado, la información se transmite físicamente mediante señales eléctricas.

Si utilizamos fibra óptica, se emplean señales luminosas. En ambos casos, la función de esta capa sigue siendo permitir la transmisión física de los bits.

Idea clave

El modelo OSI divide las funciones de comunicación en siete capas, desde la transmisión física de señales hasta los servicios que utilizan las aplicaciones.

Cada capa tiene unas responsabilidades determinadas, pero todas colaboran para hacer posible la comunicación.

No debemos interpretar que cada capa necesita un dispositivo o un protocolo exclusivo. Un mismo dispositivo puede realizar funciones de varias capas y las arquitecturas reales no siempre siguen exactamente esta división.

Esta organización nos servirá para comprender cómo funcionan las redes y para localizar problemas de comunicación. En la siguiente unidad estudiaremos con mayor detalle cómo colaboran las capas cuando enviamos y recibimos información.

4️⃣ El modelo TCP/IP: la arquitectura utilizada en Internet​

La arquitectura TCP/IP es el conjunto de protocolos y funciones que permite la comunicación entre dispositivos a través de redes interconectadas. Es la arquitectura utilizada en Internet y también en la mayoría de las redes informáticas actuales.

Su nombre procede de dos de sus protocolos fundamentales:

  • TCP (Transmission Control Protocol): proporciona un servicio de transporte fiable y ordenado entre aplicaciones.
  • IP (Internet Protocol): permite identificar el origen y el destino de los paquetes y enviarlos a través de distintas redes.

Aunque recibe el nombre de estos dos protocolos, la arquitectura TCP/IP incluye muchos otros, como UDP, HTTP o DNS. No todas las comunicaciones que utilizan IP necesitan utilizar TCP.

A diferencia del modelo OSI, que se utiliza principalmente como referencia para estudiar las funciones de comunicación, TCP/IP es una arquitectura de protocolos utilizada en redes reales.

🔶 Las cuatro capas de TCP/IP​

La arquitectura TCP/IP suele representarse mediante cuatro capas, que agrupan las funciones necesarias para comunicar dispositivos.

CapaFunción principalProtocolos y tecnologías relacionados
AplicaciónProporciona los servicios de comunicación que necesitan las aplicaciones.HTTP, HTTPS, DNS, SMTP.
TransportePermite la comunicación entre aplicaciones de distintos equipos.TCP, UDP.
InternetSe encarga del direccionamiento y envío de paquetes entre redes.IP, ICMP.
Acceso a la redPermite transmitir la información mediante la tecnología de red utilizada.Ethernet, Wi-Fi.

Las funciones de estas capas son similares a las que hemos estudiado en OSI, pero se organizan de una forma más sencilla.

Ejemplo

Cuando accedemos a una página web:

  1. La capa de aplicación permite que el navegador solicite el contenido mediante HTTP o HTTPS.
  2. La capa de transporte proporciona la comunicación entre el navegador y el servidor mediante un protocolo como TCP.
  3. La capa de Internet utiliza direcciones IP para enviar los paquetes hacia su destino.
  4. La capa de acceso a la red permite transmitir la información a través de tecnologías como Ethernet o Wi-Fi.

En este ejemplo, las cuatro capas colaboran para hacer posible la comunicación. No todas las comunicaciones web utilizan necesariamente TCP, pero es un caso habitual y sencillo para comprender la arquitectura.

🔶 Correspondencia entre OSI y TCP/IP​

Aunque ambos organizan las funciones de comunicación en capas, OSI utiliza siete y TCP/IP suele representarse mediante cuatro.

La principal diferencia es que la arquitectura TCP/IP agrupa en una misma capa algunas de las funciones que el modelo OSI describe por separado.

Idea clave

OSI y TCP/IP no son dos tecnologías de red diferentes, sino dos formas de organizar y describir las funciones necesarias para la comunicación.

  • OSI: modelo de referencia de siete capas.
  • TCP/IP: arquitectura de protocolos utilizada en la práctica, representada habitualmente mediante cuatro capas.
